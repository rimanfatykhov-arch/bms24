# Task Center UI release acceptance

This is a selectively assembled candidate, not a deployment. Input SHAs and independent reviews are in origins.json. The only product change against main is task_center.css (PR90 menus + PR99 discussion overlap fix). No schema, ACL, Moodle Core or business-rule changes; no PR92/SaaS architecture. Existing FULL/security/Corporate/shadow/merge gates remain intact.

The dedicated pull-request workflow runs only for release/* branches. It builds one deterministic install ZIP in a separate job, with source checkout SHA/tree, PR head/base, component versions, input origins, per-file hashes and SHA256SUMS. Both DB jobs download that same immutable artifact, compare it to their exact checkout and verify installed bytes after upgrade/cache purge. They never rebuild the package. Source archive is not an install artifact.

Disposable GitHub-hosted Ubuntu22, Moodle4.1.22 at b27f0816159a7555a0b3ad9ff2f8f8ef701a29fa, PHP8.1, pinned MariaDB10.11.19/Percona8.0.46-37 and Playwright1.49.1. Synthetic A/B only; no live data, shared volumes, real email or integrations. Browser requests are loopback-scoped; this is not an OS-level outbound firewall claim. Never run these scripts on production/staging or a shared runner.

Sequence: prove known baseline overlap using real DOM/normal click, retain expected before failure explicitly → snapshot full code+DB+moodledata → install exact ZIP → M01–M10, menus/keyboard/mobile, writes/CSRF/downloads, owned/legacy repeated pointer/keyboard messages, new-file foreign/revoked ACL → full restore → before restart require equal DB dump, every code and moodledata file hash → after restart history/ACL/files checks using baseline file identities → reinstall same ZIP and repeat. Reports include timings and comparison policy; cache/session temp files may change after restart. Synthetic timings do not establish production RPO/RTO.

Actual baseline failure is not treated as candidate PASS. Candidate and reinstall must succeed without CSS overrides, force-click, JS submit, removed panels or weakened ACL. Layout experiments are diagnostic only; real repeated sends use normal interaction and verify exactly one persisted message after reload. The server's existing post→Discussion redirect is preserved; each repeat explicitly returns to Overview to test the compact composer.

Public artifacts contain package/manifest/reports/screenshots only. Never upload config.php, actors.private.json, SQL, snapshots or private server logs. One report applies only to its recorded source/tree/package. Keep the release head frozen after acceptance; changes require rebuilt evidence. Production requires separate read-only baseline verification, tested real backup/restore, owner approval for the exact candidate/target/window and release smoke/rollback plan. No GitHub Release publication, merge or deploy is authorized by CI.
