# BMS24 1.1.0-rc29 build2026101638 — Position Coverage 03: рабочий контроль (read-only)

**База:** полный local_kbacompany `build2026101637`.
**Статус:** кандидат для тестовой Moodle 4.1/4.0; live-acceptance не выполнена.

## Реализовано

- В карточке ранее утверждённого замещения `position_coverage.php?uuid=...&coverage=...` добавлен раздел «Контроль работы на период замещения» только для пользователей с company-scoped правом управления замещениями.
- Кнопки перехода по неделям ограничены включительными датами конкретного замещения; произвольная дата за пределами авторизованного периода отклоняется сервером.
- «График должностных задач» строится **без копирования данных** из канонических задач `local_kbacompany_task` по компании, закреплённой должности `dutypositionuuid`, исходному исполнителю, открытому состоянию и сроку на выбранной неделе; возвращается не больше 50 строк. Для просмотра нужен независимый `task_service::can_manage`.
- «Показатели должности» — агрегат план/факт **только для просмотра** из `battle_plan_indicator_service::projection`, по должности и выбранной неделе. Нужен отдельный `indicator_registry_service::can_manage`. Установление плана, внесение факта и подтверждения отсутствуют.
- «Рабочий календарь сотрудника»: ссылки только для календарей, где **в действующем** `employee_work_calendar_service::allowed(...,'view')` есть право просмотра. Никаких новых разрешений или расширения доступа по факту замещения. Сами личные/закрытые события не агрегируются в график.
- Запрошенное/отклонённое/отменённое замещение не получает блок оперативного контроля. При просмотре согласованного старого замещения блок исторический, а не механизм повторной выдачи прав.

## Безопасность и границы

- `position_coverage_service::operational_snapshot` проверяет компанию, менеджерские права, существующую запись и дату; отдельные rights gates для задач/метрик/календарей. Отсутствующие права => пустая закрытая секция, а не обход ACL.
- Полностью исключены изменения `task.assigneeid`, реклассификация задач, переотправка регулярных экземпляров, записи `statval`, изменения `bplan`, персональные Moodle Calendar events и автоматическая выдача work-calendar grants.
- Календарь в данном релизе — **расписание сроков должностных задач**, не новый единый календарь отпускного сотрудника. Передача управления рабочим календарём или KPI потребует отдельного согласованного RBAC-контракта.
- БД: **без DDL**, только `version.php` и контрольная точка `2026101638` в `db/upgrade.php`. `position_coverage_service` contract `0.3.0`.

## Файлы

- `classes/local/position_coverage_service.php` — авторизованная read-only проекция.
- `position_coverage.php` — три блока в DetailView (недельный график задач; KPI; только разрешённые ссылки на рабочие календари).
- `lang/ru/local_kbacompany.php`, `lang/en/local_kbacompany.php` — подписи и пустые состояния.
- `db/upgrade.php`, `version.php` — no-DDL checkpoint.

## Проверки

- PHP syntax check всего плагина; XMLDB `install.xml` parse.
- Русская/английская локализации: идентичные наборы уникальных ключей.
- Изолированный PHP smoke на модель: company/manager ACL, раздельные права на задачи и показатели, явные календарные разрешения, отсечение даты за периодом и нулевые записи в БД.
- ZIP CRC и SHA256.

**Не выполнены**: реальный Moodle 4.1/MySQL upgrade и тесты полномочий, Behat/browser, полноценный PHPUnit на БД, производительность KPI в компании с большим количеством показателей. До промышленного запуска необходим staging и резервные копии.
