# BMS24 RC29 build2026101819 — сквозной контроль результата внедрения

## Назначение
Связать в одном защищённом представлении этап внедрения Corporate, задачу, недельный Боевой план и **подтверждённый куратором результат**. Не смешивать выполнение задачи с её независимой приёмкой.

## Изменения в `local_kbacompany`
- В «Административная шкала → Проекты внедрения BMS → Этапы внедрения» добавлена сводка решений куратора для каждого раздела подтверждённого аудита.
- Состояния: не начато, в работе, пакет подтверждения передан на проверку, на проверке без пакета, возвращено на доработку, принято, завершено без подтверждения, отменено, несогласованные данные.
- Показано число версий подтверждения и дата решения без просмотра частных заметок/файлов. Ссылки ведут к оригинальной карточке Corporate; при наличии прав добавлены ссылки на Боевые планы выбранной недели.
- Связи с недельными планами проверяются на совпадение задачи и статусных снимков. При несогласованных данных выводится сообщение «обновите страницу» без недостоверных агрегатов.
- Дашборд продолжает работать и при недостаточных правах на общекорпоративные Боевые планы: аналитика результата управляется существующими правами проекта Corporate и отображается независимо от недельных планов.
- Новые таблицы БД не создаются; данные и права пользователя не меняются. Вся новая сводка доступна только для явно связанной программы и опубликованного проекта той же компании.

## Изменения в `local_kbacorporate 0.40.8` / публичный API 1.26
- Метод `bridge::get_implementation_program_result_statuses($companyid, $actorid, $programid)` возвращает только безопасное состояние результата для задач связанной оплаченной программы.
- API использует действующие проверки доступа, уникальную каноническую программу на базовый аудит и ограничение 5000 задач.
- Только последняя версия пакета подтверждения определяется по уникальному `(taskid, versionno)`. Запросы к доказательствам ограничены пакетами максимум 250 задач; никаких отдельных запросов на каждую задачу.
- API не передаёт файлы, текст подтверждения, комментарий куратора, контакты, имя проверяющего и не изменяет задачи.
- Завершённая задача **не считается принятой**, пока последний пакет подтверждения не принят и её исходный статус не `completed`. Противоречивые сочетания возвращаются как требующие проверки.
- При отсутствии таблиц подтверждений возвращается причина `evidence_unavailable`, а не фиктивные нулевые значения.

## Ограничения
- Состояние подтверждений отражает **текущий** статус задачи, а привязка к Боевому плану — выбранную неделю. Подтверждение, выполненное позже той недели, не объявляется фактом той недели.
- Старые выполненные задачи без версии принятого пакета считаются «завершены без подтверждения», а не «приняты куратором».
- Сводка результатов по разделам подтверждённого аудита; задачи без раздела не приписываются искусственно ни к одному этапу.
- Не изменяются жизненный цикл Corporate, существующие планы, история обсуждений, право на подтверждение и параметры проектов.
- При несовпадении снимков источников, отсутствии подтверждённого аудита, общем базовом аудите, превышении лимитов результаты не отображаются как полноценные.

## Установка
1. Сделать резервную копию кода и БД Moodle; сначала проверить на стенде.
2. Установить **Corporate 0.40.8** (build `2026102517`, API 1.26).
3. Установить **BMS24 RC29 build `2026101819`**.
4. Выполнить миграции Moodle, очистить кэш, проверить версии.
5. Открыть связанный проект внедрения и вкладку этапов. Сверить текущие статусы задач и последнее подтверждение с их оригинальными карточками в Corporate.

## Ручная приёмка
- Сотрудник передаёт результат, задача переходит в «На проверке», в BMS24 появляется «Ожидает проверки».
- Куратор возвращает результат с замечаниями: Corporate сохраняет обсуждение, в BMS24 отображается «Возвращено на доработку».
- Сотрудник отправляет новую версию; BMS24 видит последнюю версию, а не ранее отклонённую.
- Куратор принимает: только теперь BMS24 показывает «Результат принят»; закрытая ранее задача без принятого подтверждения остаётся отдельной категорией.
- Убедиться, что один и тот же объект в двух Боевыx планах не удваивается, а статусы не зависят от выбранной недели.
- Проверить чужую компанию, пользователя без прав управления, неоплаченную программу, архивный проект, общий аудит и удалённую задачу.
- Проверить производительность для сотен и тысяч задач, PHP 8.1.34, Moodle 4.1.22 и MySQL 5.7.21.

**Локальные проверки не заменяют серверную приёмку на `edu.kzn.mba`.**
