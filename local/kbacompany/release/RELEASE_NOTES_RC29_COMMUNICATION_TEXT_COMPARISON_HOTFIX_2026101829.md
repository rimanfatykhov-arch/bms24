# BMS24 — RC29 build2026101829

## Назначение
Hotfix ошибки Moodle при отзыве сообщения в Коммуникационном центре:

> Не допускаются условия, содержащие сравнения полей типа text. Пожалуйста, используйте в запросе sql_compare_text().

## Причина
В `classes/local/communication_service.php::change_message()` проверка связанного управленческого решения использовала `$DB->record_exists()` с условием по полю `local_kbacompany_decision.rationale`. Поле имеет тип XMLDB `TEXT`. Moodle запрещает такое сравнение без `$DB->sql_compare_text()`.

Аналогичная проблема обнаружена в `create_decision_from_message()`, где для дедупликации решения использовался `$DB->get_record()` с тем же текстовым условием.

## Исправления
- Обе проверки переведены на параметризованные SQL-запросы с `$DB->sql_compare_text('rationale', 255)`.
- В проверке связанности сообщения сохранён фильтр по UUID компании.
- В поиске ранее созданного решения сохранены фильтры по UUID компании и встрече.
- Сохранены все существующие требования: сообщение редактирует или отзывает только автор; сообщения, используемые для задач/решений, защищены; существующий журнал `commrev` не изменялся.
- Добавлены PHPUnit-тесты для сообщения, связанного с решением, и отсутствия ложной связи из другой компании.

## Установка
1. Сделать резервную копию базы данных, moodledata и текущих файлов плагина.
2. Установить ZIP как обновление `local_kbacompany` (не удалять действующий плагин).
3. Выполнить штатное обновление Moodle и очистить кэши.
4. Проверить тестовым пользователем отзыв собственного сообщения без связи с задачей или решением.
5. Проверить, что связанное с решением сообщение по-прежнему запрещено отзывать.
6. Проверить аналогичный сценарий редактирования и создание решения из сообщения в обсуждении встречи.
