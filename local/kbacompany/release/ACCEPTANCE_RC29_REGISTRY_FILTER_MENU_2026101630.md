# BMS24 RC29 build2026101630 — приемка фильтра и бокового меню

После резервного копирования плагина/БД, установки и очистки кэша Moodle:

- [ ] В левом рабочем меню после «Задачи» появился пункт «Регулярные задачи», далее «Боевой план»; при нажатии открывается company-scoped реестр.
- [ ] При входе в реестр пункт подсвечен. Он остаётся активным в DetailView, EditView, CreateView и библиотеке регулярных задач. «Задачи» и «Боевой план» подсвечиваются только на собственных страницах.
- [ ] Над таблицей реестра имеется «Состояние серии»: Все состояния / Черновик / Активна / Приостановлена / Архив. В вариантах указано количество только видимых пользователю серий.
- [ ] Значение по умолчанию «Все состояния» показывает пять имеющихся серий из предоставленного скриншота (если содержимое БД не изменилось). Данные не стираются при переключении.
- [ ] Выбрать «Активна» → видны только активные; «Черновик» → только черновые; «Архив» → только архивные. Счётчики соответствуют видимым данным.
- [ ] «Сбросить фильтр» возвращает полный список, пустая выборка показывает понятное сообщение.
- [ ] Клик по серии сохраняет выбранный status в URL; «К реестру» возвращает к прежнему состоянию фильтра; plan/uuid не теряются.
- [ ] GET `status=unknown` безопасно возвращает «Все состояния», не вызывает PHP fatal.
- [ ] Пользователь без управленческих прав видит только допустимые ему серии; число по фильтру не раскрывает чужие серии/компании.
- [ ] У контекстной ссылки из боевого плана сохранён `plan`. По прямой ссылке из левого меню (без `plan`) реестр работает без привязки к одному плану.
- [ ] На узком экране таблица прокручивается внутри блока, а меню и вся страница не получают горизонтальную прокрутку.
- [ ] Сохранение, активация, пауза, архивирование и генерация экземпляров ведут себя как до установки; не появляются дубли; ссылки на созданные задачи работают.

Реальную активацию/архивирование проверять только на тестовых сериях, не на производственных данных.
