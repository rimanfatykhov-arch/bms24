# BMS24 RC29 — build2026101798: аналитика циклов согласования

## Изменения

- Добавлен блок **«Циклы согласования: аналитика»** в `battle_plan_overview.php` для выбранной недели Боевых планов.
- Счётчики записанных отправок, возвратов, планов с двумя и более отправками/возвратами, решений с измеренной длительностью и среднего времени принятия решения.
- Разбивки по подразделениям, сотрудникам и **назначенным** проверяющим; список до 15 планов с повторными циклами, переход к вкладке «История».
- Счётчики и группировки вычисляются **до ограничения отображаемых строк**, после серверных фильтров доступа, недели, подразделения, проверяющего и компании.
- Для каждого результата используется только журнал событий `review_cycle_events` из `statepayload`. Исторические события, не записанные до `1797`, не домысливаются. Сводка показывает покрытие журнала и количество планов без событий.
- В среднее попадают только интервалы от сохранённой отправки до сохранённого решения. Самостоятельное утверждение и решения без достоверного начала цикла исключаются.
- Функция исключительно аналитическая, изменений БД, задач или статусов нет. Время ожидания **не** является SLA.

## Техническая реализация

- `classes/local/battle_plan_review_cycle_analytics_service.php`: чистая проекция событий, не обращается к БД.
- `battle_plan_review_timeliness_service::context()`: собирает отдельную безопасную выборку по уже прошедшим ACL записям; не передаёт `statepayload` во view.
- `cli/test_review_cycle_analytics.php` и `cli/check_review_cycle_analytics_contract.py` добавлены в обязательные проверки release runner.
- Версия плагина: `2026101798`, upgrade savepoint без изменения XMLDB.

## Приёмка на Moodle 4.1.22 / PHP 8.1.34

1. Открыть «Боевые планы → Обзор боевых планов» и выбрать неделю.
2. Проверить, что новый блок виден, но на старых неделях не выдумывает историю.
3. В тестовой неделе провести два цикла отправка → возврат и отправка → утверждение; проверить 2 отправки, 1 возврат, 1 план с повторной отправкой и рассчитанные длительности.
4. Проверить фильтры подразделения/проверяющего и права сотрудника: данные чужих планов не должны попадать в отчёт.
5. Сверить агрегаты со вкладкой «История» у выбранного плана, пройти по ссылке в таблице повторных циклов.
