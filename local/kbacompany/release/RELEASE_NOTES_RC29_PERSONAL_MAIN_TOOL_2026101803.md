# BMS24 RC29 / build2026101803 — персональное рабочее пространство

## Цель

Переход от одинакового для всех пользователей стартового экрана к индивидуальному **«Мой главный инструмент»** на базе существующей навигации BMS24. Ни бизнес-данные, ни жизненный цикл Боевых планов не изменяются.

## Функциональность

1. **Безопасная точка входа** `bms_home.php`: проверяет авторизацию, компанию и серверный перечень доступных пользователю разделов, затем переводит на сохранённый главный инструмент. Прямые ссылки на отдельные разделы **не перенаправляются**.
2. **Персональная настройка** `bms_home_preferences.php`: выбор одного из доступных вариантов — Рабочее пространство, Боевой план, Задачи, Управление, Коммуникации, Бизнес-архитектура, Люди. Недоступные разделы не отображаются; сохранить неразрешённый маршрут нельзя. Варианты карточек формируются из действующего sidebar, а не из произвольных URL.
3. **До пяти быстрых переходов**: список только из имеющихся навигационных маршрутов, очистка от дубликатов, проверка существующих прав и компании. Редактирование на странице персональной настройки.
4. **Левое меню**: группы «Мой главный инструмент» и «Избранное» перед существующими разделами. Владелец маршрутов и ACL по-прежнему `local_kbacompany`, а не тема Moodle.
5. **Верхняя панель**: ссылка «Сменить главный инструмент» рядом с пользовательским меню и в служебной области бокового меню; доступна из общего shell и из рабочего пространства.
6. **Разовый выбор для новых учётных записей**: нативное окно `<dialog>` на рабочем пространстве с выбором инструмента и кнопкой «Выбрать позже». Запоминается раздельно по компаниям. Время начала новой модели регистрируется при upgrade; уже существующим пользователям окно автоматически не навязывается. При необходимости все могут самостоятельно открыть страницу настройки.
7. **Расширение `bms_workspace.php`**: реальный статус личного Боевого плана на текущую неделю, переход к существующей карточке и быстрые действия в доступных разделах. При отсутствии плана показывается корректное пустое состояние; не выводятся вымышленные KPI или проценты эффективности.
8. **Точка выбора компании**: переходы из списка компаний (`index.php`) теперь направляются через точку входа; логотип в обеих версиях BMS App Shell открывает персональный главный инструмент. Прямая ссылка на `bms_workspace.php` всегда открывает именно рабочее пространство.
9. Локализация всех новых пользовательских строк на русском и английском.

## Хранение / безопасность

- Пользовательские предпочтения Moodle (`get_user_preferences` / `set_user_preference`) с ключом на основе хэша `companyuuid` и явным ID пользователя. Предпочтения одной компании не перезаписывают другую.
- `company_context_service` вызывается через `bms_ui_service::shell_model` до чтения/сохранения; необходим `require_login` и `local/kbacompany:viewowncompany`.
- Сохранение и пропуск обучения доступны только через POST с `require_sesskey`.
- Серверная фильтрация маршрутов и избранного по доступным пунктам существующей навигации. Нельзя задать внешний URL или открыть пункт «Управление» после потери соответствующего права.
- Нет новых XMLDB таблиц, пользовательских capabilities или прямой записи в таблицы бизнес-данных. `version.php=2026101803`; savepoint в `db/upgrade.php` и время rollout через plugin config.
- Производительность: без новых внешних запросов и без дополнительных запросов к общим спискам задач, кроме одного чтения личного Боевого плана текущей недели (индексированный фильтр компании/пользователя/недели).

## Автоматическая проверка

- Чистый PHP-тест персонализации (без Moodle): изоляция компаний и пользователей, сохранение, запрет неизвестных и ограниченных маршрутов, переход при потере права, предел избранного, устранение дубликатов, отмена выбора при первом входе.
- Статический контракт маршрутов, POST/sesskey, UI-встраивания в оба App Shell, версии.
- Обязательная общая RC29 регрессия, PHP lint, проверка PHP 8.1 совместимости, языковых ключей, XMLDB и SHA256 — конкретные результаты фиксируются логом сборщика.
- **Интеграционное/браузерное тестирование на Moodle 4.1 + PHP 8.1 и на рабочем edu.kzn.mba НЕ проводилось**. Проверку и решение о развёртывании принимает владелец портала.

**Важно:** делайте тесты на тестовой компании/стенде. Создайте резервные копии кода и БД перед обновлением `edu.kzn.mba`.

## Ограничения и следующий релиз

Настройка **виджетов** (перетаскивание, скрытие/добавление отдельных блоков, персональное расположение карточек) намеренно отложена до `build2026101804`. Здесь реализован законченный MVP выбора главного инструмента и рабочего пространства без обязательного обновления темы KBA. Перед утверждением RC30 требуется реальная приёмка PHP 8.1 / Moodle 4.1, особенно пользовательские preference API и обе оболочки UI.
