# Приёмка — BMS24 RC29 build2026101620 (после установки)

**Только ручная проверка на тестовом/боевом Moodle; до установки сценарии не выполнены.**

## Создание новой задачи

- [ ] Открыть черновик боевого плана и «Добавить задачу». Период и владелец должны совпадать с исходным планом.
- [ ] По умолчанию активен режим «Создать новую задачу»; рядом есть «Добавить существующую».
- [ ] Название, ожидаемый продукт и срок на первом экране; имя исполнителя показано без возможности назначить другого владельца плана.
- [ ] Описание, приоритет, поток, проверяющий, наблюдатель, начало, время, плановые минуты и файл — в «Дополнительных параметрах».
- [ ] Незаполненные название/продукт/срок вызывают подсказку формы; удаление срока при POST также отвергается сервером.
- [ ] Проверить срок до даты начала: канонический task_service должен отвергнуть некорректный диапазон.
- [ ] Сохранить: открывается вкладка задач исходного плана, ровно одна запись задачи в каноническом `local_kbacompany_task`, одна связь в `local_kbacompany_bplanitem`.
- [ ] После создания открыть задачу из единого центра задач и проверить ожидаемый продукт, даты, участников, историю и прикреплённые файлы.

## Добавление существующей задачи

- [ ] Переключить на «Добавить существующую». Длинная форма создания исчезает.
- [ ] Поиск с названием и кнопкой «Применить» сохраняет режим выбора и запрос.
- [ ] Выдача показывает название, источник, исполнителя, статус и срок. Можно выбрать одну задачу.
- [ ] «Добавить в план»: появляется только ссылка на каноническую задачу, не создаётся её копия.
- [ ] Повторное добавление того же UUID не создаёт второй ссылки.
- [ ] Кнопка отмены возвращает к исходному плану.
- [ ] Шаблоны, административные задачи и задачи должности продолжают работать.
