# RC30 — протокол приёмки BMS24 (build2026101864)

## Золотое правило
RC30 присваивается только после серверной приёмки. Локальная проверка исходников, прохождение технического CLI gate или скачивание ZIP не означает выпуска RC30.

## Предварительные действия

1. Развернуть тестовую копию Moodle, использующую реальную или обезличенную базу нужного объёма.
2. Проверить фактические версии PHP, MySQL, Moodle и установленных плагинов.
3. Сделать резервную копию и проверить процедуру восстановления.
4. Установить build1864 после build1863 через `/admin/index.php`; очистить кэши.
5. Убедиться, что миграция индексов build1863 не завершилась ошибкой.

## Машинная проверка (права доступа к серверу Moodle)

```bash
php local/kbacompany/cli/rc30_acceptance.php --company=UUID_КОМПАНИИ --format=json --strict > rc30_acceptance.json
php local/kbacompany/cli/rc30_task_integrity.php --company=UUID_КОМПАНИИ --strict
```

При наличии разрешённого окна для полной диагностики:

```bash
php local/kbacompany/cli/rc30_acceptance.php --all --format=json --strict > rc30_acceptance_all.json
```

Проверить `technical_gate`, `errors`, `warnings`, `indexes`, `integrity_summary`. Не включать `rc30_promotion_approved` вручную: отчёт всегда указывает, что требуется дополнительная приёмка.

## Обязательные пользовательские сценарии

- **Компании A/B:** сотрудник A не видит задачи, историю, файлы и Боевые планы компании B, включая прямые ссылки и POST.
- **Роли:** собственник, руководитель подразделения, исполнитель, принимающий, наблюдатель. Проверить просмотр, комментирование, изменение, приёмку, отзыв прав.
- **Жизненный цикл:** новая → начать → сдать результат → принять / вернуть → повторная сдача → завершить. Проверить обязательные результаты и журнал событий.
- **Массовые действия:** лимит 25, недопустимый UUID, конфликт ревизии, повтор POST, права, запрет нарушения утверждённого Боевого плана.
- **Канбан:** ширина, стрелки и прокрутка, группировки, пределы колонок, drag-and-drop и штатная форма подтверждения.
- **Боевой план:** новые и старые связи `externalid`/`taskuuid`, повторная привязка, черновик/утверждение, удаление/блокировки.
- **Аналитика:** нагрузка и замещение исполнителя, просрочки, переходы из показателей, изоляция компаний.
- **Производительность:** MySQL 5.7 `EXPLAIN` для списка и счётчиков задач, истории и связей с планом, замеры на реальном количестве записей.

## Серверные PHPUnit

Запустить новый `tests/task_rc30_acceptance1864_test.php`, а также RC29/RC30 тесты предыдущих сборок на установленном Moodle. Убедиться, что нет пропущенных/падающих проверок. Протокол тестирования приложить к релизу.

## Решение GO / NO-GO

**GO:** нет критических замечаний, техническая проверка успешна в `--strict`, PHPUnit и пользовательские сценарии пройдены, производительность приемлема, резервная копия проверена. Решение подтверждено владельцем продукта.

**NO-GO:** ошибки миграции, нарушения прав, проблемы целостности данных, непроверенное восстановление, критические проблемы задач или падение обязательных сценариев.
