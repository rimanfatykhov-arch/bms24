# BMS24 — RELEASE NOTES build2026101864

**Продукт:** BMS24 / `local_kbacompany` 1.1.0-rc29  
**Тип:** накопительная приёмочная сборка (pre-RC30; RC30 не объявлен)  
**База:** build2026101863

## Результат релиза

### 1. Единый технический контроль RC30 в Moodle CLI

Добавлена команда `local/kbacompany/cli/rc30_acceptance.php`, которая в режиме **только чтения** проверяет:

- соответствие установленной версии плагина build2026101864;
- наличие **четырёх** индексов из build1863;
- **18** действующих диагностик целостности BMS-задач, истории, Боевыми планами и назначений ролей;
- отсутствие проблемных категорий (`error`) и наличие предупреждений (`warning`);
- отсутствие задач в выбранной области как повод для дополнительной ручной проверки;
- информацию о PHP/семействе БД (MySQL 5.7 — целевая среда).

Поддерживаются `--company=UUID`, `--all`, `--format=text|json`, `--strict`, `--help`. Проверка по отдельной компании предпочтительна. Формат JSON содержит только счётчики/состояния, без имён пользователей, текстов задач и UUID объектов. По умолчанию предупреждения не приводят к ненулевому exit code, в `--strict` — приводят. Ошибки и отсутствие индексов всегда блокируют техническую проверку.

**Технический результат PASSED не означает, что RC30 разрешён к выпуску.** В отчёте зафиксировано `rc30_promotion_approved: false`. Нужны реальные серверные PHPUnit, проверка бизнес-сценариев и производительности.

### 2. Устранён пробел диагностики дубликатов задач Боевого плана

Проверка `duplicate_bms_plan_items` ранее сравнивала только `externalid`. Теперь проверяется канонический идентификатор `COALESCE(NULLIF(externalid, ''), taskuuid)` — с учётом **старых, новых и смешанных** связей. Проверка сохраняет фильтры компании, Боевого плана и провайдера; данные не меняются. Количество диагностик остаётся 18.

### 3. Подготовлена точка обновления и регрессия

В `db/upgrade.php` добавлена контрольная точка `2026101864` без изменений схемы. Новые индексы, добавленные в build1863, остаются обязательными при приёмке. Добавлены PHPUnit `task_rc30_acceptance1864_test.php` и изолированный SQL-контракт `cli/test_rc30_acceptance_1864.py`.

## Запуск после установки

Из корня установленного Moodle:

```bash
php local/kbacompany/cli/rc30_acceptance.php --company=UUID_КОМПАНИИ --strict
php local/kbacompany/cli/rc30_acceptance.php --company=UUID_КОМПАНИИ --format=json --strict > rc30_acceptance.json
```

Полный охват компаний (только в разрешённое окно обслуживания, может быть затратным):

```bash
php local/kbacompany/cli/rc30_acceptance.php --all --format=json --strict > rc30_all.json
```

Коды возврата: `0` — технические проверки пройдены (или предупреждения в нестрогом режиме), `1` — ошибка/строгое предупреждение, `2` — некорректные параметры или ошибка выполнения.
