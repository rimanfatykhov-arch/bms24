# BMS24 RC29 — build2026101640: Owned UI foundation, design tokens & reversible App Shell

Status: **STAGING CANDIDATE ONLY**. Based on RC29 build2026101639. No DB schema migration and no changed task/approval/staffing/position data.

## Changes
- Created `classes/local/bms24_shell_service.php`: strict plugin-owned render boundary, version 1.0.0-beta.1, allowlisted partials, opt-in mode.
- Added Moodle admin setting `local_kbacompany/bms24_shell_mode` (`legacy` default / `owned` test-only). No GET parameter or end-user permission bypass can enable it.
- Added `templates/bms24_*` for App Shell, sidebar navigation, cards, task list, badges, empty state, tree navigator and architecture split view. Navigation and URL map remain generated by `bms_ui_service`.
- Added `bms_ui/tokens.css` from BMS24 UI Standard v1.0 and `bms_ui/owned_shell.css`, scoped exclusively under `.bms24-app` (root selector excepted).
- Updated three rendering entry paths: `bms_workspace.php`, `bms_architecture.php`, shared `bms_page_shell_service` (used by additional domain pages). Owned mode selects standard Moodle layout and BMS-owned templates; legacy mode remains bit-for-bit behaviorally equivalent to existing KBA/standard fallback except the new opt-in configuration and plugin version.
- Added protected `bms24_styleguide.php?uuid=<companyuuid>` with demo-only swatches and no company secrets.
- Updated contract bms_ui_service 0.7.0.17; additional RU/EN localization; upgrade savepoint 2026101640 (no DDL).
- Added `tests/bms24_shell_service_test.php` for the opt-in mode, rollback, template existence and partial allowlist.

## Important limits
- This is **first-stage UI separation, not total Moodle theme removal**. Moodle still owns header/footer, login, standard layout, user menu and runtime.
- `legacy` mode still deliberately uses `theme_kba/bms/*` when theme KBA supports it. Several view bodies still output old `kba-bms-*` and Bootstrap classes; staged screen migration and CSS removal will follow.
- Staging on Moodle 4.0+/MySQL under both KBA and Boost theme, real PHP Mustache rendering and browser regression with actual user rights **NOT performed here**. Static CSS and standalone mock browser screenshots are not a substitute.
- On KBA's `standard` page layout, host Moodle navigation may still be visible around the new BMS shell. Later shell hardening can remove duplicate host chrome carefully, without changing core output lifecycle.

## Staging installation / switch / rollback
1. Backup Moodle DB + deployed plugin + `theme/kba` version and record build1639 state.
2. Install ZIP with correct `kbacompany/` root to `local/kbacompany` and run normal admin plugin upgrade.
3. Moodle admin → Plugins → Local plugins → BMS24 — interface → set shell to `BMS24 owned shell — staging preview`.
4. Purge Moodle caches; review `bms_workspace.php?uuid=...`, `bms_architecture.php?uuid=...`, tasks, Battle Plans and employee pages at 390/768/1024/1440px. Review permissions for two separate companies. Preview tokens: `bms24_styleguide.php?uuid=...`.
5. Immediate UI rollback (no data rollback): set configuration to `Legacy shell`, purge Moodle caches. If needed revert plugin files to build1639 from backup.
