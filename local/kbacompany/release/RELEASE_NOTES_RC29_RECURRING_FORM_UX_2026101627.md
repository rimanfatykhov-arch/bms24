# BMS24 — Release Notes: RC29 build2026101627

Дата: 16.10.2026. Основа: `build2026101626`.

## Причина исправления
Реальная форма создания регулярной задачи выглядела узкой и двухколоночной вопреки BMS-UX-CRUD-001. Общий CSS `.kbacompany-form` задаёт `display:grid; grid-template-columns: 1fr 1fr`, а `bms-recurring-form` в прошлой сборке не переопределял layout. Из-за этого метки, поля и пояснения перемешивались по двум колонкам. Текст «3. Периодичность» был унаследован от старой многошаговой формы.

## Изменения
- `recurring_tasks.php`: два смысловых раздела внутри формы: «Основные данные» и «Расписание повторения». Дополнительные параметры раскрываются по запросу. Верхний повторный заголовок удалён, используются связанные `label/for` и семантические `section/aria-labelledby`.
- `styles.css`: специфичный CSS-селектор `.kbacompany-form.bms-recurring-form` отменяет общую двухколоночную сетку; форма имеет `flex-direction: column`, максимальную ширину 960 px, центрирование в рабочей области, выровненные слева подписи над полями, компактный ряд дней недели, действия справа. Адаптация под мобильную ширину.
- RU/EN: «Создать регулярную задачу» вместо «Создать серию», «Расписание повторения» вместо «3. Периодичность», сокращённые пояснения, «Сохранить черновик» и новый ключ `recurringtask_form_basics`.
- `version.php` и `db/upgrade.php`: новая версия и уникальный no-DDL savepoint 2026101627.

## Что не изменено
- Канонический `recurring_task_service`, формат данных, UUID, расписания, генерация экземпляров и механизм активации.
- Правила company isolation и проверки прав, POST + sesskey.
- Передача контекста `plan` и закрепление потока `run` для создания из боевого плана.
- Серия сохраняется черновиком, активация выполняется отдельно. Согласованные планы не получают экземпляры автоматически.

## Локальная проверка
- PHP lint: 383/383 файлов.
- RU/EN: 7869 уникальных языковых ключей каждый, ключи совпадают.
- HTML mock smoke: семь сценариев create/list/detail/edit/readonly/badcreate/badsave; HTML-разметка проверена на корректную структуру формы, id и связанные label.
- Chromium visual smoke: на 1440 px форма шириной 960 px, поля расположены вертикально; на мобильной ширине 390 px форма помещается без горизонтального переполнения.
- XML валиден. Savepoint 2026101627 следует после 2026101626. Данные/DDL не менялись.
- ZIP CRC, SHA256 и структура архивов проверены.

## Ограничения
На рабочем Moodle авторизованный интерфейс, установка, cron и реальные DB PHPUnit тесты не проверялись. После установки выполнить Moodle **Site administration → Development → Purge caches**, открыть форму из боевого плана в тестовой компании и пройти чек-лист.
