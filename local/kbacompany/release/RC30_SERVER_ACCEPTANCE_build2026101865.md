# RC30 — протокол серверной приёмки, build2026101865

## Важно

Этот документ и диагностическая команда не заменяют Moodle PHPUnit и ручную
проверку. Перевод BMS24 в RC30 **не производится автоматически**.

## Порядок проверки

1. Создать резервную копию базы данных и каталога `local/kbacompany`.
2. Проверить обновление на тестовой копии Moodle, затем пройти `/admin/index.php`.
3. Очистить кэши Moodle.
4. Проверить целевое окружение: PHP 8.1.x и MySQL 5.7.x.
5. Запустить из корня Moodle (с заменой UUID):

```bash
php local/kbacompany/cli/rc30_acceptance.php --company=UUID --format=json --strict > rc30_company.json
```

6. Прочитать `technical_gate`, `runtime`, `indexes`, `integrity_summary`, `errors`, `warnings`.
7. При отказе исправить причины, затем повторить проверку.
8. Проверить вручную пользователей разных компаний/подразделений, исполнителей,
   принимающих и наблюдателей (включая прямые HTTP-запросы с неверным UUID).
9. Проверить создание задач, сдачу на приёмку, возврат, массовые действия,
   Канбан и связь с утверждёнными Боевыми планами.
10. Выполнить PHPUnit на том же экземпляре Moodle, проверить EXPLAIN и задержки MySQL 5.7.
11. Подписать протокол приёмки и подтвердить возможность восстановления резервной копии.

## Значение технического статуса

- `passed`: перечисленные автоматические проверки прошли, **не означает RC30 готов**.
- `warnings`: есть отклонения; в строгом режиме будет `failed`.
- `failed`: обнаружено нарушение целостности, версии, индекса или строгое предупреждение.
- `rc30_promotion_approved`: остаётся `false` до отдельной приёмки.

## Ограничения

- Проверка только читает БД.
- В JSON нет названий компаний, персональных данных и текстов задач.
- Скрипт `--all` может выполнять тяжёлые запросы по всем компаниям:
  использовать его только в согласованное окно обслуживания.
- Локальные проверки под PHP 8.4 не подтверждают работу под PHP 8.1 на сервере.
