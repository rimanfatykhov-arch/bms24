# RELEASE NOTES — 0.9.0.2 / build 2026092414

## Назначение

Убрать второй редактор планирования и путаницу между исполнением конкретного проекта
и управленческим периодом. Реализовано по согласованному разбору экрана
«Исполнение и встречи / Управленческий цикл». Новый самостоятельный домен не создан.

## Изменения

- У проекта в Административной шкале появились вкладки «Описание» и «Исполнение».
  Вторая вкладка — read-only проекция уже существующих объектов, а не отдельная БД.
- Отображаются ожидаемый результат, ответственная должность, продукт и сроки проекта;
  исходное основание/трассировка остаются в заголовке карточки. Связанный показатель
  открывается в каноническом разделе; факт автоматически не меняется.
- В задачах показаны статус, исполнитель, срок, продукт, план/факт минут и записанный
  результат. Ссылки ведут в существующие задачи и разрешённые пользователю Боевые планы.
- Задачи приходят по явной связи с проектом, по точной исходной редакции дочернего
  task-definition Административной шкалы или по решению доступной встречи проекта.
  Дубли между этими путями исключены одним SQL SELECT/EXISTS. Встреча не является
  обязательной предпосылкой создания/исполнения задачи.
- Встречи видны только при активном участии пользователя. Руководитель не получает
  доступ к чужой приватной встрече через карточку проекта. Задачи проверяются отдельно
  по существующим task/plan participant rules до получения строк.
- Счётчики относятся только к доступному пользователю срезу этого проекта. «Завершена»
  и «есть запись результата» считаются отдельно. Ноль здесь не означает отсутствия
  работы во всей компании; результат задачи не доказывает достижение цели проекта.
- Исторические source/context revisions не перепривязываются к текущей редакции.
  Устаревшие привязки встреч и явных проектных задач отмечаются; просмотр не завершает
  задачи, не меняет факт показателей, сроки, статусы или историю.
- Дублирующий экран исключён из видимого меню. Верхняя группа «Планирование» теперь
  содержит Управленческую неделю, Боевой план и Управленческие циклы. Переход из цепочки
  обзора управления исправлен на канонические Управленческие циклы.
- `administrative_cycle.php` оставлен как совместимый GET/HEAD переход. Старые операции
  изменения не пересылаются и не выполняются. Ссылка на проект из встречи открывает
  новую вкладку; редактирование плановых объектов остаётся в единой форме.

## Архитектурные границы

Переиспользованы `administrative_cycle_service`, `administrative_scale_ui_service`,
`task_service`, `meeting_service`; добавлены read selectors в существующие классы.
Новых классов domain engines, таблиц, capabilities, web service endpoints или cron нет.
`db/install.xml`, `db/upgrade.php`, `db/access.php`, `db/services.php`, `db/tasks.php` и
privacy provider byte-identical базе 0.9.0.1. Канонические mutators планирования,
управленческих периодов, Боевых планов и интеграций не изменены.
KBA Theme остаётся presentation layer. AI/provider transport и operational actual не менялись.

## Ограничения среза

Подзадачи без собственной связи с проектом не приписываются ему автоматически.
Недоступные встречи/задачи/Боевые планы не раскрываются; итоговые количества не являются
общекорпоративной аналитикой. Отдельное подтверждение бизнес-эффекта проекта не добавлено.
Вкладка не является редактором факта, новым канбаном или task engine.
Создание встречи доступно по прежним правилам для опубликованного актуального проекта;
кнопка только открывает существующий workflow, не создаёт встречу при просмотре.
