# BMS v0.5.7 — Управленческое действие из строки показателя Боевого плана

Build: `2026091505`

## Цель

Замкнуть недельный цикл управления прямо в строке канонического показателя: состояние -> решение руководителя -> canonical Task -> ссылка в тот же Боевой план.

## Реализовано

- В ячейке «Состояние» канонического показателя появился раскрываемый блок «Управленческое действие».
- Руководитель подтверждает аналитическое состояние или выбирает контекстное; контекстное решение по-прежнему требует комментария.
- Вместе с решением задаются название задачи, ожидаемый продукт, описание, приоритет, срок и план времени.
- Исполнитель, проверяющий и наблюдатель не принимаются из браузера: они берутся из выбранного Боевого плана.
- Создаётся только canonical `local_kbacompany_task` с `sourcekind=condition`; в Боевой план добавляется существующая ссылка `bplanitem`.
- Если задача уже существует для решения, но ещё не добавлена в текущий план, её можно добавить без создания копии.
- Если задача существует, но недоступна по ACL, её содержание не раскрывается.
- Точная повторная отправка одного решения идемпотентна. Soft-deleted Task не воскрешается.

## Историческая корректность

Endpoint действия повторно вычисляет каноническую проекцию на неделю выбранного плана и не доверяет состоянию/периоду клиента. Событие фиксирует точную revision `statbind` и период последнего факта, использованного аналитикой; если фактов нет вообще — неделю Боевого плана. Более новые факты не могут попасть в решение старого плана.

## Схема

Schema-neutral. Новых таблиц, полей, capabilities и external services нет. `upgrade.php` содержит только savepoint `2026091505`.

## Совместимость

Moodle production target: 4.1.22. PHP target: 7.3. Legacy pinned quota state overrides остаются compatibility-only и не участвуют в новом action bridge.
