# BMS24 — RC29 / build2026101620

**Дата:** 16.10.2026  
**Компонент:** `local_kbacompany`  
**Основа:** RC29 / build2026101519 (приложенный установочный архив)  
**Стандарт:** BMS-UX-CRUD-001 v0.3  
**Тип:** UX и серверная валидация; **без изменений схемы БД**.

## Что изменено

1. Добавлен однозначный контекст создания задачи: период боевого плана и владелец-исполнитель.
2. В основной части формы создания оставлены название, ожидаемый продукт, исполнитель (показывается без редактирования) и срок выполнения. Описание перенесено в раскрываемые дополнительные настройки.
3. Срок новой задачи обязателен и на клиенте (`required`), и при POST на сервере. При ошибке значения формы сохраняются. Отдельный редактор задач и шаблоны не меняют прежнюю валидацию срока.
4. Исполнитель устанавливается существующим `battle_plan_service::create_manual_task()` по владельцу плана. Изменение на произвольного пользователя запретили намеренно: `battle_plan_service::add_task()` разрешает задачи только исполнителя этого плана.
5. Список существующих задач теперь показывает карточки выбора с источником, исполнителем, состоянием и сроком, не только одно название. POST сохраняет прежний идентификатор `provider::externalid`.
6. Исправлено сохранение сценария `flow=existing` при поиске GET (ранее возвращалось в режим создания).
7. Добавлены кнопки отмены и выравнивание основных действий справа в выборе существующей задачи.
8. Включены существующие кнопки ИИ-помощи для названия, продукта и описания непосредственно возле полей. На экране добавления задачи не выводится большая самостоятельная форма ИИ. ИИ по-прежнему только предлагает текст, не сохраняет задачу автоматически.
9. Сохранён ранее реализованный переход из имени исполнителя в существующую карточку сотрудника (build2026101518); его код не менялся.
10. Канонические сервисы и таблицы задач, боевых планов, регулярных задач, UUID и разграничение компаний не изменялись.

## Установка

1. Сохранить резервную копию каталога `local/kbacompany` и БД Moodle.
2. Развернуть `INSTALL_ME_local_kbacompany_v1.1.0-rc29_build2026101620.zip` так, чтобы на сервере итоговый каталог был `local/kbacompany` (в архиве верхний каталог `kbacompany`).
3. Выполнить обновление плагина стандартными средствами Moodle (`Site administration → Notifications` или `php admin/cli/upgrade.php --non-interactive`).
4. Очистить кеши Moodle.
5. Пройти тесты из `ACCEPTANCE_RC29_TASK_PLAN_BUILD2026101620.md`.
6. При ошибке не пытаться установить более старую версию поверх новой без планирования отката данных и версии Moodle.
