# BMS24 · 1.1.0-rc29 · build2026101807

## Унификация кнопок и действий форм по BMS24 UI Kit

**Статус:** установочный кандидат после локальной проверки; **рабочий `edu.kzn.mba` не обновлялся, визуальная и E2E-приёмка не выполнялись**.

### Основание

На странице настройки главного инструмента `bms_home_preferences.php` и на странице порядка виджетов `bms_workspace_widgets.php` первичные кнопки имели белый текст без ожидаемого зелёного фона. Причина — использование `kba-bms-button kba-bms-button--primary` в теле страницы; текущие правила Owned App Shell описывали legacy-класс преимущественно внутри `.bms24-topactions`. Внутри `.bms24-content` не было универсального оформления для этих классов. BMS24 UI Kit уже содержит каноническую пару `bms24-ui-btn bms24-ui-btn--primary`.

### Что изменено

1. `bms_workspace_widgets.php` — «Сохранить расположение» использует `bms24-ui-btn bms24-ui-btn--primary`, «Отмена» и сброс — нейтральный `bms24-ui-btn`; пара «Сохранить / Отмена» находится в общей группе `bms24-ui-actions`; форма сброса получила отдельный CSS-контекст `bms-widget-reset-form`.
2. `bms_home_preferences.php` — «Сделать главным и сохранить» переведена на канонический primary-класс, «Отмена» — на нейтральный. Добавлена группа действий с мобильным переносом.
3. `bms_workspace.php` — кнопки **внутри содержимого рабочего пространства** (карточки задач, архитектуры, менеджмента, модальное окно первичного выбора, персональные настройки и быстрые ссылки) переведены на канонические классы. Topbar оставлен неизменным.
4. `bms_ui/ui_kit.css` — уточнена контрастность primary-кнопки при клавиатурном фокусе и disabled-состоянии.
5. `styles.css` — добавлена ограниченная CSS-совместимость canonical-кнопок для KBA Theme / стандартного Moodle: формы персональных настроек, рабочее пространство и модальное окно; состояния hover, focus-visible, disabled, адаптация действий.
6. `docs/BMS24_BUTTON_ACTION_STANDARD_RC29.md` — зафиксированы типы кнопок, классы, поведение, доступность, архитектурная граница и правила сохранения форм.
7. `cli/check_bms_button_standard_1807.py` и `cli/build_release.py` — отдельный контракт проверки класса кнопок, формы, маршрутов, защиты POST и подключения CSS теперь включён в release gate.
8. `version.php`, `db/upgrade.php` — сборка 2026101807 и Moodle upgrade savepoint. Новых таблиц, полей, capabilities и модификаций данных нет.

### Границы изменений

- **Не изменены** POST-handlers, логика сохранения настроек, `require_sesskey`, capabilities, персонализация в разрезе компаний, маршруты, БД и бизнес-процессы.
- Legacy-классы в правой верхней панели `bms_page_shell_service.php`, `bms_workspace.php` и `bms_architecture.php` сохранены: App Shell имеет отдельный контракт topbar, и его миграция потребовала бы независимой визуальной приёмки.
- Универсальные `btn btn-primary` и собственные рабочие controls в других модулях не переопределяются массовой заменой; они уже поддерживаются через `bms_ui/ui_kit.css`. Это целевой аудит обнаруженного дефекта, **не полная визуальная приёмка всех CRUD-форм**.

### Проверки

- `python3 cli/check_bms_button_standard_1807.py`: 26 контрактных проверок, без подключения к Moodle.
- `python3 cli/build_release.py`: PHP lint всех PHP, регрессионные проверки RC29, XMLDB, локализации, корректность upgrade, ZIP и SHA256 — результат указан в артефакте `BUILD_RESULT.json`.
- Запуск тестов в данной среде использует PHP CLI 8.4.24. PHP 8.1 проверяется статическими контрактами; **реальная приёмка под PHP 8.1 не выполнялась**.

### Рекомендуемая приёмка на edu.kzn.mba

1. Сделать резервную копию БД и плагина, установить новую версию, проверить `2026101807`, очистить кэш Moodle.
2. Открыть `bms_workspace_widgets.php?uuid=...`: убедиться, что кнопка «Сохранить расположение» зелёная с контрастным белым текстом, «Отмена» нейтральная, «Вернуть расположение по умолчанию» читается. Проверить реальное сохранение, повторный вход, сброс и сохранение прав.
3. Открыть `bms_home_preferences.php?uuid=...`: «Сделать главным и сохранить» зелёная, «Отмена» нейтральная. Сменить основной инструмент и проверить сохранение, вернуться к прежнему.
4. Открыть рабочее пространство: проверить кнопки карточек, открытия разделов, быстрые действия и разовое диалоговое окно нового пользователя. Проверить отсутствие повторной верхней ссылки «Сменить главный инструмент».
5. Пройти через интерфейс с клавиатуры (`Tab`, `Enter`), в состоянии hover и на ширинах 320, 375, 768 и 1440 px. Проверить контраст и отсутствие перекрытия кнопок.
6. Повторить в альтернативной KBA Theme / Moodle fallback (если активируется) и под сотрудником без прав управления; проверить, что недоступные действия не появляются.
7. Проверить server logs / DevTools на CSS 404 и PHP warnings. Браузерное сравнение CSS при пользовательской теме — часть приёмки.
