# BMS24 — 1.1.0-rc29 build2026101808

## Назначение
Компактное рабочее пространство с акцентом на ежедневные действия. Изменения на странице `bms_workspace.php` не затрагивают управленческий цикл, данные, роли и сценарии редактирования других модулей.

## Реальные изменения
- Удалена повторная горизонтальная навигация **только** на главной странице; левое меню и контекстные меню прочих модулей сохранены.
- Убраны постоянно отображавшийся баннер выбора главного инструмента и вторая ссылка «Настроить рабочее пространство» внутри контента. Настройка доступна в заголовке и левом меню; первичное модальное окно для новых пользователей сохранено.
- Заголовок изменён с имени компании на «Моё рабочее пространство»; название компании остаётся в хлебных крошках и корпоративном контексте.
- Блок «Сегодня» сокращён до одной компактной строки, **если нет ближайших событий и задач со сроком сегодня**; реальные счётчики и переход в календарь сохранены. Для активного дня остаётся полная карточка календаря.
- «Быстрые действия»: теперь создание задачи ведёт непосредственно в **существующую форму** `tasks.php?view=create`, Боевой план — в реальный объект/список, коммуникации — в соответствующий центр. Используется только действующий фильтр доступных навигационных маршрутов.
- Сокращены отступы статистики и управленческой недели, добавлена компактная адаптивная компоновка. Не меняется общий UI Kit других модулей.
- Сроки задач в предпросмотре сравниваются с локальным днём пользователя вместо UTC-дня.
- Существующие 9 виджетов, порядок, видимость, сохранённые настройки и серверная ленивaя загрузка не изменены.

## Архитектура и безопасность
- Только UI и read-only GET-маршруты. Никаких новых таблиц/permissions, изменение данных по GET отсутствует.
- Сохранены `require_login`, проверка компании, персональные разрешения, `sesskey` для изменяющих настроек.
- Доступность операций продолжает проверять целевой модуль. Навигация не предоставляет дополнительных прав.

## Проверки
- Новый `cli/check_workspace_1808_contract.py`: статическая проверка структуры, маршрутов, прав, режима «Сегодня», адаптивности, сохранения предпочтений и версии.
- Регрессионные контракты сборок 1799–1807, PHP lint, XMLDB, локализация, контроль ZIP/SHA256 — согласно журналу сборки.
- Проверка на целевом `edu.kzn.mba` не выполнялась. Доступный PHP CLI — 8.4.24; поведение Moodle 4.1 / PHP 8.1 и реальные метрики производительности требуют отдельной приёмки.

## Сценарии приёмки на Moodle
1. Открыть рабочее пространство и убедиться: дублирующей горизонтальной навигации и зелёного баннера больше нет; кнопка настройки виджетов доступна в заголовке, смена главного инструмента — в левом меню.
2. При пустом календаре блок «Сегодня» занимает одну компактную строку; ссылка в календарь открывается. Добавить событие — должна появиться полная карточка.
3. Проверить кнопку «Создать задачу»: открывается форма; обычное GET-открытие ничего не создаёт. Проверить создание по штатному POST.
4. Проверить «Мой Боевой план» с существующим планом и без него: ссылки корректны.
5. Скрыть и восстановить блоки, изменить порядок, обновить страницу. Настройки не теряются.
6. Проверить сотрудника, руководителя, владельца и двухкомпанейную изоляцию.
7. Проверить ширины 375, 768, 1280 px, клавиатуру и контраст кнопок.
8. Сравнить список и сроки задач вблизи смены суток пользовательского часового пояса.
9. Проверить KBA Theme и автономный BMS24 App Shell, если оба используются.

## Ограничения / следующий этап
Это UX-уплотнение, а **не** единая очередь управленческих действий. Следующим этапом `build2026101809` — безопасно объединить элементы «Требует моего действия» из существующих сервисов, убрать повторяющиеся ссылки на одно событие, сохранить детализацию по компании/сотруднику.
