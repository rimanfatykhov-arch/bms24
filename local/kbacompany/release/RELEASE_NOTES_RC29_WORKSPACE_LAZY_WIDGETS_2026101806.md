# BMS24 · 1.1.0-rc29 · build2026101806

## Оптимизация загрузки рабочего пространства и мобильной компоновки

**Статус:** установочный кандидат. Изменения подготовлены в исходниках и проверяются локальным release gate. **Установка и E2E-приёмка на `edu.kzn.mba` не выполнялись.**

### Причина

Сборка 1804 научила скрывать и менять местами девять виджетов, однако модель `bms_ui_service::workspace_model()` при каждом посещении страницы продолжала загружать полную оргструктуру, процессы, подробный центр коммуникаций и задач, данные управленческого обзора даже для скрытых блоков. Страница настроек также запускала полную модель без необходимости.

### Что сделано

1. `classes/local/bms_workspace_load_policy.php` — введена чистая политика зависимостей от разрешённого перечня видимых карточек. Не хранит пользовательских URL, не меняет возможности доступа.
2. `bms_workspace.php` — проверка контекста компании до чтения предпочтений; загрузка модели с актуальным перечнем виджетов. При скрытом виджете архитектуры больше не отображается фиктивный нулевой показатель сотрудников в шапке. Отдельные загрузки календаря и личного плана, добавленные ранее, сохранены.
3. `classes/local/bms_ui_service.php` — аргумент `?array $visiblewidgets = null` для обратной совместимости. При `null` модель полностью сохраняет прежнее поведение; при списке активных карточек тяжёлые сервисы вызываются лишь при необходимости:

| Активные карточки | Чтение из сервиса |
| --- | --- |
| Архитектура или Компания | Организационная структура |
| Архитектура | Контекст процессов |
| Задачи, Обзор или Требует внимания | Полная коммуникационная модель и задачи |
| Обзор | Дополнительный контур обучения |
| Управление или Требует внимания | Управленческие отклонения и Боевые планы (только для пользователей с правами) |
| Нет подробных рабочих блоков | Облегчённые счётчики App Shell вместо загрузки сообщений и карточек задач |

4. `bms_workspace_widgets.php` — страница настройки виджетов вызывает только штатную проверку компании и проверку прав, без полной модели домашнего экрана.
5. `styles.css` — адаптация карточек к экранам до 640 px: единая колонка, перенос длинных строк, доступные по ширине кнопки и быстрые ссылки. Базовый сеточный макет на десктопе сохранён.
6. `cli/test_workspace_1806_policy.php`, `cli/check_workspace_1806_contract.py` — добавлены тесты политики выборочной загрузки и проверки интеграции с исходным кодом, обязательные для сборщика.
7. `cli/check_bms_workspace_widgets_contract.py`, `cli/check_main_tool_topbar_cleanup.py` — прежние проверки адаптированы к правомерному изменению порядка загрузки и повышению версии, проверка удаления дублирующей верхней ссылки сохранена.
8. `version.php`, `db/upgrade.php` — версия `2026101806`, шаг обновления без новых таблиц и миграции данных.

### Обратная совместимость и границы

- Прямые ссылки, запись предпочтений и порядок блоков не изменяются.
- Все серверные ACL и разделение по компаниям остаются на исходных сервисах; пользователь не может указать произвольный источник данных.
- Счётчики для навигации при скрытых рабочих блоках формируются более лёгким `communication_center_service::shell_counters()`. Счётчики, включающие дополнительные провайдеры задач, могут отличаться от полного рабочего центра. Сравнить в приёмке на реальных данных.
- Никаких миграций XMLDB, новых capabilities или новых таблиц нет.
- Локальная проверка политики и исходного кода **не доказывает** конкретного ускорения в миллисекундах без инструментирования Moodle и профилирования SQL на тестовом сервере.
- Бизнес-логика согласования Боевых планов и управления KPI не затрагивалась.

### Локальные проверки

- `php cli/test_workspace_1806_policy.php` — 30 сценариев политики (без Moodle DB).
- `python3 cli/check_workspace_1806_contract.py` — 23 проверяемых исходных условия.
- Полный `python3 cli/build_release.py` — набор регрессий предыдущих сборок, проверка XMLDB, RU/EN языковых строк, PHP lint, ZIP и SHA256.
- Локальный PHP CLI: 8.4.24; проверка на реальном PHP 8.1 отдельно требуется.

### Рекомендуемая приёмка на `edu.kzn.mba`

1. Создать копию БД и каталога плагина. Установить ZIP поверх существующего `local_kbacompany`, убедиться в версии `2026101806` и очистить кэши Moodle.
2. Под пользователем-руководителем открыть рабочее пространство с девятью активными блоками: проверить корректность счётчиков, отклонений, списка задач и карточки плана.
3. Скрыть «Архитектура», «Компания», «Управление», «Обзор», «Задачи», «Требует внимания», оставив «Сегодня», «Мой Боевой план», «Быстрые действия». Убедиться, что нет PHP warnings и ошибки отсутствующих ключей; переходы работают.
4. Профилировать через Moodle DB debugging/logging число SQL запросов и время страницы до/после скрытия блоков на одних и тех же данных; ожидание — сокращение полной загрузки сервисов, **числа не прогнозируются**.
5. Вернуть «Архитектуру» и «Управление»: проверить реальные данные и сохранность прав, разграничение компаний.
6. Под сотрудником без прав управления: виджет «Управление» не предоставляется; настройки другой компании не переиспользуются.
7. На мобильной ширине 320, 375, 640 px проверить отсутствие горизонтального скролла всей страницы и читаемость содержимого карточек; таблицы при необходимости прокручиваются локально.
8. В KBA Theme и резервном стандартном режиме Moodle проверить аналогичное поведение; пересохранение/сброс порядка работает.
9. В левом меню команда «Сменить главный инструмент» остаётся, в верхней правой панели её по-прежнему нет.
10. Сверить счётчики задач и обучения при разных конфигурациях виджетов; отдельно проверить внешние провайдеры задач при их использовании.
