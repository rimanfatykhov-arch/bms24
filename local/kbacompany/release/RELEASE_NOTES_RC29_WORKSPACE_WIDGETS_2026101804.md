# BMS24 1.1.0-rc29 · build2026101804
## Персональная настройка виджетов рабочего пространства

**Состояние:** установочный кандидат для приёмки. **Рабочий Moodle `edu.kzn.mba`: приёмка НЕ проведена.**

### Цель

Продолжение build2026101803: пользователь BMS24 может выбрать видимые информационные блоки и их порядок в пределах активной компании. Изменения **не меняют данные, права, бизнес-операции или выбранный главный инструмент**.

### Изменения

- Создан независимый серверный `bms_workspace_widget_service`: фиксированный белый список девяти существующих карточек (`today`, `plan`, `actions`, `overview`, `attention`, `tasks`, `management`, `architecture`, `company`), нормализация сохранённого JSON, отказ от неизвестных ключей, сортировка по позициям с детерминированной обработкой совпадений, фильтрация доступности `management`.
- Добавлена страница `/local/kbacompany/bms_workspace_widgets.php?uuid=...` с чекбоксами видимости, позициями, клавиатурными/кнопочными стрелками изменения порядка и командами «Сохранить» / «Вернуть по умолчанию».
- В рабочем пространстве добавлена команда «Настроить рабочее пространство». Блоки выводятся в сохранённом порядке в адаптивной сетке, без JS-зависимости от сохранения; сохранены существующие ссылки и содержимое карточек.
- Настройка существует отдельно для каждой комбинации **Moodle user ID + компания**, использует `set_user_preference` и хеш идентификатора компании в имени предпочтения.
- Разрешения не расширяются: доступность карточки «Управленческая неделя» определяется по `management_home.available` из авторизованной модели `bms_ui_service::workspace_model`. Неизвестные ключи никогда не попадают в шаблон.
- В стандартном fallback Moodle теперь также отображаются видимые карточки по сохранённому порядку; этот режим показывает упрощённые данные, как и ранее.
- Скрытие «Сегодня» пропускает отдельный агрегирующий вызов календаря; скрытие «Мой Боевой план» пропускает отдельный запрос к плану. Остальные данные пока извлекаются через существующий `workspace_model` и независимо от видимости, что отмечено как зона следующей оптимизации.
- Не используются новые XMLDB-таблицы или поля. Добавлен штатный Moodle upgrade savepoint `2026101804`.

### Безопасность

1. Авторизация `require_login`; `local/kbacompany:viewowncompany` + `workspace_model` для проверки фактического доступа к компании.
2. Изменения **только POST** с `require_sesskey()`; GET не меняет пользовательские предпочтения.
3. Сервер принимает только предопределённые идентификаторы карточек, а не URL или HTML; проверяется доступность управленческой карточки.
4. Сохранение выполняется от имени текущего `$USER->id`. Передавать ID другого пользователя или компании в форму невозможно без прохождения доступа к этой компании.
5. При повреждённом сохранённом JSON или исчезновении карточки список безопасно восстанавливается. Нельзя скрыть вообще все карточки.

### Установка

1. Сделать резервную копию файлов `local_kbacompany` и БД Moodle.
2. Установить пакет как обновление существующего плагина, **не копировать папку `kbacompany` дважды**.
3. Пройти обновление администратора Moodle, убедиться в версии `2026101804` и очистить кэши.
4. Войти в компанию и выбрать «Настроить рабочее пространство».
5. Рекомендуется сначала проверить на копии портала/стенде, затем выполнить приёмку на рабочем портале.

### Сценарии ручной приёмки на Moodle

1. У существующего пользователя после обновления все стандартные блоки отображаются в исходном порядке.
2. Нажать «Настроить рабочее пространство», скрыть «О компании», сохранить. Карточка должна исчезнуть, остальные остаться.
3. Переместить «Задачи» выше «Сегодня» (стрелками или позицией), сохранить. Проверить порядок.
4. Обновить страницу, выйти и войти: порядок и видимость сохраняются.
5. Восстановить стандартную раскладку, проверить возвращение скрытого блока.
6. Попытаться убрать все флажки: должна быть понятная ошибка; пустой стартовый экран не сохраняется.
7. Для другого пользователя в этой компании — независимые настройки.
8. Для одного пользователя в двух компаниях — независимые настройки.
9. Под сотрудником без management-привилегий нет карточки «Управленческая неделя» и её настройки; под руководителем доступна.
10. Попытка подменить POST и записать неизвестный ключ / скрытую по правам карточку отвергается.
11. Прямые ссылки на задачи, Боевые планы, KPI и архитектуру по-прежнему работают.
12. Проверить работу в Chrome и на узком экране; кнопки ↑/↓ доступны с клавиатуры, порядок меняется после сохранения.
13. Проверить fallback при отключённом KBA Shell: упрощённые блоки отображаются в заданном порядке.
14. Проверить сохранение предыдущего «Главного инструмента» — оно не должно измениться.

### Известные ограничения и дальнейший план

- Перетаскивание мышью в MVP не добавлялось: доступный способ — кнопки перемещения вверх/вниз и номера позиций.
- Блоки не конструируются из произвольных пользовательских виджетов — разрешён только существующий каталог.
- Консолидация запросов `workspace_model`, оптимизация невидимых карточек, визуальный E2E и замер времени загрузки планируются после фактической приёмки.
- После успешной приёмки: UX-полировка персонального рабочего пространства, затем возврат к стабилизации RC30.
