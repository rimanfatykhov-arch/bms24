## 1. Классификация задачи менеджером

- [ ] В карточке открытой задачи у менеджера доступно «Закрепить ответственность за должностью».
- [ ] Варианты — только действующие основные должности текущего `assigneeid` данной компании.
- [ ] Неавторизованному сотруднику пункт и POST недоступны.
- [ ] POST требует sesskey, явное подтверждение и точную revision; повторная старая форма отклоняется.
- [ ] Выбор другой компании, другой должности, чужого `assigneeid`, закрытой задачи отклоняется.
- [ ] Смена персональная ↔ должностная пишет `tasklog:duty_classification`; UUID не меняется.

## 2. Передача исполнения

- [ ] Дано одобренное замещение для основного работника, должности и периода. До начала периода исполнитель — первоначальный.
- [ ] В день начала (UTC) должностная задача появляется в «Моих задачах» замещающего; у исходного сотрудника исчезает из scope=my, но остаётся доступной для просмотра истории.
- [ ] На карточке видны первоначальный и текущий исполнитель. `start` и `submit` разрешены замещающему.
- [ ] `start`/`submit` через прямой POST от исходного исполнителя в период замещения отклоняются.
- [ ] Список/счётчики «Мои задачи» совпадают со временем исполнения и не дублируют задачи.
- [ ] У персональной задачи ничего не меняется. У чужой компании нет доступа или выдачи/подмены обязанностей.
- [ ] На дату окончания включительно замещающий ещё исполнитель; на следующий день исполнение возвращается основному сотруднику.
- [ ] При отмене замещения исполнение немедленно возвращается основному сотруднику; роль RBAC не меняется.

## 3. История и сохранение границ

- [ ] Проверяющий (`reviewerid`) по-прежнему согласует или возвращает, без автоматического переназначения.
- [ ] Изменения и действия фиксируются актёром в `tasklog`, исходный `assigneeid`, task UUID и привязки боевых планов остаются прежними.
- [ ] Задача с чеклистом и файлом результата: исполнитель может отправить результат; `submit` не теряет вложение из-за перехода к review/done.
- [ ] Приватные обсуждения остаются под ACL Communications Center (не выдавать автоматических прав).
- [ ] У старой задачи `positionwork`, созданной до обновления, связь не проставилась без согласования руководителя.
- [ ] Новая task `positionwork` получает `dutypositionuuid`; регулярный генератор не создаёт дубликатов при смене исполнителя.
