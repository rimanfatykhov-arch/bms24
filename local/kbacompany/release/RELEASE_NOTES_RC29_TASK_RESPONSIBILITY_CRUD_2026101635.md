# BMS24 RC29 / build2026101635 — Task responsibility CRUD hotfix

**Основа:** полный `local_kbacompany` build2026101634. **Назначение:** исправить невозможность изменить «Тип ответственности» в карточке задачи и выбрать его при создании. **Схема БД:** без изменений (используется `local_kbacompany_task.dutypositionuuid` из build2026101634).

## Исправлено

1. В `tasks.php?task=...` на вкладке «Обзор» у реквизита «Тип ответственности» для уполномоченного пользователя теперь показана явная кнопка **«Изменить тип»**. Прежнее действие не потеряно: остаётся тот же защищённый экран `operation=classifyduty`, POST, sesskey, подтверждение, revision и аудит. Больше не требуется искать его в выпадающем «Действия».
2. **CreateView и EditView** стандартного Task Center содержат поле «Тип ответственности» для пользователей, имеющих company-scoped право управления задачами (`task_service::can_manage`, включая разрешение RBAC `task:edit`). Выбор: персональная задача (значение по умолчанию, никакой автоматической передачи) или одна из действующих **основных должностей выбранного исполнителя**.
3. При смене исполнителя поле подгружает доступные должности через новый GET `tasks.php?view=dutypositions&assigneeid=...`. Только уже авторизованный руководитель может получить список. Серверная проверка должности сохраняется при каждом сохранении — прямой POST с чужой/отменённой/иной должностью не проходит.
4. Новая ручная задача может сразу получить привязку должности **в той же транзакции, что и создание**, без второго действия на карточке. При изменении существующей задачи смена классификации атомарно фиксируется вместе с задачей с историей в `tasklog`. Исходный `assigneeid`, UUID и статус остаются прежними.
5. Для новой/изменённой привязки к должности руководитель должен явно подтвердить, что задача и материалы допустимы для передачи замещающему. Без подтверждения POST не сохраняется. Снятие привязки возвращает персональную ответственность. Для неуполномоченных сотрудников отдельное поле недоступно, а сервер отвергает попытку подмены.
6. Если у сотрудника нет активной основной должности, форма объясняет, что сначала нужно оформить назначение в разделе «Люди → Должности и роли». Личные задачи можно создавать независимо. Статусы `review`, `done`, `cancelled`, `deleted` не допускают изменение классификации.

## Границы

- Утверждённая схема BMS-POS-COVERAGE-02 сохраняется: изменение `dutypositionuuid`, **не** `assigneeid`; изоляция компании и ACL по должности; метрики/календари/регулярные определения не переназначаются.
- Существующие задачи не переводятся автоматически, менеджер выбирает ответственность осознанно.
- Кнопка относится к каноническому **Task Center**. Создание из боевого плана продолжает использовать ранее согласованный поток; впоследствии ответственность можно назначить прямо в карточке созданной задачи.
- Дополнительных SQL-таблиц и DDL нет. Версия и no-DDL checkpoint `2026101635`.
