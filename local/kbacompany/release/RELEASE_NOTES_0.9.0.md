# local_kbacompany 0.9.0 — Integration Identity Foundation

Build: `2026092412`. Статус: ALPHA, устанавливаемый development checkpoint.
База: загруженный пользователем INSTALL 0.8.12 build 2026092411.
Это функциональный релиз плагина, не внешний Acceptance Kit.

## Что появилось

В BMS → Настройки → Интеграции открыт рабочий реестр ручных связей с Odoo и Bitrix24.
Поддержаны канонические Компания, Должность и Показатель. UUID BMS не меняются.
Создание выполняется в два шага: проверка/предпросмотр → явное подтверждение → повторная
серверная проверка прав, компании, объекта и конфликта → сохранение.
Можно открыть карточку связи, фильтровать сохранённые/закрытые связи и закрыть связь
без удаления ID. Повторная отправка той же активной связи не создаёт вторую запись.

Сначала регистрируется компания во внешней среде, затем её должности/показатели.
Компания не может быть закрыта, пока существуют активные дочерние связи этой среды.
Для архивной BMS-компании нельзя создавать новые связи; история доступна по прежним правам.
Закрытые ID зарезервированы: автоматического повторного открытия или переназначения нет.

## Границы

Это декларация соответствия ID, подтверждённая человеком, а не проверенное соединение.
Внешний API не вызывается; существование объекта у провайдера не проверяется.
Нет импорта факта, изменения показателей, создания задач, отправки outbox или фонового обмена.
Текущая связка Bitrix24 → KBA Connect работает через прежнее пространство связей.
Новые связи её не заменяют и автоматически в неё не переносятся.
Не создавались новый AI plugin, Integration Hub worker, task/KPI engine или ERP ledger.

## Схема и права

Расширена только существующая `local_kbacompany_extmap`: Company UUID, среда, внешняя модель,
namespace, UUID связи, хеш внешней идентичности. Новых таблиц нет.
Прежние записи получают пустое пространство имён и NULL в новых уникальных ID-полях.
Индексы обеспечивают сохранение прежней уникальности и независимость новых сред.
Конфликт с чужой компанией отклоняется ограничением БД без чтения чужой записи.
Создание/закрытие используют транзакцию, Moodle Lock API и стандартные события Moodle.
Права и API-declarations не расширены. Используется существующее управление организацией;
для изменения связи показателя дополнительно проверяется существующее право управления показателями.
Срок хранения стандартных событий зависит от включённого Moodle logstore и его настроек.
