# BMS24 — 1.1.0-rc29 build2026101809

## Назначение
Единый личный центр «Требует моего действия» в рабочем пространстве, заменяющий разрозненные управленческие тревоги на **актуальные действия текущего пользователя**. Основа: проверенные сервисы задач BMS, согласований Боевых планов и управленческих отклонений KPI. Не является общей очередью проблем компании и не предполагает автоматического назначения виновных.

## Реализовано
- Новый read-only сервис `classes/local/bms_workspace_action_service.php`: формирует персональную очередь, объединяет события по ID исходного объекта, сортирует по подтверждённому состоянию и дате (упрощённые приоритеты), ограничивает выдачу восемью элементами без выдачи этого ограничения за общее число проблем.
- **Личные канонические задачи BMS**: просрочено, срок сегодня, возвращено на доработку. Исключены завершённые, чужие и внешние провайдеры. Реальная карточка открывается через `tasks.php?uuid=...&task=...`.
- **Задачи на приёмке**: отдельная проверка существующего канонического фильтра `scope=review`; при совпадении с другими условиями одна задача появляется ровно один раз с приоритетом приёмки.
- **Боевые планы**: ограниченная выборка по компании и явно назначенному проверяющему, либо владельцу. Ожидающие согласования показываются назначенному проверяющему, а обычные черновики НЕ показываются как проблемы. Черновик показывается как доработка только при последнем достоверном событии `returned` в `statepayload`.
- **Управленческие решения по KPI**: только строки `requires_new_decision` из уже защищённого capability и компанией read-моделя руководителя, с переходом в раздел отклонений для нужного показателя.
- Дубли прежнего manager-only списка отклонений в виджете «Требует внимания» убраны, отдельный существующий виджет «Управленческая неделя» сохранён.
- Сохранены девять ID виджетов, их порядок и видимость, personalisation, KBA Theme и автономный BMS24 App Shell. Для стандартного Moodle fallback выведен тот же список действий.
- Весь интерфейс на RU/EN Moodle language strings. Разметка и стили очереди ограничены рабочим пространством.

## Безопасность и ограничения
- Источники по компании и actor, права проверяются через действующие сервисы и company context; ссылки только на внутренние известные GET-маршруты. Ни одна кнопка очереди не меняет данные.
- Не отображаются задачи внешних интеграций: нужны отдельные доверенные deep-link адаптеры/ACL. Сообщения и общее количество уведомлений остались в Коммуникационном центре.
- Очередь показывает **до 8** действий, не является полной статистикой по компании и не заменяет настоящие списки. Список личных задач из существующего read-моделя уже ограничен первыми 25 открытыми каноническими задачами; проверка согласований задач — 20; планов — 60. Приоритет высоких сигналов извлечённых из этих выборок не гарантирует глобальную полноту на больших базах.
- KPI-отклонения извлекаются из существующей затратной management модели только при видимом виджете. Не выводятся пользователям без управленческих прав.
- KPI-ссылка открывает страницу отклонений с переданным `stat`, но пользовательское действие/решение выполняется только в существующем модуле, с его проверками прав.
- Нет новых таблиц, миграций данных, ролей или изменений жизненного цикла задач/планов. XMLDB без изменений. Один checkpoint upgrade `2026101809`.
