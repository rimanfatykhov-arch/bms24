# BMS24 build2026101834 — Подзадачи и Боевые планы

## Пакет
- Plugin: `local_kbacompany`
- Версия: `1.1.0-rc29` / build `2026101834`
- База: `2026101833`
- Таблицы БД: **без изменений**
- Moodle PHP: целевой 8.1.34; локальные тесты синтаксиса отдельно от серверной приёмки.

## Изменения

1. **Недельная сводка в родительской задаче.** Для выбранной недели показываются: открытые подзадачи, включённые в доступные Боевые планы; открытые подзадачи без найденной доступной привязки; завершённые подзадачи.
2. **Без ограничения одной страницей.** Агрегат рассчитывается серверным SQL по всей разрешённой выборке, а не по 20 строкам карточки.
3. **Быстрые ссылки на планы.** В каждой видимой подзадаче на текущей странице есть переход к Боевому плану выбранной недели или действие «Добавить в Боевой план», ведущее в уже существующую проверяемую форму.
4. **Нагрузка по подзадачам.** В доступных планах недели показываются исполнители, количество подзадач и сумма запланированных минут; вывод ограничен 12 исполнителями.
5. **Ограничение доступа.** Сводка учитывает только доступные задачи и планы. При неполной видимости пользователь видит пояснение, вместо ложного утверждения об отсутствии планирования.
6. **Bugfix.** Удалена ссылка на неопределённую переменную `$provider` в методе `battle_plan_service::add_task()`; правила проверки прав, исполнителя и статуса сохранены.

## Архитектура
- Подзадачи — прежние записи `local_kbacompany_task` с `parentuuid`.
- Участие в плане — прежняя запись `local_kbacompany_bplanitem` c `provider=bms` и `externalid=taskuuid`.
- Ничего не копируется; статусы задач, приёмка и график плана не меняются.
- Подсчёт использует `EXISTS`, чтобы одна подзадача в нескольких планах не увеличивала число задач.
- Для выбора недели используется GET-параметр `subweek` с ISO-нормализацией в понедельник; изменения данных через GET не производятся.
- Серверная операция добавления уже существует: `task_service`/`battle_plan_service::add_task` через `tasks.php` POST + `sesskey`.

## Ограничения
- При ограниченном доступе «Нет в доступных БП» не означает, что подзадача вообще не запланирована.
- Сводка рассматривает **прямые** дочерние задачи, не сворачивает все уровни иерархии в одну задачу.
- Сумма плановых минут относится к подзадачам конкретного родителя, а не ко всей загрузке работника по всем проектам.
- Кнопка добавления открывает существующую форму выбора черновика; она не создаёт Боевой план автоматически.
- Полный PHPUnit на Moodle и реальная интеграционная приёмка не выполнялись.

## Порядок установки
1. Резервная копия Moodle и БД.
2. Обновить `local_kbacompany` до `2026101834` штатным способом Moodle.
3. Очистить кэши Moodle.
4. Открыть задачу с дочерними задачами и переключить неделю.
5. Проверить добавление одной подзадачи в черновик исполнителя и её появление в недельной сводке.
6. Проверить запрет чужого плана, завершённой задачи, повторной привязки и сохранение существующих БП.
