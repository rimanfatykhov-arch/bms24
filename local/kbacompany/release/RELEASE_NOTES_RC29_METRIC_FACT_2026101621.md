## Реализовано

1. Во вкладке **Боевой план → Метрики** прежний общий переход «Внести факт / действие» заменён на действие **«Внести факт» непосредственно у каждой должностной метрики**. Специализированные действия (управленческие решения и наследуемые квоты) сохранены по отдельной ссылке «Дополнительные действия с метриками».
2. В дневных метриках дата факта выбирается в пределах недели данного боевого плана; в недельных — дата жёстко совпадает с началом недели. Недельная сумма дневной метрики — read-only projection из истории ежедневных фактов.
3. После успешного ввода факта контроллер возвращает пользователя на вкладку «Метрики». Используются `POST + sesskey`, канонический `stat_uuid` и привязка метрики к должности плана.
4. Запись выполняется **через `product_service::record_value()`**, то есть общие проверки активности, даты, точности десятичного числа, блокировка записи и append-only версии метрик остаются едиными. Добавлен *узкий* параметр контекста боевого плана: он разрешён только для факта, доступного пользователю плана, только для должностной метрики и только внутри периода. Редактировать нормы и определения метрик этим способом нельзя.
5. В форме указан комментарий / причина корректировки. Повторная запись за ту же дату не перезаписывает исходную: для новой ревизии нужна причина. Имеется список фактов за дни недели с действием «Исправить». Полный ревизионный журнал продолжает храниться в канонической таблице.
6. Уточнены экранные статусы: «Факт не внесён», «Не задан план», «Данные неполные». На сводке вместо неопределённого «Нет данных» отображается «Без оценки» (сам статус в аналитическом контракте сохраняется `nodata`).
7. Для дневной метрики оценка не рассчитывается из несовпадающих по датам неполных плановых и фактических сумм. Если записи плана и факта есть на одинаковых датах, оценка отражает **промежуточный срез**, а не финальный недельный результат.
8. Переименована визуальная отметка важности метрики: «Критична по значимости» — отдельно от статуса исполнения.
9. Сохранены канонические UUID, текущие факты, шаблоны, связи, расчёты статусов, маршруты карточек метрик, механизмы управленческих задач и legacy-квот. Новых таблиц и миграций БД нет.

## Установка

1. Сделайте резервные копии каталога `local/kbacompany` и базы Moodle.
2. Установите `INSTALL_ME_local_kbacompany_v1.1.0-rc29_build2026101621.zip` поверх плагина. В архиве корневой каталог `kbacompany`, итоговый путь должен быть `local/kbacompany`.
3. Выполните стандартный Moodle upgrade через «Администрирование → Уведомления» или `php admin/cli/upgrade.php --non-interactive`.
4. Очистите кеши Moodle, протестируйте чек-лист ACCEPTANCE из комплекта.
5. Не устанавливайте предыдущую сборку после обновления без корректной стратегии отката (ошибка `cannotdowngrade`).
