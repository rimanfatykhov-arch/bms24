# BMS24 — Коммуникационный центр: редактирование и удаление сообщений

**Plugin:** `local_kbacompany` 1.1.0-rc29\
**Build:** `2026101828`\
**Тип:** функциональный релиз с миграцией БД

## Реализовано

- **Редактирование собственного сообщения.** В карточке активного сообщения автор видит «Редактировать», меняет текст и сохраняет. Сообщение получает метку «Изменено».
- **Удаление из переписки.** Автор выбирает «Удалить», подтверждает действие. Содержание скрывается от участников, а вместо него показывается «Сообщение отозвано». Удаление мягкое, не физическое.
- **История исправлений.** Добавлена таблица `local_kbacompany_commrev`, которая хранит предыдущую версию текста, автора изменения, тип операции и дату; через обычный интерфейс она не раскрывается. Для полной юридической политики хранения/удаления требуется отдельное решение владельца данных.
- **Строго авторские действия.** Руководитель компании или другой участник не может исправить чужое сообщение. Повторно изменить отозванное сообщение нельзя.
- **Сохранность связанных объектов.** Изменение и отзыв сообщения заблокированы, если на его основе создана задача или принято управленческое решение.
- **Проверка актуальности.** Перед изменением сервер сверяет хеш текущего текста и статуса с хешем, полученным из формы. Устаревшая форма отвергается.
- **Безопасность.** Изменения требуют авторизации в компании, активного участия в беседе, доступа к объекту, `POST` с Moodle `sesskey` и подтверждения удаления.
- **Вложения.** При мягком удалении сохранённые файлы не отображаются в переписке и не выдаются через стандартную проверку доступа pluginfile. Файлы физически не удаляются из аудиторского хранения.
- **Live-updates.** Информация об изменениях попадает в существующую систему проверки изменений через `thread.timemodified`.

## Порядок обновления

1. Сделайте резервную копию файлов Moodle, `moodledata` и базы данных.
2. Установите ZIP `local_kbacompany` поверх текущего RC29, не удаляя плагин.
3. Выполните штатное обновление Moodle для создания таблицы `local_kbacompany_commrev`.
4. Очистите кэши Moodle.
5. Под двумя тестовыми учётными записями проверьте создание, редактирование, отмену редактирования (без отправки), отзыв сообщения, обновление у второго участника, защиту от изменения чужого сообщения и запрет на изменение сообщения, породившего задачу.

## Ограничения

- Это **мягкое удаление** из пользовательского интерфейса; прошлые тексты остаются в закрытом журнале аудита. Не равнозначно полной процедуре удаления персональных данных.
- История версий не выводится пользователям в интерфейсе.
- Существующие упоминания остаются привязанными к сообщению при редактировании текста; при отзыве упоминания удаляются.
- Автоматические PHPUnit/Behat на установленном Moodle и полноценная серверная приёмка не проводились в текущей среде.
