# BMS24 1.1.0-rc29 — build2026101815

**Тема:** Добавление задачи внедрения Corporate в черновик Боевого плана пользователя без копирования.
**Пара:** local_kbacorporate 0.40.4 / build2026102513, bridge API >=1.22. **Дата:** 2026-10-25.

## Изменения

- Новый защищённый маршрут `/local/kbacompany/implementation_battle_plan_attach.php` открывается из задачи Corporate по `taskid`, `companyid` (числовой ID Corporate, не UUID BMS).
- BMS выбирает только доступные пользователю компании, с уже подключённым источником `kbacorporate_impl`, согласованным с публичным API Corporate. По имени компании ничего не сопоставляется.
- Проверка исходного Corporate company ID, статуса задачи, `attachable`, исполнителя и действующего источника. Сервис `battle_plan_service::add_external_task()` заново проверяет editable draft, company, исполнителя, состояние и наличие прежней привязки.
- Пользователь выбирает один из своих существующих черновиков по неделе. При отсутствии черновика даётся переход на штатное создание плана; автоматического создания/изменения статуса нет.
- Никакие изменения по GET. POST только с Moodle sesskey; redirect на фиксированный внутренний путь, без returnurl.
- Провайдер BMS дополнил нормализованную проекцию `corporate_company_id`, строго из подтверждённого Corporate company ID.
- Источником задач, обсуждений и приёмки по-прежнему является Corporate; новая строка канонической задачи BMS не создаётся.
- Новых таблиц, полей или миграций XMLDB нет. Версия плагина `2026101815`, checkpoint в `db/upgrade.php`.

## Требования установки

1. Backup Moodle и БД; убедиться, что Corporate >= 0.40.4 build2026102513 (вместе с этим этапом) и BMS provider Corporate ранее настроен и разрешён руководителем компании.
2. Установить `local_kbacorporate` пакет, затем `local_kbacompany` пакет. Выполнить штатный Moodle upgrade и purge caches.
3. Перейти в карточку задачи внедрения, открыть «Добавить в Боевой план», выбрать черновик и подтвердить.
4. Сверить связь с исходной задачей и обсуждениями. Исходные статусы/комментарии не должны измениться.

## Ручная приёмка на Moodle / PHP 8.1

- В компании А владелец задачи со статусом planned/inprogress видит кнопку и список **только собственных** editable draft планов.
- Задача со статусом review/completed/cancelled или из paused/completed программы недоступна для прикрепления.
- Отсутствие BMS/неподключённый источник/неподходящий company ID даёт отсутствие кнопки либо контролируемое недоступное состояние.
- Подмена в POST компании, Corporate task ID, `plan` другого работника, чужой компании или утверждённого плана отвергается.
- Повторное POST не создаёт повторную связь, отсутствует новая каноническая задача BMS.
- В карточке Corporate обсуждения/результат/вложения продолжают работать без изменений.
- Проверить двух независимых компаний с пользователями А и Б, и мобильный UX.
