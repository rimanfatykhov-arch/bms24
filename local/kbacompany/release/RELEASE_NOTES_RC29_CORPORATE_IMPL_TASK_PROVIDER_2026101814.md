# BMS24 local_kbacompany 1.1.0-rc29 — build2026101814

**Этап:** 1814 — подключение задач внедрения Corporate как read-only источника BMS24.  
**Основа:** BMS24 `2026101811`. **Зависимость для источника:** `local_kbacorporate >= 0.40.3`, публичный bridge API `>= 1.22` (build `2026102512`).  
**Область:** `local_kbacompany`. **Изменения БД:** нет.

## Что реализовано

1. `classes/local/task_provider/kbacorporate_impl_task_provider.php`: провайдер `kbacorporate_impl`, использует **только** публичные методы `bridge::list_implementation_task_projections()` и `bridge::get_implementation_task_projection()`. Не читает таблицы Corporate и не записывает туда данные.
2. Сопоставление компании: BMS UUID -> проверенный legacy Corporate company ID и/или Bitrix24 external company identity -> **публичный** `bridge::get_company_by_bitrix_id`. При противоречии идентификаторов источник выключен (fail-closed). Связь по названию исключена.
3. Явное подключение **руководителем, имеющим доступ в обоих контурах**, через «Задачи → Источники → Настройки источников». Сохраняется в существующей `local_kbacompany_tasksrc`; новые таблицы не добавляются. Произвольный ID Corporate вручную не вводится.
4. Задачи отображаются в существующем центре задач через фильтр «Внедрение BMS (Куратор)», в исходной корпоративной карточке доступна история обсуждений и сдача результата. В Боевом плане доступны только задачи, которые Corporate разрешил планировать (`attachable`). Для `review/completed/cancelled`, приостановленных программ и несогласованных статусов включение блокируется и на сервере.
5. Нормализация: planned->open, inprogress->doing, review->review, completed->done, cancelled->cancelled, иные->unknown. Дата/ответственный/продукт/программа — из Corporate, `canonical_task_uuid` пуст. Никаких копий и синхронизации статусов нет.
6. Локализация RU/EN и единый стиль кнопок BMS24. Тесты контракта + автономный runtime smoke, запущенные в рамках сборщика.

## Границы текущего релиза

- **Нет отдельной новой кнопки в `implementation_task.php` Corporate.** Выбор существующей внешней задачи для Боевого плана осуществляется уже имеющимся интерфейсом BMS24 после подключения источника. Отдельная кнопка у куратора и проект «Внедрение BMS» — следующие этапы.
- Руководители BMS24 без полномочий на внедрение в Corporate не получают задачи других людей из Corporate — BMS полномочия **не заменяют** Corporate ACL.
- Выборка из публичного API ограничена 500 задачами на запрос BMS для защиты нагрузки. На предприятиях с большой историей нужна серверная фильтрация/курсорная пагинация в следующем контракте API, иначе полный список может быть неполным.
- Кураторская роль сама по себе не разрешает доступ в BMS24. Реальная проверка компании/пользователей необходима на Moodle.
- Если `local_kbacorporate < 0.40.3` / API <1.22 или отсутствует, провайдер неактивен, остальные задачи BMS24 продолжают работать.

## Установка

1. Сохранить резервные копии файлов и БД обеих компонентов.
2. Убедиться, что `local_kbacorporate` обновлён до build `2026102512` и правильно работает страница куратора.
3. Установить этот ZIP через Moodle как `local_kbacompany` (`kbacompany/` в корне ZIP). Запустить обновление Moodle до версии `2026101814`, очистить кэш.
4. Открыть «Задачи → Источники → Настройки источников» под управляющим. При корректной связке компаний и полномочиях Corporate станет доступно «Внедрение BMS (Куратор)» → «Подключить источник».
5. Убедиться, что у сотрудника появились **его** задачи внедрения с кликабельной защищённой карточкой Corporate; другие компании не видны.
6. Проверить выбор задачи внедрения в черновик Боевого плана сотрудника, затем закрытые/проверяемые/отменённые задачи и отсутствие дублей.
7. Для двойной проверки выполнить logout/login сотрудника A, сотрудника B, управляющего A и куратора, затем попытаться сменить company UUID в URL. Доступ должен зависеть от обоих контуров.

## Выпускной контроль

Синтаксис PHP, статические контракты, XMLDB, языковые строки RU/EN, регрессия RC29 и ZIP проверены локально; результаты в отдельном отчёте. **Целевой Moodle 4.1, PHP 8.1 и реальные корпоративные данные — не тестировались в среде сборки.** Этот build не является подтверждённой стабильной RC30.
