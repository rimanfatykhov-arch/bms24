# Release Notes — BMS v0.5.3 build 2026091501

## Состояния показателей

Добавлен центральный `indicator_condition_service` поверх канонической истории показателей. Тренд, событие и состояние остаются разными аналитическими слоями.

Автоматически поддерживаются:

- Опасность;
- Чрезвычайное положение;
- Нормальная деятельность;
- Изобилие;
- Могучество.

`Несуществование` и `Смена Власти` доступны в методологической модели и формулах действий, но не выводятся из одной статистики автоматически: для них требуется организационный контекст.

## Явная методологическая политика

Добавлена versioned-таблица `local_kbacompany_statpolicy` для конкретной `statbind`.

Она хранит только явно утверждённые границы интерпретации качественных понятий методики — «очень резкое ухудшение», «крутой рост», «высокий уровень» и длительность ЧП/Могущества. Скрытые проценты в коде не используются.

## Интерфейс

- новая вкладка `Показатели → Состояния`;
- состояние в Информационном центре;
- состояние в общем реестре показателей;
- состояние, причина и рекомендуемая формула действий в карточке показателя;
- управление редакциями политики состояния по конкретной бизнес-привязке.

## Управленческие действия

Для каждого состояния BMS показывает методологическую формулу действий. Рекомендации не создают параллельный объект задачи и не создают Task автоматически. Исполнение должно конвергировать в существующий канонический Task/Боевой план после решения менеджера.

## Совместимость

- Moodle production target: 4.1.22;
- PHP compatibility target: 7.3;
- миграция additive;
- canonical Indicator остаётся `local_kbacompany_stat`;
- facts остаются append-only в `local_kbacompany_statval`;
- старые опубликованные Battle Plan quota revisions сохраняют прежний расчёт через compatibility adapter, но он больше не является общей формулой состояния BMS;
- `minval/maxval` сохранены.
- новая норма для уже настроенной привязки продолжает её UUID как новую revision, а не создаёт параллельный поток нормы.
