# BMS24 1.1.0-rc29 / build2026101624 — Battle Plan DOCX Export 2.1

**Основа:** install/source build2026101623. **Дата релиза:** 16.10.2026.

## Изменения

1. В конце Word-экспорта помещены две соседние графы **«План подготовил»** и **«План одобрил»**, каждая с должностью, ФИО, датой и временем. Блок отображается после всех потоков задач. Если план ещё не согласован, второй блок честно сообщает **«Не одобрен»** и не показывает ложную дату или фамилию утверждающего.
2. Источник аудита: `createdby/timecreated` для подготовившего; `approvedby/approvedat` для одобрившего. Если автор создания и владелец плана различаются, показывается фактический автор создания. Для исторических записей без `createdby` отображается владелец, но не выдумывается время. Должности извлекаются из BMS назначений должностей в контексте данной компании с фильтром интервала на дату события; если роль не определена, показывается тире.
3. Убран технический заголовок `[[bpu_metric_export_quota_or_plan]]` — добавлен локализованный резервный заголовок на период устаревшего языкового кэша Moodle. Название новой колонки — «План / квота».
4. В экспорте сохраняются «Прошлая неделя», «План / квота», «Состояние», «Факт», «Динамика»; данные предыдущей недели не подменяются текущими и не предполагаются известными, если записи отсутствуют.
5. В таблицах Word улучшены отступы внутри ячеек, переносы длинных надписей, формат дат DD.MM.YYYY и избавление от одинаковой даты начала/окончания.
6. У таблицы подписей установлен запрет разрыва строки между страницами.

## Архитектура

- Только read-only изменение export модели + DOCX OOXML, без новых таблиц/колонок, без смены UUID и без изменения прав. `battle_plan_service::context()` сохраняет основной ACL-check, дополнительные имена/должности получаются только по actor ID из данной компании.
- Word формат остаётся DOCX; исходная XLSM-книга не меняется, макросы не выполняются.
- `version.php` = `2026101624`, `db/upgrade.php` содержит монотонный no-DDL savepoint `2026101624`.

## Тесты

- 383 PHP-файла проверены синтаксически.
- Локальная OOXML-модель согласованного плана с 11 задачами сформирована, структурно проверена, DOCX отрисован на 2 страницах и визуально проверен.
- Проверена модель несогласованного плана: утверждающая подпись не формируется.

- В настоящем Moodle 4.1.22 экспорт по HTTP, извлечение ролей из реальной БД и соответствие реальной организации пока **не тестировались**.

## Инструкция установки

1. Сделать резервную копию `local/kbacompany` и базы Moodle.
2. Установить содержимое `INSTALL_ME` в `/local/kbacompany` (верхний каталог архива `kbacompany`).
3. Запустить Moodle upgrade (администрирование / CLI), затем очистить кэши Moodle, в том числе языковые.
4. Открыть существующий согласованный боевой план и нажать **«Действия → Выгрузить в Word»**.
5. В конце файла проверить два блока подписей с реальными датами. Повторить для черновика: утверждающая подпись должна быть пустой.
6. Проверить «Прошлую неделю»: без истории факт не придумывается, при частичной истории видно число внесённых дней.
