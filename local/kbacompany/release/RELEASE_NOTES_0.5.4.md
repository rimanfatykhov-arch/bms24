# Release Notes — BMS v0.5.4 build 2026091502

## Подтверждение состояния → каноническое исполнение

v0.5.4 завершает управленческий мост после аналитики показателей:

`Показатель → аналитическое состояние → подтверждение/контекст руководителя → каноническая задача → Боевой план`.

Автоматически вычисленное состояние по-прежнему не сохраняется как отдельный факт. BMS хранит только самостоятельное неизменяемое управленческое событие — подтверждение руководителя либо контекстное решение, если выбранное состояние отличается от аналитического вывода.

## Новый governance event

Добавлена additive-таблица `local_kbacompany_stateevt`.

Событие фиксирует:

- компанию;
- показатель;
- точную UUID/revision бизнес-привязки;
- период последнего факта;
- подтверждённое состояние;
- аналитическое состояние и причину на момент решения;
- комментарий руководителя;
- автора и время.

Событие не копирует `statval`, не содержит собственный факт показателя и не заменяет `statbind`/`statnorm`/`statpolicy`.

Если руководитель выбирает состояние, отличное от аналитического, комментарий обязателен. Это позволяет зафиксировать организационный контекст для состояний, которые нельзя корректно вывести только из графика, включая `Несуществование` и `Смена Власти`.

## Каноническая задача

При выборе исполнения BMS создаёт задачу только через существующий `local_kbacompany_task`.

Для трассировки добавлен источник задачи `condition`:

- `sourcekind = condition`;
- `sourceuuid = UUID события состояния`;
- `periodkey = период события`.

Отдельная таблица Action/ConditionTask не создаётся. Источник отображается в Центре задач и ведёт обратно к карточке показателя/вкладке состояний.

## Боевой план

Руководитель может сразу добавить созданную каноническую задачу в доступный черновик Боевого плана исполнителя.

Используется существующая `local_kbacompany_bplanitem` как ссылка на Task. Копия задачи в Боевом плане не создаётся. Существующая проверка принадлежности плана выбранному исполнителю и прав редактирования сохранена.

## Права и изоляция

Подтверждать состояние может только пользователь, имеющий существующее право управления показателями. Это не выдаёт ему автоматически права администратора других BMS-контуров.

История подтверждений доступна в контуре показателя, но сведения о связанной задаче и Боевом плане выводятся только если текущий пользователь имеет право видеть соответствующий canonical Task/план. Новый governance bridge не является обходом Task Center/Battle Plan access control.

## История и неизменяемость

`stateevt` является append-only журналом управленческих решений. Старое подтверждение не редактируется и не удаляется при следующем подтверждении. Новое решение создаёт новое событие.

Связи с Task и Battle Plan не дублируются внутри события: они выводятся on-read по существующим каноническим объектам.

## Совместимость

- Moodle production target: 4.1.22;
- PHP compatibility target: 7.3;
- миграция только additive;
- canonical Indicator остаётся `local_kbacompany_stat`;
- canonical Fact остаётся append-only `local_kbacompany_statval`;
- canonical Task остаётся `local_kbacompany_task`;
- Battle Plan по-прежнему хранит ссылку на Task;
- `minval/maxval` сохранены;
- существующие тренды, события, состояния, нормы и политики не мигрируются разрушительно.
