# 0.9.0.3 build 2026092415 — Управленческие циклы: BMS CRUD

Полное обновление `local_kbacompany` поверх 0.9.0.2 build 2026092414.
Target: Moodle 4.1.22, PHP 7.3+. Статус ALPHA. Сервер не обновлялся.

## Назначение раздела

Управленческий цикл организует работу за период: приоритет, ожидаемый результат,
владелец решений, куратор ритма, показатели и контрольные точки. Он не заменяет
стратегию, проект, Боевой план, встречу или реестр задач. Завершённые контрольные
точки показывают выполнение ритма управления, а не доказанное достижение бизнес-результата.

## Интерфейс

Главная страница теперь ListView: кнопка «Создать цикл», сводка по четырём существующим
состояниям, поиск по названию, фильтры по состоянию, шаблону, владельцу и пересечению
периодов. Поиск, фильтры, COUNT и постраничная выборка (25 строк) выполняются в SQL
в рамках текущей компании. Сводка явно относится ко всей компании, не к отфильтрованному списку.

Создание вынесено отдельно: сначала шесть существующих шаблонов с объяснением назначения
и числа контрольных точек/показателей, затем форма с секциями «Приоритет и результат»,
«Период», «Ответственность», «Как проверяем результат», «Дополнительно — связь периодов».
Владельца и куратора нужно выбрать явно; первый сотрудник списка больше не назначается
автоматически. Они могут быть одним человеком. Сохранение создаёт черновик, не запускает цикл.

Вместо пустых дат новая форма предлагает видимые редактируемые даты: календарную неделю,
месяц, квартал, год; для проектного и консультационного шаблонов — существующую номинальную
длительность. Это предложения, а не автоматическая привязка к проекту или создание новой стратегии.
Существующая логика следующего периода сохранена: такой же интервал после предыдущего;
его даты показываются перед подтверждением и могут быть скорректированы в новом черновике.

После сохранения открывается карточка, а не общий список. В карточке: название, тип,
состояние, период, ответственные, следующий шаг и вкладки:
«Обзор», «Контрольные точки», «Исполнение», «Разборы A3», «История».
Редактирование — отдельное основное действие для доступного черновика. Остальные операции
собраны в «Действия» и имеют отдельное подтверждение. UUID скрыт в технических сведениях;
Stable Code не придуман, поскольку у этого домена его нет.

Показатели, родитель и дочерние периоды открывают существующие записи.
«Исполнение» показывает Боевые планы владельца с началом внутри периода и перенесённые
ссылки на открытые задачи; это не все задачи компании и не полная эффективность проекта.
Существующие встречи, A3, отчёт периода и переход в следующий период сохранены.
Встреча показывается доступной только действующему участнику; обычное право управления
не делает человека участником частной встречи.

## Логика и защита изменений

Дата проверяется строго как реальная календарная дата, без нормализации 30 февраля в март.
Окончание не может быть раньше начала. Родитель принадлежит той же компании, соблюдает
Year → Quarter → Month → Week; любой дочерний период, включая проектный/консультационный,
должен помещаться внутрь родителя. Нельзя создать цикл в иерархии или сократить родителя
так, чтобы ранее созданные дочерние периоды оказались за его границами.

Формы читают только активных, не удалённых и не заблокированных участников компании;
канонические показатели проверяются в company scope. Требования к количеству показателей
шаблона сохранены. Ошибки показываются у полей, введённые данные не теряются.

Параметры редактируются только в черновике. Разрешённым редактором остаётся имеющий
действующие права BMS создатель/владелец/куратор или администратор сайта. Конкурирующее
изменение отклоняется по токену актуальности. Шаблон после создания не меняется.
Изменение дат черновика пересчитывает запланированные точки без замены их UUID;
при уже связанной встрече/зафиксированном результате изменение дат блокируется.

Запустить, закрыть или отменить цикл может владелец решений (либо администратор сайта),
но не куратор только на основании назначения. Запуск повторно проверяет актуальность
участников и связей. Назначение в цикле не выдаёт membership, роль или capability.
Для результата контрольной точки обязательна запись итога; подтверждённый итог не
перезаписывается повторным запросом с другим текстом. Идентичный повтор — без новой записи.
Закрытие периода не завершает открытые задачи/точки и не переписывает факт показателей.

Создание цикла и его контрольных точек выполняется одной транзакцией с company lock.
Повтор той же формы с тем же request key возвращает существующий UUID, а не создаёт дубль.
Создание следующего периода и сохранение provenance также атомарны. Задачи и исходные
Боевые планы не копируются, их сроки, состояния и история не сбрасываются.
Изменения возможны только POST + sesskey + явное подтверждение для вторичных действий;
GET/HEAD читают. Другие методы и неизвестные действия отклоняются.

## История и границы

Новые события создания, изменения параметров, состояния и контрольных точек передаются
штатному журналу Moodle. Вкладка показывает последние 50 событий конкретного разрешённого
цикла: кто, когда, операция и названия затронутых полей. Нового history engine/таблицы нет.
Содержимое приоритета/итога не копируется в лог; это не полная история значений полей.
Для ранее созданных циклов старые события не создаются задним числом. Наличие и срок хранения
событий зависят от активного SQL log reader и настроек журналирования Moodle.

Схема БД, db/upgrade.php, capability declarations, external services, scheduled tasks и privacy
provider не менялись. Существующие management/learning/AI/CRM engines не заменены.
KBA Theme и local_kbaai обновлять этим релизом не требуется; их исходники не изменялись.

наследуются при обновлении с более старой версии; для перехода с 0.9.0.2 новая схема не добавлена.
