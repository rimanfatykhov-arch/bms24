# BMS24 RC29 / build2026101636 — Position Coverage 03 (part 1)

**Основа:** полная сборка build2026101635. **Модуль:** `local_kbacompany` Moodle 4.0/4.1. **Статус:** staging candidate, не прошёл live Moodle/cron acceptance.

## Изменено

1. В определении регулярной серии `local_kbacompany_taskrec` добавлено `dutypositionuuid CHAR(36) NOT NULL DEFAULT ''`. Старые серии остаются персональными; никакой ретроактивной классификации.
2. Уполномоченный руководитель может выбрать «Тип ответственности»: персональная регулярная задача либо конкретная **действующая основная должность** первоначального исполнителя, с явным подтверждением доступа к рабочим материалам замещающему сотруднику. При смене исполнителя список должностей обновляется из существующего company-scoped маршрута Task Center; серверная проверка обязательна независимо от JavaScript.
3. Каждая новая ревизия серии фиксирует `dutypositionuuid` в каноническом immutable журнале. Замещающий не получает право редактировать само определение серии лишь в силу замещения. Обычный сотрудник не может изменить сохранённую классификацию серии.
4. Новые экземпляры регулярных задач наследуют `dutypositionuuid` от исходной ревизии. В самом экземпляре исходный `assigneeid` остаётся первоначальным пользователем, а разрешённое выполнение текущим замещающим определяется уже действующим `position_coverage_service::effective_executor`. Старые экземпляры не переписываются.
5. **Idempotency:** проверка существующей задачи при генерации теперь использует `(companyuuid, sourcekind=recurring, sourceuuid, periodkey)` без `assigneeid` и без изменения исходной `sourcerevision`. В обеих точках (предпроверка cron и проверка под taskcenter-lock) результат одинаков. Уже существующий экземпляр возвращается вместо создания дубля. Старые дубли автоматически не объединяются.
6. Если первоначальный исполнитель утратил действующее **основное** назначение на указанную должность, новая генерация должностного экземпляра останавливается с ошибкой вместо незаметной персональной переклассификации; требуется корректировка серии менеджером. Личные регулярные задачи обрабатываются по прежним правилам.
7. В DetailView показаны тип ответственности, должность и (при действующем замещении) текущий исполнитель. Правила канонического Task Center, история согласованных боевых планов и ACL приватных обсуждений неизменны.

## Границы этапа

Это **первый безопасный срез BMS-POS-COVERAGE-03**, а не завершение всех интеграций: автоматическое изменение уже согласованных боевых планов, передача полномочий одобрения, управление фактами/планами KPI от имени другого человека, приватные события календаря **не включены**. Следующий срез возможен только после проверки ACL и согласования правил доступа по каждому объекту.
