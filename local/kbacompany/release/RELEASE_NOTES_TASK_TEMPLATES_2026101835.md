# BMS24 / local_kbacompany — релиз 2026101835

**Название:** Шаблоны задач и подзадач 1.0\
**Версия:** local_kbacompany `1.1.0-rc29` / `2026101835`\
**Основа:** `build2026101834` (полный установочный ZIP).

## Что реализовано

1. **Библиотека шаблонов задач** `/local/kbacompany/task_templates.php?uuid=<companyuuid>` доступна руководителю компании; вход также из меню инструментов раздела «Задачи».
2. **«Сохранить как шаблон»** в карточке задачи: снимок основной задачи, её прямых подзадач (до 20) и чек-листов (до 50 пунктов на каждую задачу). Снимок не переносит статусы выполнения, результаты, файлы, обсуждения и историю.
3. **Создание по шаблону:** выбираются исполнитель родителя, проверяющий, новая дата отсчёта. По умолчанию исполнители всех подзадач соответствуют выбранному исполнителю; можно сохранить прежних исполнителей подзадач, если они ещё числятся сотрудниками компании.
4. **Относительные сроки:** исходные календарные даты сохраняются как смещения от исходной даты начала; при создании рассчитываются от выбранной даты. Если начало в исходной задаче не заполнено, для новой задачи используется выбранная дата отсчёта. Существующие времена суток не копируются.
5. **Атомарный запуск:** одна транзакция создаёт обычную родительскую задачу BMS24, дочерние задачи, новые невыполненные чек-листы и квитанцию запуска. Используются существующие `task_service::create` и `add_checklist` со всеми проверками доступа.
6. **Защита от повторного запуска:** сервер сохраняет уникальный ключ запроса и отпечаток параметров. Повтор той же операции возвращает предыдущую задачу; повтор с изменёнными параметрами отклоняется.
7. **Архивирование** шаблона с явным подтверждением; уже созданные задачи остаются неизменными.

## Изменения БД

`db/install.xml` и `db/upgrade.php` добавляют:
- `local_kbacompany_taskbundle`: описание и неизменяемый JSON-снимок шаблона (статус меняется только при архивировании).
- `local_kbacompany_taskbrun`: квитанции идемпотентного запуска.

В `install.xml` также устранено расхождение со старой миграцией: поля `starttime`/`duetime` добавлены в **определение новой установки** таблицы задач. На существующей БД они уже предусмотрены более ранним `upgrade.php`, массового изменения задач не проводится.

## Пределы версии 1.0

- Только **прямые** подзадачи; если есть вложенные подзадачи второго уровня, сохранение шаблона останавливается с пояснением вместо потери данных.
- До 20 подзадач, 50 пунктов чек-листа на задачу и ~60 КБ JSON-снимка.
- Отклонения сроков: -730 … +1095 дней от даты начала источника.
- Редактирование существующего шаблона не предусмотрено: создайте новый снимок, старый архивируйте.
- Изначальная привязка к управленческому объекту/Боевому плану **не копируется**: новые экземпляры — независимые задачи, которые при необходимости включаются в план существующим механизмом.
- Управление библиотекой доступно **только руководителю компании** в текущем релизе.
- Без расписания автоматических запусков — его рассмотрим в следующем отдельном улучшении регулярных задач.

## Установка

1. Создать резервные копии БД, файлов и каталога `local/kbacompany`.
2. На тестовом Moodle заменить каталог плагина содержимым INSTALL ZIP (внутри папка `kbacompany`).
3. Открыть `/admin/index.php`, завершить апгрейд БД до `2026101835`; очистить кэш Moodle.
4. Открыть родительскую задачу → «Сохранить как шаблон», проверить библиотеку шаблонов.
5. Создать комплект задач с новой датой, проверить исполнителей, сроки, отдельные записи дочерних задач и чистые чек-листы.
6. Повторно отправить тот же запрос из браузера; проверить отсутствие дублей; попробовать архивирование.

**Важно:** проводились только локальные статические и изолированные тесты. Серверная приёмка, выполнение новой миграции на MySQL Moodle, PHPUnit и проверка PHP 8.1 должны быть проведены отдельно. Не устанавливать в продуктив без резервной копии и проверки на стенде.
