# BMS24 — RC29 build2026101818

## Назначение
Связь этапов программы внедрения Corporate с недельными Боевыми планами компании — без копирования задач или изменения их статусов.

## Что изменилось
- На странице «Проекты внедрения BMS → Этапы внедрения» появился выбор недели (предыдущая/следующая/текущая).
- По каждому разделу подтверждённого аудита отображаются: активные задачи с ссылками в Боевых планах выбранной недели; активные задачи без такой ссылки; задачи на проверке у куратора; завершённые задачи.
- Руководитель может открыть оригинальную задачу в Corporate и конкретный Боевой план в BMS24.
- Подсчёты не повторяют одну задачу, даже если у неё несколько ссылок на планы; ссылки на план другого исполнителя отбрасываются.
- Недостаток прав на просмотр общекорпоративных Боевых планов, неподтверждённый аудит, неканоническая программа или усечённый ответ Corporate обозначаются отдельно от нулевых показателей.
- Новый read-only сервис `classes/local/implementation_project_weekly_service.php` использует только существующие таблицы BMS24 и публичный API Corporate 1.25.
- Сервис не меняет статусы задач/планов и не создаёт новых таблиц БД.

## Требования
- `local_kbacorporate` 0.40.7 / API 1.25 (установить первым).
- BMS24 `local_kbacompany` build2026101818.
- Явная действующая привязка оплаченной программы Corporate к опубликованному проекту BMS24; включённый источник `kbacorporate_impl`.

## Приёмка на Moodle
1. Сделать резервную копию кода/БД, обновить Corporate, затем BMS24, очистить кэш.
2. Открыть связанную программу и проверить соответствие исходным этапам Corporate.
3. Выбрать неделю, добавить задачу внедрения в черновик Боевого плана, обновить страницу этапов — ожидается переход из «не включено» в «в плане» без дублирования задачи.
4. Проверить повторную ссылку на ту же задачу в другой план той же недели — задача учитывается один раз.
5. Сверить статусы «На проверке» и «Завершено» с Corporate (не смешивать их с планированием).
6. Проверить права сотрудника без управления планами, пользователя чужой компании, программу без подтверждённого аудита и неоплаченную программу; ожидать явную ошибку/ограничение, не раскрытие записей.
7. Проверить программы с общей базой аудита — недельное сопоставление не должно выдавать недостоверные цифры.
8. Проверить работу на целевом Moodle 4.1.22 / PHP 8.1.34 и MySQL 5.7; измерить время открытия при большом числе задач.

## Границы релиза
- Сводка только для выбранной недели; «не включено» не означает «не планируется никогда».
- Пользователь с правами просмотра этапов, но без доступа к общекорпоративным планам, не получает недельной детализации.
- При более чем 5000 задачах одного аудита недельные цифры не показываются — API сигнализирует о неполных данных.
- Выполнение задачи не означает принятия её результата куратором и не является показателем зрелости внедрения BMS.
- Live E2E, PHPUnit с реальной Moodle БД, проверка PHP 8.1 и фактические замеры производительности не проводились в локальном окружении.
