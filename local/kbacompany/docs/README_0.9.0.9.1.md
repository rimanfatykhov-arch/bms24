# local_kbacompany 0.9.0.9.1 build2026092504
## Hotfix: восстановление схемы отклонений после неполного обновления

Полный устанавливаемый пакет поверх 0.9.0.9. Нового функционального контура нет.
Основание: пользовательский скриншот `Unknown column 'd.code' in 'field list'`
при открытии deviations.php. Отсутствие code подтверждено сообщением сервера;
причина неприменения миграции на конкретном сервере не установлена без его журнала.

В исходном 0.9.0.9 миграция 2026092503 присутствует. Hotfix добавляет следующий
версионный шаг 2026092504: недостающие поля/индексы и nullable-изменения повторно
проверяются штатным Moodle upgrade, даже когда сохранённая версия уже 2026092503.
Пользовательские UUID, коды, факты, статусы, редакции и история не переписываются.
Правильная схема 0.9.0.9 не требует DDL от нового шага. Старый шаг не удалён.

Обязательно: резервная копия БД + moodledata + кода; сначала тестовая копия Moodle.
Установить INSTALL_ME ZIP, затем завершить штатное обновление Moodle:
«Администрирование → Уведомления» (admin/index.php), после него очистить кэши.
Загрузка ZIP/замена PHP и очистка кэшей без обновления БД не заменяют миграцию.

CLI-альтернатива из корня Moodle, от системного пользователя веб-сервера
(не запускать параллельно с браузерным обновлением):

```sh
php admin/cli/maintenance.php --enable
php admin/cli/upgrade.php --non-interactive
php admin/cli/purge_caches.php
php local/kbacompany/cli/check_deviation_schema.php --json
```

После успешного завершения и проверки:

```sh
php admin/cli/maintenance.php --disable
```

Если upgrade завершился ошибкой, остановиться, сохранить полный вывод и проверить
его до снятия режима обслуживания. Не изменять вручную config_plugins.version,
не удалять/переустанавливать плагин, не добавлять только одно поле code произвольным SQL.
Для отката нужен согласованный снимок БД + кода + moodledata, не снижение версии в БД.

Новый диагностический CLI читает только метаданные схемы и сохранённую версию;
сам не исправляет БД. SCHEMA_PRESENT означает наличие проверенной структуры,
а не функциональную приёмку. При нехватке схемы страницы и команды отклонений
останавливаются до SQL к данным с понятным сообщением; DDL на GET/POST страницы нет.
