# BMS v0.5.13 — Готовность управленческой недели

## Назначение

Read-model показывает руководителю готовность уже созданных недельных Боевых планов к следующему переходу существующего lifecycle. Отдельный реестр статусов готовности не создаётся.

## Жёсткие блокеры

Жёсткие блокеры полностью повторяют уже существующие правила `battle_plan_service::transition()`:

- у черновика/отправленного плана отсутствует корректный проверяющий;
- в черновике нет ни одной ссылки `bplanitem` на задачу.

Никаких дополнительных скрытых требований для `submit`, `selfapprove` или `approve` не вводится.

## Состояния read-model

- `blocked` — есть жёсткий lifecycle-блокер;
- `ready_submit` — черновик с задачами и отдельным проверяющим;
- `ready_selfapprove` — черновик с задачами, сотрудник сам выбран проверяющим;
- `ready_activate` — план уже отправлен и может быть утверждён;
- `active` — план активен;
- `closed` — план закрыт.

## Управленческие предупреждения

Отдельно показываются пробелы, которые важны для качества управленческого контура, но не меняют существующую state machine:

- у должности нет критических показателей;
- у критического показателя нет действующей на неделю нормы.

Observer остаётся опциональным и не является блокером.

## Источники

`local_kbacompany_bplan`, `local_kbacompany_bplanitem`, справочник сотрудников, `position/orgnode`, историческая проекция показателей должности.

Storage нового read-model: отсутствует.
