# BMS24 UI / CRUD: Стандарт кнопок и действий — RC29 / build1807

## Цель

Единая визуальная система **действий внутри страниц** `local_kbacompany` (в том числе формы выбора главного инструмента и настройки рабочего пространства). Источник истины для BMS24 Owned Shell — `bms_ui/tokens.css` и `bms_ui/ui_kit.css`, а не ad hoc оформление `.kba-bms-button` в topbar.

| Тип | Классы | Поведение |
| --- | --- | --- |
| Основное («Сохранить», «Создать», «Применить») | `bms24-ui-btn bms24-ui-btn--primary` | Тёмно-зелёный `#0C6C52`, белый текст, изменение оттенка при hover |
| Второстепенное («Отмена», «Назад») | `bms24-ui-btn` | Белый фон, тёмно-синий текст и рамка |
| Тихое контекстное | `bms24-ui-btn bms24-ui-btn--quiet` | Бледно-зелёный фон, тёмно-зелёный текст |
| Опасное («Удалить») | `bms24-ui-btn bms24-ui-btn--danger` | Красный фон, белый текст; только для явно опасных действий |
| Неактивное | Нативный `disabled` для `<button>` | Не кликается, видна причина при необходимости; не выдавать визуальную «неактивность» из-за отсутствующего фона |

### Правила форм

1. Одно основное действие на группу. `Сохранить` располагается первым, `Отмена` — рядом.
2. Кнопки ставить в `bms24-ui-actions`, чтобы они переносились на мобильной ширине.
3. Сохраняющие/сбрасывающие операции — **только POST**, с `require_sesskey()` и проверками компании / capabilities. Отмена — обычная безопасная ссылка.
4. Использовать действующий языковой ключ Moodle для подписи, не хардкодить текст в PHP.
5. Сброс личной раскладки — нейтральная кнопка в отдельной форме, не красная операция удаления данных.
6. Состояния hover, focus-visible, disabled должны сохранять контраст текста, целевую область не меньше 40 px по высоте. Учитывать доступность с клавиатуры.
7. Для BMS24 Owned Shell классы применяются через `.bms24-app ...` в `bms_ui/ui_kit.css`. Для страниц KBA Theme и Moodle fallback существует строго ограниченный мост в `styles.css` — в формах `bms-main-preferences`, `bms-widget-preferences`, `bms-widget-reset-form`, карточках `bms-home-simple` и модальном окне `bms-main-intro-dialog`.
8. **Переходный этап:** кнопки topbar в `bms_page_shell_service.php`, `bms_workspace.php` и `bms_architecture.php` оставлены на legacy-классах, так как оформляются отдельным контрактом App Shell. Не менять их в этом UX hotfix без проверки совместимости с KBA Theme.

### Проверка релиза

- `python3 cli/check_bms_button_standard_1807.py` проверяет классы обеих форм, действия, мост fallback, версионирование и маршрут.
- `python3 cli/build_release.py ...` выполняет общие тесты RC29 и сборку.
- На `edu.kzn.mba` вручную проверить обе формы на 320/375/768/1440px в Owned Shell и, если используется, в KBA Theme: **основная кнопка зелёная, текст белый**, отмена нейтральная, клавиатурный фокус заметен, действия работают.

Это UI-стандарт и статический контракт, а не доказательство прохождения браузерной приёмки.
