# BMS24 / local_kbacompany 0.9.0.3

Build **2026092415**. **Управленческие циклы: BMS CRUD**.
База 0.9.0.2. Moodle target 4.1.22, PHP target 7.3+. ALPHA, live acceptance NOT RUN.

## Установка

Использовать `INSTALL_ME_local_kbacompany_v0.9.0.3_build2026092415.zip`.
Это полный plugin ZIP с единственным корнем `kbacompany/`. SOURCE и Release Kit не
загружать в установщик. Резервная копия БД/moodledata/кода → обновить `local/kbacompany`
→ штатное обновление Moodle → очистить кэши. Новых изменений схемы относительно 0.9.0.2 нет.
Обновление сервера этим действием в чате не выполнялось.

## Где работать

Управление → Планирование → Управленческие циклы.
Список → «Создать цикл» → выбор шаблона → форма → «Сохранить черновик» → карточка.
В карточке: Обзор / Контрольные точки / Исполнение / Разборы A3 / История.
Даты и ответственные проверяются до запуска. Владелец и куратор выбираются явно.
«Редактировать» доступно для разрешённого черновика. В «Действиях» — запуск, закрытие,
отмена, следующий и дочерний период по текущим правам и состоянию.

## Что важно

Цикл задаёт ритм управления, а не новый проект или список задач. Счётчик завершённых
контрольных точек не подтверждает бизнес-результат. Факт показателей проверяется в
существующем реестре/отчёте, открытая работа остаётся в канонических задачах и Боевых планах.
Куратор сопровождает период и точки; он не закрывает цикл вместо владельца решений.
Все назначенные роли требуют существующих прав BMS и доступа к компании.

Полный перечень изменений: RELEASE_NOTES_0.9.0.3.md.
Domain/UI contract: MANAGEMENT_CYCLES_BMS_UI_0.9.0.3.md.
Core logging доступно только для новых событий и при настроенном reader; старые события
не восстанавливаются. История не является versioned snapshot полного содержимого.

Проверки static/isolated/component не заменяют Moodle install/upgrade, настоящие роли,
драйверы БД, блокировки при реальной конкуренции и совместимость с KBA Theme.
Следующий продуктовый этап Odoo 0.9.1 этим UI/stabilization выпуском не реализуется.
