# Установка BMS 0.9.0

Полный плагин: `local_kbacompany`, версия 0.9.0, build 2026092412.
База: 0.8.12 build 2026092411. Целевой Moodle: 4.1.22.

Установочный файл: **INSTALL_ME_local_kbacompany_v0.9.0_build2026092412.zip**.
Внутри ровно один корень `kbacompany/`. Это обновление существующего плагина, не второй плагин.
Архивы SOURCE / RELEASE_KIT и старый LIVE_ACCEPTANCE_KIT не устанавливать вместо него.

На тестовой копии сначала сохранить БД, moodledata и код. Затем штатным способом Moodle
обновить local_kbacompany из INSTALL ZIP, завершить процедуру обновления БД и очистить кеши.
При ручной установке заменить каталог `local/kbacompany`, сохранив владельца/права файлов,
и выполнить обычный `admin/cli/upgrade.php` из установленного Moodle.
Не пропускать upgrade: релиз расширяет существующую таблицу extmap.
После обновления войти с существующим правом управления организацией:
**BMS → Настройки → Интеграции → Добавить связь**.

Первый пример: провайдер Odoo, среда `client-a-prod`, объект BMS «Компания», внешняя модель
`res.company`, ID нужной компании в этой среде. Сначала «Проверить связь», затем проверить
сопоставление на экране и явно подтвердить сохранение. Использовать реальные разрешённые ID,
а не пример из документа. После связи компании доступны связи её должностей и показателей.
Внешний сервер этим действием не опрашивается, API-ключ вводить не нужно.

Существующие связи Bitrix/KBA Connect остаются отдельно и продолжают использовать прежний контракт.
Добавление ручной связи само по себе не включает обмен. Не закрывать рабочую связь ради изменения
ID: в 0.9.0 нет восстановления/переназначения закрытой связи, только сохранение её истории.

Статус пакета: статический QA и изолированные проверки PASS; live Moodle/браузер/production NOT RUN.
Успешная сборка не является подтверждением обновления вашего сервера.
Сведения о SHA256, исходниках, patch и ограничениях — в Release Manifest / QA Report / Release Kit.
