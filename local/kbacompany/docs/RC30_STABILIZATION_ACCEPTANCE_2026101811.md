# BMS24 — RC30. План стабилизации и критерии допуска

Статус: **HOLD до живой приёмки**. Базовая версия: RC29 build2026101811.

## Цель
Не объявлять RC30 стабильной до проверок прав, полного управленческого цикла, интерфейса и производительности на изолированном стенде Moodle 4.1/PHP 8.1.

## Блокирующие проверки

| Tenant isolation | Два непривилегированных пользователя, по одному на компанию, двусторонний deny; обе позитивные пробы проходят | A→A PASS, B→B PASS, A→B DENY, B→A DENY | NOT RUN |
| RBAC | Сотрудник/руководитель/владелец, прямые ссылки и URL с чужим UUID | Ни один недоступный объект не возвращает данные/действия | NOT RUN |

| Approvals | Согласование/возврат/повторная отправка/утверждение | Данные циклов и счётчики согласованы | NOT RUN |

## Безопасная read-only диагностика

Запускать **только на стенде**, с тестовыми сотрудниками без глобальных привилегий. Параметры A и B должны указывать на две разные компании, где A-пользователь не является участником B и наоборот.

```bash
php local/kbacompany/cli/qa_management_cycle.php \
  --company=<UUID_A> --actor=<USER_ID_A> --week=2026-10-19 \
  --denied-company=<UUID_B> --denied-actor=<USER_ID_B>
```

Вывод `cross_company_denial=PASS_RECIPROCAL_DENIAL` означает **только успешную проверку четырёх контекстов компании**. Он не подтверждает отсутствие ошибок во всех endpoint/CRUD и не заменяет E2E. `HOLD_*`, неожиданное исключение или отсутствие обеих сторон означает, что релиз нельзя считать принятым.

## Выпускной критерий RC30

Для обозначения RC30 stable требуется подписанная ручная приёмка и логированные результаты. До неё любые пакеты build1811+ являются **RC29 кандидатами на стабилизацию**, а не новой стабильной веткой. Изменения прав/объектов — только отдельными исправлениями с регрессией.
