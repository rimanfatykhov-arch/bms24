# RC30 — контроль происхождения диагностических отчётов (build1870)

## Зачем это нужно

До 1870 года два полных отчёта `--all` можно было сравнить, даже если они были сформированы на разных установках Moodle, а также поменять местами старый и новый файл без проверки времени снимка.

Build1870 добавляет в успешный отчёт `rc30_acceptance.php`:

- `installation_digest` — SHA-256 от нормализованной комбинации адреса Moodle, типа БД, сервера БД, имени БД и префикса таблиц. Исходные значения в JSON не записываются.
- `captured_at` — Unix-время формирования отчёта.

Команда `rc30_compare_reports.php` проверяет совпадение отпечатков, а также что время нового снимка не раньше исходного. Сравнение одного и того же файла по двум путям блокируется, если оба пути разрешаются в один файл.

## Создать исходный отчёт на build1870

Из корня Moodle:

```bash
php local/kbacompany/cli/rc30_acceptance.php \
  --all --format=json --strict > rc30_before_1870.json
```

После проверки/обновления системы создайте новый отчёт:

```bash
php local/kbacompany/cli/rc30_acceptance.php \
  --all --format=json --strict > rc30_after_1870.json
```

Затем сравните:

```bash
php local/kbacompany/cli/rc30_compare_reports.php \
  --baseline=rc30_before_1870.json \
  --current=rc30_after_1870.json \
  --format=json --strict > rc30_comparison.json
```

Сравнение файлов с разных установок возвращает код 2 и `report_installation_mismatch`. Более старый по времени текущий отчёт возвращает код 2 и `report_time_rollback`. Передача одного файла как baseline и current возвращает `report_same_file`.

## Старые отчёты 1866–1869

Старые JSON-файлы по-прежнему разбираются, но отсутствие отпечатка или времени явно отражается в `provenance_warnings`. Обычное сравнение возвращает `warnings`, строгий режим — `failed`. Для полноценной строгой приёмки нужно создать **два новых** отчёта на build1870 или выше.

## Ограничения

- Отпечаток отражает **настроенную** идентичность сайта и подключения к БД, а не является криптографической подписью сервера или данных. Его невозможно использовать для доказательства, что содержимое файла не менялось.
- Смена адреса Moodle, имени/хоста БД или префикса таблиц приведёт к разным отпечаткам; такой случай требует ручной сверки.
- Два снимка, созданные в одну секунду, допустимы; сравнение не доказывает, что был фактический интервал между ними.
- Отчёты не содержат имён сотрудников, содержимого задач, исходного URL, имени БД или SQL.
- Команды только читают данные. Положительный технический результат **не утверждает RC30** без ручной приёмки на `edu.kzn.mba`.
