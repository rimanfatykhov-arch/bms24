# RC30 — отчёты диагностики командной строки (build2026101866)

Диагностика BMS24 доступна из командной строки Moodle. Команды не изменяют бизнес-данные.

## Запуск и сохранение отчёта

Из корня Moodle:

```bash
php local/kbacompany/cli/rc30_acceptance.php --all --format=json --strict > rc30_acceptance.json
```

Для одной компании (рекомендуется при большой базе):

```bash
php local/kbacompany/cli/rc30_task_integrity.php --company=UUID_КОМПАНИИ --format=json --strict > rc30_integrity.json
```

Пути вывода выбираются администратором. Отчёт может содержать числа по данным компании; храните файл в защищённой папке и не публикуйте открыто.

## Возвращаемые коды

- `0`: проверка завершилась; блокирующих отклонений по выбранным правилам нет (в нестрогом режиме возможны предупреждения).
- `1`: проверка завершилась и нашла отклонения, блокирующие текущий режим.
- `2`: проверить не удалось — неверные параметры, недоступная схема БД или другая ошибка выполнения.

**Код 2 никогда не считать «проверка пройдена».**

## Формат JSON при ошибке выполнения

При использовании `--format=json` даже неполная диагностика теперь возвращает JSON. Для общей проверки:

```json
{
  "schema_version": 1,
  "scope": "company",
  "strict": true,
  "read_only": true,
  "diagnostic_complete": false,
  "rc30_promotion_approved": false,
  "errors": ["missing_rc30_table"],
  "warnings": [],
  "technical_gate": "failed"
}
```

Для `rc30_task_integrity.php` поле `technical_gate` заменяется на `gate`. Коды ошибок фиксированные: `invalid_arguments`, `unsupported_format` (вывод только в stderr, так как JSON не был выбран), `invalid_company_uuid`, `missing_rc30_table`, `database_query_error`, `preflight_execution_error`.

Сообщения исключений, SQL, пути сервера и UUID не включаются в ошибочный JSON. Подробности ошибок следует искать в защищённых журналах PHP/Moodle.

## Критерий приёмки RC30

Успешный технический отчёт **не даёт разрешения выпускать RC30**. Отдельно нужны:
- серверный Moodle PHPUnit;
- проверка ACL на разных ролях и компаниях;
- жизненный цикл задач, приёмка, массовые действия, Канбан;
- связи с Боевыми планами;
- проверка SQL на целевом MySQL 5.7;
- резервное копирование и восстановление.

При переносе результатов диагностики прикладывайте JSON-файлы и коды завершения обеих команд. Не изменяйте результаты вручную.
