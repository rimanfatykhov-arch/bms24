# BMS24 / local_kbacompany 0.9.0.2

Build: **2026092414**. Название: **Исполнение в карточке проекта**.
База: 0.9.0.1 build 2026092413. Target: Moodle 4.1.22; PHP 7.3+ syntax target.
Статус: ALPHA, live/staging/production acceptance не выполнен.

## Что устанавливать

Использовать только `INSTALL_ME_local_kbacompany_v0.9.0.2_build2026092414.zip`.
Это полный плагин с единственным корнем `kbacompany/`, не дополнение и не набор проверок.
SOURCE и Release Kit не предназначены для загрузки в установщик Moodle.
Отдельного обновления KBA Theme или local_kbaai нет.

Перед установкой сделать резервные копии БД, moodledata и кода. Обновить существующий
`local/kbacompany`, выполнить штатное обновление Moodle и очистить кэши. Сам сервер
данным выпуском из чата не обновлялся. Относительно 0.9.0.1 новых DB migration нет;
при переходе с более старой версии действуют унаследованные upgrade-шаги, в том числе
extmap migration из 0.9.0. При откате после таких миграций нужен согласованный backup,
а не произвольный downgrade только version.php.

## Где посмотреть

**Архитектура → Административная шкала → Проекты → карточка проекта → Исполнение.**

«Описание» содержит существующее определение проекта, связи и историю.
«Исполнение» показывает ожидаемый результат, ответственную должность, продукт,
сроки, связанные доступные задачи с планом/фактом времени и записанным результатом,
доступные Боевые планы, встречи и решения. Индикатор открывается отдельной ссылкой.

Планирование изменяется в одном каноническом редакторе — Административной шкале.
Периоды остаются в «Управленческих циклах». Встреча не требуется для обычной задачи:
в существующей форме задачи можно выбрать проект в поле «Подзадача / связано с».
Подзадачи без собственной связи с проектом автоматически не выводятся в этот срез.

## Старые ссылки

GET/HEAD `administrative_cycle.php?uuid=...` ведёт к списку проектов.
С параметром `project=...` — к вкладке «Исполнение» того же доступного проекта.
С `edituuid=...` — к существующей форме Административной шкалы при наличии права.
Несуществующий/недоступный проект не заменяется автоматически первым найденным.
Старые POST/PUT/PATCH/DELETE и другие изменяющие/неподдерживаемые методы не сохраняют
ничего: показано сообщение об открытии канонической формы. Введённый в старую форму
несохранённый текст не переносится автоматически. Сохранённые данные не удаляются.

## Ограничения проверки

Статические, standalone PHP/SQLite и Chromium DOM-fixture проверки выполнены.
Это не Moodle PHPUnit/Behat, не реальная Moodle DB, не проверка установленной KBA Theme.
PHP 7.3 проверен сканированием известных несовместимых конструкций, не runtime.
Установка/upgrade Moodle, браузер на live-сайте и production acceptance — NOT RUN.
Следующий функциональный roadmap-срез 0.9.1 Odoo adapter этим UI-патчем не реализован.
