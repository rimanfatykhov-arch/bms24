# BMS 0.5.0 — Реестр и дерево показателей

## Архитектурный принцип

BMS не создаёт отдельные «показатели ССП», «показатели должности» и «показатели Боевого плана». Канонический показатель существует один раз в `local_kbacompany_stat`. План/факт хранится append-only в `local_kbacompany_statval`.

Новые слои 0.5.0:

- `local_kbacompany_statmeta` — версионный паспорт: описание, источник, способ получения/агрегации;
- `local_kbacompany_statbind` — версионные связи с компанией, стратегической целью, подразделением или должностью;
- `local_kbacompany_statnorm` — версионные нормы/квоты конкретной связи с периодом действия.

## Две проекции одного реестра

### По стратегии

`ССП → перспектива → стратегическая цель → показатель`

Существующая связь `StrategicGoal.metricuuid` отображается как read-only compatibility-связь. Массовая миграция не выполняется.

### По организации

`Компания → ОФС → подразделение → должность → показатель`

Существующие связи через продукт и его target (`company/node/position`) также отображаются как compatibility-связи.

## Нормы

Норма не является свойством определения показателя. Одна и та же статистика может иметь разные нормы для разных должностей/подразделений и разных периодов времени. Изменение нормы создаёт новую редакцию и не переписывает исторический факт.

## История и график

График строится из append-only истории фактических значений. Сам график не хранится отдельным объектом. Исправление уже введённого значения сохраняет предыдущую редакцию наблюдения.

## Периоды

Поддерживаются: день, неделя, месяц, квартал, год. Для недели каноническая дата — понедельник; для месяца — первое число; для квартала — первое число января/апреля/июля/октября; для года — 1 января.

## Границы релиза

0.5.0 создаёт фундамент реестра, деревьев, норм и истории. Он не переносит расчёт состояний и не переписывает существующий Боевой план. Следующий слой будет потреблять данные реестра, а не создавать собственные копии показателей.
