# Corporate 0.40.10 — этап 1822: проверка полного кураторского контура

Build `2026102610`, прежний API 1.26. Базовая сборка: Corporate 0.40.9 (`2026102518`). Обновление BMS24 не требуется.

## Изменения

1. Сужена проверка полномочий назначенного куратора на задачи: одновременно совпадают `companyid`, `baselineauditid` и `curatorid`. Обычная роль `curateimplementation` не даёт доступа к другим программам.
2. В выдаче «Ученики куратора» и аналитике теперь действует SQL-связь `t.companyid = p.companyid`; ошибочная запись с чужой компанией не попадает в сводку. В списке подтверждённых аудитов привязка программы также проверяет компанию аудита.
3. Запрещён доступ к удалённой задаче, даже если сервису передали ранее полученный объект записи.
4. В карточках обсуждений отображаются текст и имя участника с явным экранированием; добавлена ссылка «Открыть проверку результата» только для задачи `review` с последней доказательной версией `submitted` и только когда пользователь имеет право проверки.
5. Добавлены Moodle PHPUnit-тесты матрицы «куратор / компания / аудит» и автономный контрактный тест, а также подробный чек-лист приёмки.

## Не изменено

Таблицы БД, протокол обсуждений, версионные доказательства, статусы задач, механизм назначения кураторов, права системной роли, интеграционный API 1.26 и интерфейс BMS24.

## Установка

1. Сделать backup БД и `/local/kbacorporate`.
2. Установить `INSTALL_local_kbacorporate_0.40.10_build2026102610.zip` штатным механизмом Moodle. Не распаковывать вторым уровнем папки (корень ZIP: `kbacorporate/`).
3. Запустить штатное обновление до `2026102610`; очистить кэши.
4. Выполнить `docs/ACCEPTANCE_CURATOR_STAGE1822.md` под куратором, исполнителем и посторонним пользователем.
5. При дефекте восстановить файлы и базу из согласованной резервной копии. Поскольку таблицы не изменялись, схема БД не требует новой миграции.
