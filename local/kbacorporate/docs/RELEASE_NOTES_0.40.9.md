# Corporate 0.40.9 — Куратор внедрения BMS с отдельными правами

Build: `2026102518` · BMS24 integration stage: `1821` · API bridge remains `1.26`.

## Изменения

- Зарегистрировано отдельное системное право `local/kbacorporate:curateimplementation` с пустыми архетипами. Это **право быть кандидатом на назначение**, а не доступ ко всем программам и компаниям.
- В `implementation_program_edit.php` доступны пользователи с новым правом, прежние администраторы программ и активный ранее назначенный куратор. Дополнительная серверная проверка выполняется при сохранении.
- Добавлена защищённая настройка `/local/kbacorporate/implementation_curator_role_setup.php`: администратор ролей вручную создаёт системную роль `kbacorporatecurator` с **одним** правом `curateimplementation`. Страница доступна только с `moodle/role:manage`; создание только POST + sesskey.
- Роль НЕ создаётся из `db/upgrade.php`: Moodle обновляет объявления возможностей после выполнения upgrade callback. Учитывается ранее встречавшийся дефект регистрации capabilities.
- Старые назначения `program.curatorid` не сбрасываются. Доступ к задачам и обсуждениям по-прежнему определяется `curatorid`, а не одним наличием системной роли.
- Не меняются таблицы, статусы, программы, обсуждения и интеграционный API (v1.26).

## Порядок установки / активации

1. Создайте резервную копию БД и исходников Moodle.
2. Установите ZIP `local_kbacorporate` версии `2026102518` и выполните штатное обновление Moodle.
3. Очистите кэш, затем администратор Moodle открывает `/local/kbacorporate/implementation_curator_role_setup.php` и нажимает «Создать отдельную роль куратора».
4. В системных назначениях ролей Moodle назначьте пользователю **«Куратор внедрения BMS»**. Не выдавайте ему `manageimplementationprograms` и `manageimplementationaudits`, если для этого нет самостоятельного основания.
5. Уполномоченный администратор программ открывает `implementation_program_edit.php` для нужной компании/аудита и выбирает пользователя в поле «Куратор внедрения».
6. Выполните проверку под пользователем-куратором: «Ученики куратора», «Панель куратора», задачи и обсуждения **только назначенных программ**.

## Критерии приёмки

- Пользователь с новым правом появляется в списке кандидатов, даже не обладая `manageimplementationprograms`.
- Назначенный куратор видит только собственные программы и соответствующие обсуждения.
- Пользователь только с ролью, но без привязки к программе, не видит данные компаний.
- Обычный сотрудник без роли не может быть назначен новым куратором через подмену POST.
- Администратор без `moodle/role:manage` не может создать роль.
- Старые назначения после обновления продолжают работать.
- Повторное открытие/подтверждение настройки не создаёт вторую роль.
- `local_kbacompany` 1820 и `local_kbacorporate` bridge 1.26 сохраняют работоспособность.

## Ограничения

PHP lint и контрактные тесты не заменяют PHPUnit на Moodle 4.1 / PHP 8.1 и проверку реальных ролей на сервере. Новый API не даёт куратору доступа к настройкам подписок/тарифов или данным других компаний.
