**Build:** `2026091006`

**Contract release:** `1.1.0`  
**Public bridge:** `1.18`

## Совместимые режимы employee

1. Связать существующего пользователя по `moodle_user_id`.
2. Найти существующего пользователя по точному `username` и/или `email`.
3. Создать пользователя только при `create_if_missing = true` и полном наборе `username`, `firstname`, `lastname`, `email`.
4. Деактивировать ERP-owned связь сотрудника через `active = false` без удаления Moodle account и истории.
5. Повторно активировать ту же связь через `active = true`.

## Правила владения

- Профиль существующего Moodle account не перезаписывается ERP.
- Имя, фамилия и email обновляются только для account, созданного этой же ERP mapping.
- Username созданного account остаётся неизменяемым.
- Пароль генерируется Moodle, не возвращается API и требует смены пользователем.
- Глобальные `suspended` и `deleted` не управляются состоянием сотрудника одной компании.
- Ручное членство компании не удаляется ERP-деактивацией.

## Результат employee push

Ответ сохраняет старые поля и дополнительно сообщает:

- `membership_created`;
- `account_created`;
- `profile_changed`;
- `managed_account`;
- `password_reset_required`;
- `active`.

## Методология

Синхронизация сотрудника не назначает компетентностный уровень, не создаёт оценку и не трактует отсутствие оценки как уровень 0. Назначения оргструктуры и ролей развиваются отдельно в v0.35.2.
