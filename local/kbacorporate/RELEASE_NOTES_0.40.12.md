# Corporate 0.40.12 — этап 1824: Канбан внедрения

**Компонент:** `local_kbacorporate`  
**Сборка:** `2026102612`  
**API:** `1.26` — без изменений  
**Целевое окружение:** Moodle 4.1.x / PHP 8.1.34 / MySQL 5.7.x (серверная проверка ещё не проводилась).

## Задача

До этого релиза `implementation_board.php` вызывал `implementation_task_discussion::get_curator_threads()` для полного набора задач, обогащал каждую запись данными обсуждений и доказательств, после чего фильтровал и сортировал задачи в PHP. При большом портфеле это увеличивало память и количество запросов к БД.

## Изменения

1. Новый read-only сервис `classes/local/implementation_board_query.php`:
   - строит ограниченную видимостью текущего куратора (или разрешённого аудитора) выборку;
   - выполняет поиск, фильтрацию по компании, куратору, аудиту, исполнителю, приоритету, сроку, периоду, статусу и актуальному статусу доказательств **на уровне SQL**;
   - считает сводку по всей отфильтрованной выборке независимо от числа карточек на экране;
   - загружает **до 15 карточек на колонку** (максимум 75 карточек одновременно);
   - сохраняет детерминированный порядок `duedate ASC, timemodified DESC, id DESC`, без срока — в конце;
   - предотвращает повторный учёт одной задачи при наличии нескольких программ, привязанных к одному аудиту, выбирая одну подходящую программу с минимальным ID.
2. `implementation_board.php`: независимые страницы 5 колонок (`p_planned`, `p_inprogress`, `p_review`, `p_completed`, `p_cancelled`), сохранение фильтров и других номеров страниц в ссылках, полные счётчики поверх колонок.
3. `implementation_task_discussion.php`: безопасный публичный метод обогащения только выбранных задач; старые публичные методы сохранены.
4. `styles.css`: компактная навигация по страницам в колонках.
5. Русские и английские языковые строки для навигации по страницам.
6. Новые тесты SQL-контракта, ограничений доступа и PHPUnit-тесты для выборок, счётчиков и пагинации.
7. `cli/benchmark_kanban.php`: сценарий замера времени, количества запросов и пикового потребления памяти без вывода названий задач, обсуждений или данных сотрудников.

**Обратная совместимость:** модели задач, статусы, связи программ, обсуждения, приёмка и события изменения карточек не затронуты. Новых таблиц или миграций нет. API 1.26 сохранён. BMS24 обновлять не нужно.

## Как измерить производительность на тестовом Moodle

Запустить из корня Moodle под системным аккаунтом PHP (только CLI):

```bash
php local/kbacorporate/cli/benchmark_kanban.php --userid=123 --companyid=456 --runs=10
```

Укажите существующего куратора (или уполномоченного аудитора) и компанию, к которой он имеет доступ. Скрипт измеряет **только серверную модель сводки и первых страниц всех колонок**, но не генерацию HTML, загрузку CSS и браузерный рендер. Он ничего не изменяет в БД. Для сравнения используйте копию с одинаковой БД, сначала baseline 0.40.11 (там CLI-скрипта ещё нет, время и SQL-запросы надо измерить иным профилировщиком), затем 0.40.12 с новым скриптом. Сделайте не менее 10 прогонов с прогревом и оцените медиану и p95.

Нужно дополнительно замерить в браузере полное время HTTP-ответа, число SQL-запросов Moodle, PHP peak memory и визуальную загрузку страницы. На 100, 1000 и 5000 задачах проверить скорость и выполнить `EXPLAIN` медленных запросов. Не публиковать отладочные трассировки на рабочем портале.

## Приёмка (ручная)

- 0, 1, 15, 16, 100 и 1000+ задач, пустые колонки, до/после последней страницы.
- Сводные показатели не изменяются при перелистывании колонок.
- Поиск и фильтры применяются ко всем доступным задачам до пагинации; смена фильтра сбрасывает номера страниц.
- Переход по страницам одной колонки сохраняет страницы других колонок.
- После быстрого редактирования сохраняются фильтры и страница; операции защищены `sesskey`.
- Выполненные и отменённые задачи не помечаются как просроченные.
- Доказательство фильтруется по **последней версии**, а не произвольной старой версии.
- Куратор видит только свои назначения, `manageimplementationaudits` может просматривать портфель по разрешениям.
- Данные другой компании не раскрываются, даже при подмене `companyid`, `auditid`, `curatorid` и `p_*` в URL.
- Проверить обычные карточки, переходы на исходные задачи, быстрые изменения исполнителя и срока, пагинацию на телефоне.

## Оговорки

Локальные статические проверки и синтаксический прогон **не заменяют** PHPUnit на реальной тестовой Moodle, проверку MySQL 5.7 или испытание на `edu.kzn.mba`. Числовое ускорение не подтверждалось. При больших объёмах данных поисковые `LIKE` и выборки фасетов ещё могут требовать оптимизации индексов после `EXPLAIN`.

## Установка и откат

1. Создать резервные копии Moodle, БД и папки `local/kbacorporate`.
2. Установить `INSTALL_local_kbacorporate_0.40.12_build2026102612.zip` штатным обновлением Moodle.
3. Проверить версию плагина `2026102612`, выполнить обновление БД Moodle (новых XMLDB-миграций в данном релизе нет), очистить кэш.
4. Проверить страницу `/local/kbacorporate/implementation_board.php` под куратором и аудитором, затем выполнить серверные приёмочные сценарии.
5. При выявленных ошибках восстановить предыдущий код `0.40.11` и при необходимости резервную копию БД согласно регламенту Moodle.
