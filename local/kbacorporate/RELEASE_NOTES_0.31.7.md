# KBA Corporate Dashboard v0.31.7
## Создание учебного плана Moodle

Дата: 8 сентября 2026 года  
Тип изменения: MINOR  
Build: `2026090803`

## Назначение

Завершить безопасную цепочку после предпросмотра учебного плана:

`подтверждённые разрывы → финальная проверка → план KBA → шаблоны бизнес-ролей → стандартный учебный план Moodle → проверка состава`.

## Добавлено

- отдельный экран финального подтверждения перед записью данных;
- повторная серверная проверка выбранных компетенций перед применением;
- явное отображение объектов, которые будут созданы или обновлены;
- создание либо обновление плана развития KBA;
- создание либо синхронизация шаблонов учебных планов Moodle по назначенным бизнес-ролям;
- создание либо обновление стандартного учебного плана Moodle сотрудника;
- проверка владельца плана Moodle;
- проверка полного совпадения состава компетенций KBA и Moodle;
- итоговый экран со ссылками на план KBA и учебный план Moodle;
- частичный результат с понятными предупреждениями, если KBA-план сохранён, а Moodle-синхронизация отложена;
- идемпотентное повторное выполнение без создания дублей.

## Изменено

Кнопка на странице предпросмотра больше не применяет изменения немедленно. Она открывает отдельный экран «Создание учебного плана Moodle», где пользователь видит финальный состав и подтверждает операцию.

## Безопасность данных

- в план попадают только повторно подтверждённые положительные разрывы;
- неоценённые и ожидающие подтверждения компетенции не включаются;
- пункты существующего плана вне текущего перечня разрывов не удаляются;
- активный либо отправленный на согласование KBA-план не пересобирается автоматически;
- stale-ссылки на Moodle-план восстанавливаются через стабильный маркер KBA;
- учебный план не зачисляет пользователя на курсы автоматически;
- схема базы данных не меняется;
- destructive migration отсутствует.

## Новые точки входа

- `/local/kbacorporate/study_plan_provision.php?companyid=<id>&userid=<id>` — финальная проверка и создание учебного плана;
- `/local/kbacorporate/gap_learning_plan.php?companyid=<id>&userid=<id>` — выбор состава и предпросмотр.

## Известные ограничения

- создание учебного плана не выполняет автоматическое зачисление на рекомендованные курсы;
- Moodle runtime/API и capability-проверки должны быть подтверждены на пилотном сервере;
- статус учебного плана Moodle продолжает использовать существующий контракт интеграции v0.31.1–v0.31.6.
