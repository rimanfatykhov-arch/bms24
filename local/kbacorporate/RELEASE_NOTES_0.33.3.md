# KBA Corporate Dashboard v0.33.3 — Прогресс внедрения по разделам BMS

- Moodle component: `local_kbacorporate`
- Numeric build: `2026090813`
- Minimum Moodle: 4.0
- Status: BETA / prepared for pilot runtime validation
- Upgrade path: in-place from `0.33.2`

## Назначение

Релиз добавляет единый read-only экран, который объединяет состояние подтверждённого аудита и фактическое выполнение действий внедрения по каждому разделу BMS.

Целевая цепочка:

`подтверждённый аудит → раздел BMS → критерии и разрывы → действия → доказательства → риски → следующий аудит`.

## Новые возможности

### Сводка по разделам

Для каждого раздела отображаются:

- средняя подтверждённая оценка зрелости;
- средняя целевая оценка;
- изменение относительно предыдущего подтверждённого аудита того же инструмента;
- количество оценённых и неоценённых критериев;
- критерии с положительным разрывом;
- критерии в зоне внимания;
- покрытие разрывов действиями;
- выполнение действий;
- принятые, отправленные и возвращённые доказательства;
- просроченные действия и действия без ответственного.

### Статусы разделов

Раздел получает один из аналитических статусов:

- требует оценки;
- цель достигнута;
- нет действий;
- частично покрыто;
- в работе;
- на проверке;
- есть просрочка;
- действия выполнены.

Статус не изменяет аудит или задачи и рассчитывается при открытии страницы.

### Детализация

По каждому разделу можно раскрыть критерии с положительным разрывом и увидеть:

- код и название критерия;
- фактический и целевой уровни;
- величину разрыва и приоритет;
- связанные действия;
- ответственного;
- срок;
- статус действия;
- статус последней версии доказательства.

При наличии прав и редактируемой программы можно перейти к созданию отсутствующего действия для конкретного критерия.

### Сравнение с предыдущим аудитом

Если у компании есть предыдущий подтверждённый аудит того же инструмента, показывается изменение средней оценки каждого раздела и изменение BMS Index.

### CSV-экспорт

Добавлен экспорт текущей сводки по разделам с учётом выбранных компании и аудита. Значения, способные интерпретироваться электронной таблицей как формулы, экранируются.

## Разделение источников истины

- зрелость берётся только из неизменяемого подтверждённого аудита;
- выполнение — из действий внедрения;
- доказательства — из последней версии доказательства каждой задачи;
- завершение действия и принятие доказательства не переписывают оценку аудита;
- изменение зрелости фиксируется только следующим подтверждённым аудитом.

## Доступ и безопасность

- менеджер видит компании в своём разрешённом контуре;
- куратор видит компании назначенных ему программ внедрения;
- выбранный аудит обязан принадлежать выбранной компании и иметь статус `confirmed`;
- детализация действий сохраняет company scope существующих рабочих страниц;
- экран не выполняет POST-операций и не изменяет данные;
- CSV использует ту же проверку доступа, что и экран.

## Изменение базы данных

Схема базы данных не меняется. Релиз добавляет только no-op upgrade savepoint `2026090813`.

## Известные ограничения

- прогресс выполнения рассчитывается как аналитическая модель по статусам: запланировано 0%, в работе 35%, на проверке 70%, выполнено 100%; это не оценка зрелости BMS;
- при нескольких действиях для одного критерия покрытие критерия считается один раз, а прогресс выполнения учитывает все незакрытые/завершённые действия;
- отменённые действия не покрывают разрыв;
- историческая динамика доступна только при наличии предыдущего подтверждённого аудита того же инструмента;
- runtime-проверка SQL, прав доступа, CSV и отображения на реальных данных выполняется на пилотном Moodle.
