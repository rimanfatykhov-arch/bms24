# AI DECISION LOG — v0.31.8

## Решение

Разделить три независимых состояния:

1. выполнение действия плана;
2. прохождение курса;
3. подтверждённый уровень компетенции.

## Причина

Курс может быть завершён, но это не доказывает автоматическое достижение целевого уровня компетенции. Если смешать эти состояния, система будет преждевременно закрывать разрывы и искажать профиль сотрудника.

## Принятый контракт

1. Moodle course completion — доказательство обучения, а не подтверждённая оценка компетенции.
2. Синхронизация курса может перевести действие KBA в «Завершено».
3. Разрыв закрывается только авторитетным текущим уровнем Moodle competency.
4. Неоценённое значение остаётся `null` и никогда не считается нулём.
5. После завершения плана создаётся отдельная повторная оценка компетенций.
6. Страница прогресса не выполняет автоматическое зачисление на курсы.
7. Фильтры и сводка являются read-only проекцией и не меняют данные.

## Отклонённые варианты

### Автоматически повышать компетенцию после завершения курса

Отклонено: прохождение курса не гарантирует требуемый уровень применения компетенции.

### Считать пункт завершённым по любому проценту прогресса

Отклонено: действие завершается только по Moodle course completion либо явному управляемому статусу.

### Создавать повторную оценку для каждого завершённого курса отдельно

Отклонено для этой версии: это создаёт множество фрагментарных аудитов. Повторная оценка запускается после завершения плана.

## Технический долг

- управляемое зачисление на курсы с проверкой лицензий и групп — v0.31.9;
- уведомления о просрочке и необходимости повторной оценки могут быть расширены;
- требуется runtime PHPUnit на Moodle 4.0.
