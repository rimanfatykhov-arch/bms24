# KBA Corporate ERP API — стабильный контракт v1

**Плагин:** `local_kbacorporate`  
**Релиз:** `0.35.0`  
**Build:** `2026091005`  
**Contract major:** `1`  
**Contract release:** `1.0.0`  
**Public bridge:** `1.17`

## Внешняя служба

- Shortname: `local_kbacorporate_erp_v1`
- Авторизация: отдельный Moodle web-service user и token
- Capability: `local/kbacorporate:useerpapi`
- Служба устанавливается выключенной и с `restrictedusers = 1`
- Формат: JSON UTF-8 внутри стандартного ответа Moodle REST

## Стабильные операции

| Moodle function | Тип | Контракт |
|---|---|---|
| `local_kbacorporate_erp_contract` | read | Версия, правила совместимости, владельцы данных, лимиты и schema hash |
| `local_kbacorporate_erp_status` | read | Готовность службы и отпечаток контракта без бизнес-данных |
| `local_kbacorporate_erp_push_entity` | write | Идемпотентный upsert по `(system, entity_type, external_id)` |
| `local_kbacorporate_erp_pull_company_snapshot` | read | Постраничный снимок компании без ФИО и email |

## Совместимость

- Major version `1` сохраняет обратную совместимость.
- Новые необязательные поля могут добавляться.
- Клиент обязан игнорировать неизвестные поля ответа.
- Ломающее изменение требует contract major `2` и новой внешней службы.
- Provider token является буквальным и неизменяемым идентификатором интеграции.
- Старые provider token и поля, включая `odoo`, сохраняются во внутренних контрактах.
- `schema_hash` позволяет коннектору обнаружить изменение опубликованной схемы.

## Владение данными

ERP владеет внешними идентификаторами компании и сотрудника, а также внешними назначениями бизнес-ролей. Moodle владеет фактом обучения, подтверждёнными уровнями компетенций, доказательствами и учебными планами. KBA хранит корпоративную бизнес-логику, разрывы, ИПР и связь с BMS.

## Методологические ограничения

- Завершение курса не подтверждает уровень компетенции.
- Неоценённая компетенция передаётся как `null`, а не `0`.
- Завершение действия и принятие доказательства не повышают зрелость BMS.
- Новая зрелость появляется только из нового подтверждённого аудита.
- Корреляция обучения, внедрения и экономики не объявляется причинностью.

## Ошибки и повтор

Ошибки параметров возвращаются стандартным Moodle REST exception. Повторять автоматически следует только временные транспортные ошибки. Бизнес-ошибку или несовместимую версию необходимо исправить до следующей отправки. Внешние ID нельзя повторно использовать для другой сущности.
