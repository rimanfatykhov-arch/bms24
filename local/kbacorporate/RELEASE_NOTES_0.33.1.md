# RELEASE NOTES — KBA Corporate Dashboard v0.33.1

## Release

- Product: KBA Corporate Dashboard
- Moodle component: `local_kbacorporate`
- Version: `0.33.1 — Управление доказательствами внедрения`
- Numeric build: `2026090811`
- Status: BETA / prepared for pilot runtime validation
- Minimum Moodle: 4.0
- Upgrade baseline: `0.33.0`

## Purpose

Релиз переводит подтверждение результата действия по внедрению из одного перезаписываемого комментария в управляемый версионный процесс. Исполнитель отправляет отдельную версию доказательства, а куратор или менеджер принимает её либо возвращает на доработку. История отправок и решений сохраняется.

## Functional changes

### Versioned evidence workspace

Добавлена страница `implementation_evidence.php` с единым рабочим пространством:

- отправка комментария исполнителя;
- внешняя подтверждающая ссылка;
- до 20 файлов на одну версию;
- история всех версий;
- статус каждой версии;
- решение и комментарий проверяющего;
- отдельный журнал событий.

Каждая новая отправка получает последовательный номер `v1`, `v2`, … . Содержимое отправленной версии не редактируется. После возврата исполнитель создаёт следующую версию; предыдущая остаётся доступной.

### Managed review workflow

Рабочий цикл задачи теперь связан с решением по доказательству:

```text
В работе
→ Доказательство отправлено
→ На проверке
→ Принято → Выполнено
   или
→ Возвращено → В работе → новая версия
```

Правила:

1. отправлять доказательство может назначенный исполнитель задачи;
2. отправка доступна только для задачи «В работе»;
3. одновременно на проверке может находиться только одна версия;
4. исполнитель не может проверить собственное доказательство;
5. принимать или возвращать может куратор программы либо менеджер с правом управления аудитами;
6. при возврате комментарий обязателен;
7. принятие завершает задачу;
8. возврат снова переводит её в работу;
9. прямое изменение workflow-статуса блокируется после начала версионной проверки.

### Backward compatibility

- старые поля задачи `completioncomment` и `resulturl` продолжают заполняться последней отправкой для существующих интеграций и отчётов;
- старые файлы из `implementation_task_evidence` остаются доступны только для чтения;
- старые доказательства автоматически не преобразуются в новые версии;
- обсуждения, чек-листы, напоминания и уведомления задачи продолжают использовать прежний механизм;
- существующие URL задач не удаляются.

### Data governance

Добавлены две таблицы:

- `local_kbacorp_impl_evid` — версии доказательств;
- `local_kbacorp_impl_evlog` — журнал отправок и решений.

Файлы хранятся в filearea:

```text
local_kbacorporate / implementation_evidence_record / <evidenceid>
```

Добавлены:

- защита файлов теми же правами, что и у задачи;
- очистка данных при удалении компании;
- privacy metadata, экспорт и обезличивание участников;
- проверка таблиц в Integration Health Center.

## Schema impact

Изменение схемы аддитивное:

- 2 новые таблицы;
- новые поля в существующие таблицы не добавляются;
- существующие записи не переписываются;
- destructive migration отсутствует;
- upgrade savepoint: `2026090811`.

## Known limitations

- старые доказательства остаются в legacy-формате и не получают номер версии;
- автоматическая миграция legacy-файлов намеренно не выполняется;
- принятие доказательства не меняет оценку критерия BMS автоматически; изменение подтверждается следующим аудитом;
- электронная подпись и отдельный маршрут согласования несколькими проверяющими не входят в этот релиз;
- полноценный runtime-тест Moodle file API, сообщений, privacy и обновления схемы требуется на пилотном сервере.

## Backup and rollback

Перед установкой обязательны резервные копии базы данных, каталога плагина и `moodledata`. Релиз добавляет таблицы, поэтому откат только заменой файлов на `v0.33.0` не является поддерживаемым downgrade. Для полного отката следует восстановить резервную копию. Новые таблицы и доказательства автоматически не удаляются.
