# KBA Corporate Dashboard v0.33.4 — Реестр экономических показателей

- Moodle component: `local_kbacorporate`
- Numeric build: `2026090815`
- Minimum Moodle: 4.0
- Status: BETA / подготовлен к пилотной runtime-проверке
- Upgrade path: in-place from `0.33.3.1`
- Schema impact: additive; добавляются 3 таблицы

## Назначение

Релиз создаёт единый управляемый слой экономических данных компании, на котором будут строиться сравнение аудитов, графики, экономические панели и обмен с ERP.

Целевая цепочка:

`компания → показатель → период → факт/план/прогноз → источник → аудит BMS → история изменения`.

## Новые возможности

### Каталог показателей

Добавлен глобальный системный каталог со стабильными кодами и возможность создавать показатели конкретной компании. Для каждого показателя хранятся:

- стабильный код;
- название и описание;
- категория;
- тип значения;
- единица измерения;
- периодичность;
- источник по умолчанию;
- желаемое направление изменения;
- активность и порядок отображения.

Системные показатели доступны всем компаниям только для чтения. Показатели компании можно создавать, изменять, архивировать и возвращать из архива. Физическое удаление через интерфейс не выполняется.

### Базовый системный каталог

В релиз входят коды:

`REV`, `GROSS_PROFIT`, `OPERATING_PROFIT`, `PROFIT`, `EBITDA`, `MARGIN`, `DEBT`, `PAYROLL`, `EMPLOYEES`, `AVG_SALARY`, `TURNOVER`, `HIRING_COST`, `CLIENTS`, `AVG_CHECK`, `CONVERSION`, `SALES_PLAN`, `REVENUE_PER_EMPLOYEE`, `CYCLE_TIME`, `PROFIT_TAX`, `VAT`, `SOCIAL_FUNDS`, `OTHER_TAXES`.

### Значения по периодам

Поддерживаются периоды:

- месяц;
- квартал;
- год;
- произвольный диапазон.

Для одного показателя и периода можно хранить отдельные сценарии:

- факт;
- план;
- прогноз.

Уникальность контролируется по сочетанию:

`компания + показатель + период + сценарий`.

### Источник и достоверность

Источники данных:

- ручной ввод;
- ERP;
- импорт;
- API.

Для каждого значения сохраняются валюта, комментарий, признак подтверждения, автор, пользователь подтверждения и даты изменения.

### Связь с аудитом BMS

Значение можно связать с аудитом той же компании. Реестр доступен из карточки аудита с уже выбранным фильтром. Аудит другой компании выбрать или передать нельзя.

### Совместимость с существующими экономическими снимками

При обновлении старые записи `local_kbacorp_impl_econ` переносятся в новый реестр без удаления исходных данных. Повторный запуск миграции идемпотентен.

После установки сохранение старого экономического снимка аудита синхронизирует соответствующие фактические значения в новом реестре. Старый снимок остаётся источником совместимости для существующего экрана аудита.

### Журнал изменений

Создание, редактирование и архивирование показателя, а также создание и изменение значения фиксируются в отдельном неизменяемом журнале со снимками состояния до и после операции.

### Приватность и удаление данных

Новые таблицы включены в Moodle Privacy API. Идентификаторы авторов, редакторов и проверяющих экспортируются как персональные данные и анонимизируются при удалении пользователя. Идентификаторы проверяющих, сохранённые внутри снимков журнала, также очищаются без удаления экономической истории компании.

### CSV

Добавлен CSV-экспорт текущей выборки. Экспорт учитывает фильтры по категории, активности показателя, аудиту, источнику, периодичности, сценарию и поисковой строке. Текстовые значения защищаются от formula injection.

### Подготовка ERP/API

Добавлен внутренний идемпотентный контракт `upsert_external_value()` по стабильному коду показателя, периоду и сценарию. Внешняя web-service операция в `v0.33.4` ещё не публикуется.

## Права доступа

Добавлены capabilities:

- `local/kbacorporate:vieweconomicindicators`;
- `local/kbacorporate:manageeconomicindicators`.

Дополнительно применяется существующая проверка доступа к конкретной компании.

## Изменение базы данных

Добавляются таблицы:

- `local_kbacorp_econ_ind` — определения показателей;
- `local_kbacorp_econ_val` — периодические значения;
- `local_kbacorp_econ_log` — история изменений.

Миграция аддитивная: существующие таблицы и данные не удаляются.

## Что не входит в релиз

- графики и KPI-панели;
- аналитика «до / после»;
- расчёт причинного влияния обучения или внедрения;
- публичная ERP API operation;
- массовый CSV-импорт;
- автоматическое удаление значений.

Это запланировано в ветке `v0.34.x` и `v0.35.x`.

## Резервное копирование и откат

Перед установкой требуется резервная копия:

- базы данных;
- каталога `local/kbacorporate`;
- `moodledata`.

Простая замена файлов на `v0.33.3.1` не удалит новые таблицы. Полный откат схемы выполняется восстановлением резервной копии либо осознанным сохранением новых таблиц с совместимым кодом.

## Известные ограничения

- системные названия базового каталога ориентированы на русскоязычную поставку;
- одна запись значения связывается не более чем с одним аудитом;
- подтверждение значения является управленческим флагом и не выполняет внешнюю сверку с ERP;
- список и история пока выводятся без серверной пагинации;
- runtime-проверка upgrade, прав, SQL и форм выполняется на пилотном Moodle.
