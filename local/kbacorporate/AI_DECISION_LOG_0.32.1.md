# AI Decision Log — v0.32.1

## Решение 1. Отдельный журнал оценок, а не повтор истории всех событий

История отдельной компетенции v0.32.0 показывает оценки, evidence, курсы и учебные планы. Для управленческого анализа сотрудника создан отдельный журнал только оценочных событий, чтобы завершение курса не выглядело как подтверждение уровня.

## Решение 2. Подтверждённый уровень Moodle остаётся источником истины

Новый отчёт является read-only проекцией. Он не создаёт и не обновляет `competency_usercomp`, аудиты, курсы или планы.

## Решение 3. Динамика использует только принятые уровни

В longitudinal comparison участвуют статусы `confirmed` и `recorded` с известным уровнем. Pending, rejected и missing остаются в журнале для аудита процесса, но не влияют на delta.

## Решение 4. Неоценённое не равно нулю

При отсутствии принятой оценки trend получает состояние «нет данных для сравнения»; нулевой уровень автоматически не подставляется.

## Решение 5. Компания ограничивает видимость истории

В отчёт попадают только competency ids, уже прошедшие company-scoped projection v0.32.0. Это предотвращает раскрытие менеджеру истории из другой компании пользователя.

## Решение 6. Динамика пересчитывается после фильтров

При выборе периода или источника первая и последняя оценка рассчитываются внутри выбранной выборки. Это делает отчёт пригодным для сравнения конкретного этапа развития, но пользователь должен учитывать активные фильтры.

## Решение 7. CSV повторяет экранную выборку

Экспорт получает те же параметры и не расширяет доступ. В файл включены сводка, динамика и журнал событий.

## Известный технический долг

Moodle core не гарантирует полный журнал всех прежних текущих grades. Для полноценной неизменяемой истории в будущем может потребоваться отдельный snapshot/audit trail, но в v0.32.1 новая таблица не вводится.
