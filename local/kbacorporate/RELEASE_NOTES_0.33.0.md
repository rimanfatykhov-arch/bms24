# RELEASE NOTES — KBA Corporate Dashboard v0.33.0

## Release

- Product: KBA Corporate Dashboard
- Moodle component: `local_kbacorporate`
- Version: `0.33.0 — Критерий аудита → действие по внедрению`
- Numeric build: `2026090810`
- Status: BETA / prepared for pilot runtime validation
- Minimum Moodle: 4.0
- Upgrade baseline: `0.32.3`

## Purpose

Релиз открывает ветку управления внедрением BMS. Подтверждённый разрыв по критерию аудита превращается в управляемое действие с ответственным, приоритетом, ожидаемым результатом и сроком. Система использует существующие задачи внедрения и не создаёт параллельное хранилище.

## Functional changes

### Audit-to-action preview

Добавлена страница `implementation_actions.php`, которая показывает только подтверждённые положительные разрывы аудита:

- критерий и раздел BMS;
- фактический уровень;
- целевой уровень;
- величину разрыва;
- автоматически рассчитанный приоритет;
- доступные маршруты внедрения;
- ожидаемый результат;
- рекомендуемый срок;
- уже существующее действие или состояние «Будет создано».

### Controlled bulk creation

- пользователь явно выбирает критерии чекбоксами;
- для нескольких маршрутов выбирается нужный маршрут;
- можно назначить общего ответственного;
- критический разрыв получает срок 30 дней;
- основной разрыв — 60 дней;
- дополнительный — 90 дней;
- при отсутствии маршрута создаётся базовое действие по критерию;
- существующее действие не перезаписывается и не дублируется;
- частичные ошибки изолируются и отражаются в итоговой сводке.

### Direct criterion action

В подтверждённом аудите для каждого критерия с положительным разрывом появляется действие «Создать действие». Если задача уже существует, отображается «Открыть действие».

### Governance

Действия создаются только когда одновременно выполнены условия:

1. аудит подтверждён;
2. у критерия есть известный положительный разрыв;
3. программа внедрения оплачена и активна;
4. ответственный является действующим сотрудником компании;
5. пользователь имеет право управлять аудитами и полный доступ к компании.

Черновые оценки, критерии без оценки и достигнутые критерии не используются как основание для автоматического действия.

## Data and schema impact

- новые таблицы и поля не добавляются;
- используется `local_kbacorp_impl_task`;
- маршруты берутся из `local_kbacorp_bms_route`;
- снимок аудита остаётся неизменяемым источником фактического и целевого уровня;
- destructive migration отсутствует.

## Backward compatibility

- существующие задачи, обсуждения, чек-листы, доказательства и история статусов сохраняются;
- индивидуальное создание и редактирование задач продолжает работать;
- жизненный цикл `Запланировано → В работе → На проверке → Выполнено` не меняется;
- существующие API и URL не удаляются.

## Known limitations

- в v0.33.0 общий ответственный назначается сразу всем выбранным действиям; индивидуальная корректировка выполняется после создания;
- автоматическая запись на связанный курс не выполняется;
- создание действий из неподтверждённого аудита намеренно запрещено;
- повторное открытие отменённой задачи выполняется через существующее административное редактирование;
- полноценный runtime-тест прав, SQL, программы внедрения и массового создания требуется на пилотном Moodle.

## Backup and rollback

Схема БД не меняется, однако перед пилотным Apply рекомендуется резервная копия базы и каталога плагина. Откат к предыдущему ZIP не удаляет созданные пользователем действия; при необходимости их следует отменить вручную либо восстановить резервную копию.
