# KBA Corporate Dashboard v0.32.2.1
## Исправление ссылки на шаблон учебного плана Moodle

Дата: 8 сентября 2026 года  
Тип изменения: PATCH  
Build: `2026090808`

## Причина

На странице интеграции учебных планов ссылка **«Открыть шаблон Moodle #N»** формировалась только с параметром `templateid`.

Стандартная страница Moodle 4.0 `/admin/tool/lp/templatecompetencies.php` требует два параметра:

- `templateid` — идентификатор шаблона;
- `pagecontextid` — контекст страницы, из которого открыт шаблон.

Без `pagecontextid` Moodle завершал запрос ошибкой `missingparam`.

## Исправлено

- метод `moodle_learning_plans::template_url()` теперь всегда добавляет `pagecontextid`;
- по умолчанию контекст читается из записи `competency_template.contextid`;
- для отсутствующего контекста предусмотрен безопасный fallback на системный контекст;
- сохранена возможность явно передать `pagecontextid` вызывающим кодом;
- добавлены регрессионные тесты для явного и автоматически определяемого контекста.

## Результат

Ссылка теперь формируется в совместимом формате:

```text
/admin/tool/lp/templatecompetencies.php?templateid=<ID>&pagecontextid=<CONTEXT_ID>
```

Для шаблонов KBA, создаваемых в системном контексте, обычно используется `pagecontextid=1`, однако код не фиксирует это значение жёстко и читает реальный контекст шаблона.

## Безопасность обновления

- схема базы данных не меняется;
- данные шаблонов и учебных планов не изменяются;
- миграция не выполняет destructive-операций;
- исправляется только построение URL;
- upgrade фиксирует savepoint `2026090808`.

## Проверка

1. Открыть `/local/kbacorporate/moodle_learning_plans.php?companyid=<ID>`.
2. Нажать **«Открыть шаблон Moodle #N»**.
3. Убедиться, что URL содержит `templateid` и `pagecontextid`.
4. Убедиться, что открывается стандартная страница компетенций шаблона Moodle без ошибки `missingparam`.
