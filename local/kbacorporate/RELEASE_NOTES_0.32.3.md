# RELEASE NOTES — KBA Corporate Dashboard v0.32.3

## Release

- Product: KBA Corporate Dashboard
- Moodle component: `local_kbacorporate`
- Version: `0.32.3 — Индивидуальный план развития сотрудника`
- Numeric build: `2026090809`
- Status: BETA / prepared for pilot runtime validation
- Minimum Moodle: 4.0
- Upgrade baseline: `0.32.2.1`

## Purpose

Релиз превращает ранее созданный план по разрывам компетенций в полноценный индивидуальный план развития сотрудника. Стандартный учебный план Moodle остаётся источником состава компетенций, а KBA хранит управленческий контекст: цель, ответственность, практика, доказательства, контроль и историю решений.

## Functional changes

### Plan level

- общая цель развития сотрудника;
- ответственный за план;
- дата контрольного пересмотра;
- проверка согласованности срока плана со сроками действий;
- отображение цели, ответственного и контрольной даты в карточке плана.

### Development action level

- отдельная цель развития по компетенции;
- обязательное или поддерживающее действие;
- практическое задание;
- критерии принятия доказательства;
- наставник действия;
- контрольная дата и комментарий;
- отдельная карточка действия;
- внешняя ссылка и/или комментарий как доказательство;
- отправка доказательства на проверку;
- принятие или возврат на доработку;
- запрет самоподтверждения доказательства;
- статус `pendingreview` / «Ожидает проверки».

### Course and competency governance

- курс без дополнительных требований может завершить действие по существующему правилу;
- если заданы практика или критерии доказательства, завершение курса переводит действие в работу, но не завершает его;
- действие с обязательным доказательством завершается только через явное принятие доказательства;
- завершение действия не изменяет уровень компетенции автоматически;
- подтверждённый уровень остаётся в Moodle Competencies.

### History and notifications

- новая таблица `local_kbacorp_devlog` хранит значимые события ИПР;
- отдельная страница истории с фильтром по типу события;
- напоминания получают сотрудник, действующий наставник плана, наставники действий и уполномоченные руководители;
- наставник отдельного действия получает только сведения по назначенным ему действиям;
- удалённый из компании наставник больше не считается действующим получателем и участником.

## Database migration

Релиз меняет схему базы данных аддитивно.

`local_kbacorp_devplan`:

- `objective`;
- `mentorid`;
- `reviewdate`.

`local_kbacorp_devitem`:

- `required`;
- `goal`;
- `practicaltask`;
- `evidencecriteria`;
- `mentorid`;
- `checkpointdate`;
- `checkpointcomment`;
- `evidenceurl`;
- `evidencecomment`;
- `evidencesubmittedby`;
- `timeevidencesubmitted`;
- `reviewedby`;
- `timereviewed`;
- `reviewcomment`;
- индексы по наставнику/статусу и проверяющему/статусу.

Новая таблица:

- `local_kbacorp_devlog`.

Backfill:

- `reviewdate` существующего плана получает текущее значение `targetdate`;
- обязательность существующего действия по возможности восстанавливается из актуального профиля роли;
- остальные новые поля остаются пустыми либо получают безопасные значения по умолчанию;
- прежняя история не реконструируется.

## Access and privacy

- сотрудник видит собственный ИПР;
- уполномоченный руководитель видит сотрудников в своей области доступа;
- назначенный действующий наставник компании получает доступ к работе с планом/действием;
- сведения новых полей и история включены в Moodle Privacy API;
- при удалении субъекта его планы, действия и история удаляются;
- идентификаторы наставника, отправителя доказательства, проверяющего и актёра истории анонимизируются при удалении соответствующего пользователя.

## Backup and rollback prerequisites

Перед установкой обязательно создать резервную копию:

1. базы данных Moodle;
2. каталога `local/kbacorporate`;
3. при production-развёртывании — `moodledata` согласно принятой политике резервирования.

Простое возвращение старого ZIP не откатывает структуру БД. Для полного rollback требуется восстановление резервной копии базы. Поля и таблица не удаляются автоматически.

## Known limitations

- Файловые вложения к доказательству ИПР в 0.32.3 отсутствуют; используются URL и текстовый комментарий.
- Автоматической записи сотрудника на рекомендованный курс нет.
- История фиксируется только после установки 0.32.3.
- Полный runtime-тест upgrade, cron, Moodle API, privacy и прав доступа должен быть выполнен на пилотном сервере до объявления Stable.
