# KBA Corporate Dashboard v0.33.3.1 — Терминология ERP в интерфейсе

- Moodle component: `local_kbacorporate`
- Numeric build: `2026090814`
- Minimum Moodle: 4.0
- Status: BETA / prepared for pilot runtime validation
- Upgrade path: in-place from `0.33.3 / 2026090813`

## Назначение

Релиз переводит пользовательский интерфейс с названия конкретного поставщика `Odoo` на нейтральный термин `ERP`.

Изменение касается только пользовательских подписей, пояснений и описаний интеграции. Технические идентификаторы, provider tokens, существующие записи обмена и контракт API сохраняются для обратной совместимости.

## Изменения интерфейса

В русском интерфейсе обновлены:

- право доступа к API обмена;
- название версии API обмена;
- подписи состояния внешней службы ERP;
- источник экономических данных;
- описание интеграции учебных планов Moodle;
- описание корпоративного расширения KBA;
- описания KBA-шаблонов и учебных планов Moodle.

Основные замены:

```text
Odoo → ERP
Odoo/BMS Digital ERP API → API обмена с ERP
Синхронизация с Odoo → синхронизация с ERP
BMS / Odoo → BMS / ERP
```

Английские пользовательские строки также переведены на нейтральное обозначение `ERP`.

## Совместимость

Технический ключ источника экономических данных остаётся:

```text
odoo
```

Он используется как стабильное внутреннее значение и не отображается пользователю. В интерфейсе это значение теперь подписано как `ERP`.

Также без изменений сохраняются:

- capability `local/kbacorporate:useerpapi`;
- имена внешних функций `local_kbacorporate_erp_*`;
- provider token `odoo` в существующих интеграциях;
- таблицы и данные обмена;
- JSON/API-контракты.

## Обновление существующих описаний Moodle

Во время обновления плагин безопасно заменяет `Odoo` на `ERP` только в описаниях объектов, созданных KBA и содержащих служебные маркеры:

```text
KBA-BUSROLE:
KBA-DEVPLAN:
```

Пользовательские шаблоны и планы без этих маркеров не изменяются.

## База данных

Схема базы данных не меняется. Выполняется только недеструктивная текстовая миграция описаний KBA-шаблонов и KBA-планов Moodle.

## Проверка после установки

1. Открыть `/local/kbacorporate/api.php` и проверить, что используется термин `ERP`.
2. Открыть форму экономических показателей аудита и проверить источник `ERP`.
3. Открыть `/local/kbacorporate/moodle_learning_plans.php` и проверить описание интеграции.
4. Открыть шаблон и учебный план Moodle, созданные KBA, и проверить обновлённые описания.
5. Убедиться, что существующий обмен с provider token `odoo` продолжает работать без перенастройки.

## Известные ограничения

- исторические release notes и техническая документация могут сохранять название `Odoo`, когда оно описывает конкретного провайдера или прежнее архитектурное решение;
- релиз не переименовывает технические значения в БД и API;
- runtime-проверка отображения и миграции выполняется на пилотном Moodle.
