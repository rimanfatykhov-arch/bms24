# BMS 0.6.9.11.2 + KBA AI 0.9.3 — сборка 2026092213

## Статус и база
Новый устанавливаемый checkpoint, не подтверждённый production release.
BMS основан на 0.6.9.11.1 build 2026092206, обнаруженном в Drive, а не на более старом 0.6.9.11.
KBA AI основан на предоставленном 0.9.2 build 2026092212.
Предыдущие артефакты не перезаписываются. Тема не изменяется.

## Новое относительно предыдущих пакетов
В общей панели Философии/Рынка добавлено поле «Ответы и уточнения для помощника».
Пользователь может получить вопросы, ввести ответы, выбрать подготовку формулировки
и отправить новый запрос. Ответы помечены как непроверенные сведения и передаются
выбранному AI-провайдеру. Панель хранит их только в памяти открытой страницы;
этот релиз не добавляет серверную историю диалога или запись уточнений в карточку.

Domain-owned методические пояснения различают предназначение, миссию, видение,
описание рынка и проверку доказательств. Пять versioned AI profiles (0.3) задают
разное поведение: объяснение, интервью, формулировка, проверка и проверка доказательств.
В запрос Yandex теперь явно включена locale. Аналитические режимы не возвращают
текст для замены поля; инструкцию вместо текста после одной неуспешной коррекции
нельзя перенести в поле.

Проверка доступности учитывает установленный контракт и наличие настроек провайдера.
Отсутствующий провайдер не подменяется mock автоматически. Явно выбранный mock
отмечается как тестовый до первого запроса. Пустая тестовая формулировка не заменяется
вымышленным примером. Readiness проверяет настройки, но не доступность сети/ключа.

После генерации BMS заново проверяет права, редакцию и разрешённый контекст.
Изменившаяся запись или исходные данные делают ответ устаревшим. Изменение уточнений
также блокирует перенос предыдущего предложения. Замена непустого текста требует
подтверждения. «Использовать» не сохраняет и не публикует запись: обычная кнопка
сохранения по-прежнему вызывает существующий domain service.

## Установка
1. Сделать согласованную резервную копию БД, moodledata и кода Moodle.
2. Установить INSTALL_ME_local_kbaai_v0.9.3_build2026092213.zip.
3. Установить INSTALL_ME_local_kbacompany_v0.6.9.11.2_build2026092213.zip.
4. Завершить обновление Moodle и очистить кэши.

Использовать только INSTALL_ME, не SOURCE и не RELEASE_KIT. Во время обновления пары
предыдущий BMS 0.6.9.11.1 временно не принимает AI contract 0.3; обычный CRUD остаётся
доступен. Новый BMS поддерживает контракты 0.1/0.2/0.3, но полная новая функциональность
проверена локально именно с парой 0.6.9.11.2 + 0.9.3.

Новых таблиц, полей, capabilities и web services не добавлено. Upgrade содержит только
новые savepoints. Откат после обновления — восстановление согласованной резервной копии,
а не уменьшение version.php. Целевая приёмочная среда: Moodle 4.1.22 / PHP 7.3+.

## Что проверить на Moodle
Философия → Редактировать → Помочь → Задать вопросы → ответы в уточнениях →
Помочь сформулировать → Получить ответ → Использовать → обычное сохранение.
Повторить для Рынка. Проверить отсутствие готового текста при нехватке сведений,
неизменность формы при отказе от замены и при ошибке, блокировку устаревшей редакции,
manager / обычного участника / site admin без membership, изоляцию двух компаний,
явный mock, отсутствие конфигурации и реальный Yandex на разрешённых тестовых данных.

## Границы
Не добавлены внешний data adapter, ISWORK endpoint, новая модель задач/финансов/AI,
server-side audit AI-диалога или исправления наследования дочерних снимков рынка.
Секреты и OWNER-CONF не следует вводить в уточнения. Провайдер получает введённый текст;
его собственная политика хранения не контролируется этим плагином.

PHPUnit/Moodle E2E/установка на staging/production и реальный запрос Yandex не запускались.
Подробности выполненных локальных проверок — в QA_REPORT_build2026092213.md.
