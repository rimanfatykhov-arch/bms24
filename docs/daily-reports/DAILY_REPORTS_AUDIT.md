## 1. Принятые требования (ПРИНЯТО, DR-D01–D05)

1. Вместо непонятной «Сводки моего…» нужен понятный вход в раздел.
2. Сотрудник может каждый день составить отчёт.
3. Отчёты сохраняются за конкретные даты.
4. Руководитель проверяет и оценивает отчёты.
5. Отчёт и оценка остаются доступны в истории.

Названия, поля, статусы, шкала, права и порядок внедрения ниже — **ПРЕДЛОЖЕНО**.

## 4. Почему «Сводка моего…» непонятна

**ПРОВЕРЕНО кодом:**

1. **Расположение.** Это не пункт меню, а кнопка над списком задач. Страница сводки открывается с подсвеченным
   разделом «Задачи», поэтому в боковом меню собственного входа нет и вернуться туда можно только через задачи.
2. **Формулировка.** «Сводка моего дня» не говорит, что это отчёт и что его можно сохранить или отправить.
   Сам экран честно предупреждает, что это «просмотр данных, а не отправленный дневной отчёт», то есть название
   не совпадает с ожиданием «отчёта».
3. **Длина.** 16 символов. В legacy-шапке темы для заголовка раздела действует `white-space: nowrap;
   text-overflow: ellipsis` (`local/kbacompany/styles.css:4461`), а заголовок страницы попадает в последнюю
   «хлебную крошку». На ширине 320–390 px строка из трёх слов легко обрезается до «Сводка моего…»,
   а обрезанная фраза теряет смысл, потому что ключевое слово «дня» стоит последним.

**НЕ ПРОВЕРЕНО:** шаблон `theme_kba/bms/app_shell` в этом репозитории отсутствует, и скриншоты владельца в эту
сессию не переданы. Поэтому точное место обрезки (заголовок темы, вкладка браузера, кнопка) не подтверждено.
Нужен скриншот или URL экрана с обрезкой (вопрос В9 в проекте).

**ПРЕДЛОЖЕНО:** пункт бокового меню «Отчёты за день» в группе рабочего пространства рядом с «Задачами»,
на узком экране — «Отчёты». Ключевое слово стоит первым, поэтому даже обрезанная надпись остаётся понятной.
Вкладки: «Мой отчёт», «История», «Сотрудники» (последняя только у проверяющих).

### 5.1. Четыре разных инструмента

| Понятие | В Битрикс24 | Для BMS24 |
|---|---|---|
| План на день | вкладка виджета рабочего дня, личные пункты | задачи со сроком и боевой план недели — **автоданные**, не «утверждённый план дня» |
| Сделано за день | короткие записи в течение дня, видны по дате, из них собирается отчёт | текст сотрудника «Что сделано» в черновике |
| Рабочий отчёт | периодический документ руководителю: отчёт, план, файлы, задачи, события; оценка | **это и есть предлагаемый ежедневный отчёт** |
| Учёт рабочего времени | кнопки начала и завершения дня, длительность, нарушения графика | **вне MVP**; часы из `factminutes` не вычисляются |

### 5.2. Потребность → подход Битрикс24 → решение BMS24

| Потребность | Подход Битрикс24 | Предлагаемое решение BMS24 |
|---|---|---|
| Понятно, куда идти | раздел «Время и отчёты» в меню сотрудников | пункт «Отчёты за день» в рабочем пространстве (ПРЕДЛОЖЕНО) |
| Составить отчёт за день | окно открывается при завершении рабочего дня | сотрудник сам выбирает дату; таймер не нужен |
| Сохранить, не отправляя | черновик, «отложить на час» | черновик на сервере с ревизией; без «отложить» в MVP |
| Связать с работой | ручной выбор задач, автоматические события | автоблок задач и отправленных результатов из BMS24 плюс ручной выбор задач; без копий |
| Не потерять прошлое | после подтверждения редактирование закрыто | отправка замораживает версию, доработка — новая версия |
| Проверка руководителем | положительная, отрицательная, подтверждено без оценки | та же минимальная трёхзначная шкала; оценка привязана к версии |
| Вернуть на доработку | в справке не описан как отдельный статус | отдельное решение «вернуть» с обязательной причиной |
| Кто проверяет | руководитель; способ назначения в справке не раскрыт | явное правило: проверяющий боевого плана → руководитель по структуре → назначение администратором (ТРЕБУЕТ РЕШЕНИЯ) |
| Видеть картину по команде | список со статусами и цветами, фильтр по отделам, процент оценённых | очередь «На проверке / Возвращены / Приняты» и таблица «сотрудники × дни»; статус виден и текстом, и значком |
| Периодичность и напоминания | день/неделя/месяц, время, напоминание на странице | этап 2 после MVP; до появления графика нет «не сдан» |
| Изменение периодичности | новые настройки действуют с даты изменения, промежуток остаётся незакрытым | исторические даты и требования не пересчитываются задним числом |

## 6. Ограничения аудита

- Код читался из `main` `d353509`, ветки #113 `5924bc0`, #111 `a75fedd`, #95 `9e80ee5`. Ветки #112/#114 детально не разбирались:

  с синтетическими данными.

  на данных. Это влияет на правило выбора проверяющего (вопрос В1).
