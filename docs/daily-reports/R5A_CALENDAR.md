# R5a — график отчётности: календарь компании и отсутствия

Статус: исходный код кандидата `local_kbacompany` 2026112400. Не принят, не развёрнут. Решения владельца К1–К6 от 24.11.2026 — в `R5_REPORTING_CALENDAR_PROPOSAL.md` (PR #170).

## Что входит в R5a

| Решение | Реализация |
|---|---|
| К1 календарь компании | Администратор компании задаёт рабочие дни недели (по умолчанию Пн–Пт) и исключения: нерабочие даты (`holiday`) и рабочие выходные (`workday`). Исключение важнее шаблона недели. |
| К2 отсутствия | Вид (`vacation` / `sick` / `other`) и даты, без диагнозов и комментариев. Вносит администратор компании или ближайший руководитель (ADR-0010 D2). Сам сотрудник, вышестоящий руководитель и коллега — нет. Периоды одного человека не пересекаются; длина до 366 дней. |
| К3 срок сдачи | `deadline()` — время (по умолчанию 12:00) следующего рабочего дня в часовом поясе сотрудника. |
| К5 с даты включения | При включении сохраняется `enabledfrom` = сегодня; дни раньше — `beforestart`. Выключение и повторное включение сдвигают дату. |
| К6 свой выключатель | `local_kbacompany_dreportcal.enabled`, по умолчанию 0. Пока выключен, `requirement()` возвращает `disabled`. Глобальный `dailyreports_enabled` остаётся обязательным. |

`requirement($company, $userid, $day)` — модель чтения для R5b/R5c: `disabled`, `beforestart`, `dayoff`, `absence`, `workday`. Обязанность вычисляется при чтении и не хранится.

К4 (утреннее напоминание) и статусы «не сдан / опоздал» в R5a **не входят**: R5b и R5c — отдельные изменения. Cron, нулевые напоминания и существующие уведомления не меняются.

## Экраны

Вкладка «Проверка» отчётов, новые очереди:

- **«График»** (`queue=calendar`) — только администратор: выключатель, дни недели, время срока, исключения.
- **«Отсутствия»** (`queue=absences`) — администратор и руководители: добавление, изменение, отмена периодов людей, которыми актор управляет.

Все формы — POST + `sesskey`, сервер повторно проверяет права. Сотрудник передаётся параметром `employee` (не `userid`).

## База данных

Шаг обновления 2026112400 добавляет три таблицы, существующие таблицы и строки не меняются, без backfill:

- `local_kbacompany_dreportcal` — один календарь на компанию (уникальный `companyuuid`), `revision` для оптимистичной блокировки.
- `local_kbacompany_dreportoff` — исключения, уникальны по (`companyuuid`, `offday`).
- `local_kbacompany_dreportabs` — периоды отсутствия, статус `active` / `cancelled`, `revision`.

Журнал изменений — `local_kbacompany_dreportlog` с пустым `reportuuid`: `calendar_changed`, `offday_added`, `offday_removed`, `absence_added`, `absence_changed`, `absence_cancelled`.

## Безопасность и приватность

- Все запросы ограничены `companyuuid` в SQL; доступ через `company_context_service::context` (отозванный участник теряет доступ).
- Новых capability нет; маршрут прежний (`daily_report.php`).
- Privacy provider: метаданные трёх таблиц; экспорт своих отсутствий, своих изменений календаря и исключений; при удалении — свои периоды удаляются, записи журнала о них теряют детали, авторство в чужих строках анонимизируется (0).
