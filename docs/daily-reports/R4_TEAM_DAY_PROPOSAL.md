# Отчёты за день R4 «Команда за день» — проект на решение владельца

Дата: 24.11.2026. Исполнитель: Claude (правило #160). Статус: **ПРИНЯТО** владельцем 24.11.2026: решения Т1–Т5 по рекомендациям. Реализация — отдельным PR.
Основание: дорожная карта [Issue #75](https://github.com/rimanfatykhov-arch/bms24/issues/75), RC34, пункт
«Экран руководителя „Отчёты моей команды“: сдали / не сдали / просрочили / на доработке / приняты».

## Что уже есть (версия 2026112301, production 23.11)

- R0–R2: свой отчёт, версии, отправка, проверка с оценкой, возврат, переназначение (ADR-0009).
- ADR-0010: проверяющий по оргсхеме; руководители и администраторы читают все отправленные отчёты компании.
- Вкладка «Проверка» с очередями «На проверке», «Возвращены», «Приняты», «Копии мне», «Все отчёты компании»,
  «Без проверяющего».

**Чего нет.** Все очереди строятся только из существующих отчётов. Руководитель не видит, у кого из сотрудников
за день отчёта нет. Сейчас это можно выяснить только вручную.

## Предложение

В разделе «Проверка» появляется очередь **«Команда за день»**. Она видна руководителям и администраторам
компании (тем же, кому сейчас доступна очередь «Все отчёты компании»).

| Колонка | Содержание |
|---|---|
| Сотрудник | имя, подразделение по основному назначению |
| Статус за выбранный день | «Отчёта нет» · «Не отправлен» · «На проверке» · «Возвращён» · «Принят» (с оценкой) |
| Отправлен | время отправки; пометка «отправлен позже», если отправлен после отчётного дня (уже есть в R1) |
| Проверяющий | имя или «Без проверяющего» |
| Действие | «Открыть» — карточка отчёта по существующим правам ADR-0010 |

Сверху: дата (по умолчанию сегодня в часовом поясе руководителя), фильтры «подразделение» и «статус», счётчики по
статусам. Страницы по 50 строк.

## Решения владельца (приняты 24.11.2026 по рекомендациям)

| № | Вопрос | Принято | Отклонённая альтернатива |
|---|---|---|---|
| Т1 | Кого показывать | Переключатель: по умолчанию **«Моя команда»** (сотрудники, для которых я ближайший руководитель по оргсхеме, как в ADR-0010 D2), рядом «Вся компания» | только вся компания (как очередь D4) |
| Т2 | Черновик руководителю | Статус «Не отправлен» **без содержимого**: черновик остаётся личным (ADR-0009) | не отличать черновик от «Отчёта нет» |
| Т3 | «Не сдан» и «просрочен» | **Не вводить сейчас.** Без графика, выходных и отпусков пишем нейтрально «Отчёта нет» (ADR-0009 D7). График — отдельный этап R5 | ввести «Не сдан» для будних дней без исключений |
| Т4 | Кто попадает в список | Действующие участники компании на выбранную дату; отозванные, удалённые и заблокированные — нет | все, у кого был отчёт за день |
| Т5 | Включение | За тем же выключателем `dailyreports_enabled`, отдельный выключатель не нужен | отдельный выключатель R4 |

## Границы

- **Только чтение.** Без новых таблиц и миграций, без повышения схемы. Новые языковые строки и шаблон.
  Запрос использует существующие индексы `company_user_day_uix` и `company_status_day_ix`.
- Компания и членство проверяются в SQL (`membership_access_service::canonical_sql`), как в очередях R2. Нельзя
  выбрать все строки, а потом фильтровать в PHP.
- Содержимое отчёта в таблице не показывается. Карточка открывается только по существующим правам ADR-0010.
- Не входит: напоминания, график отчётности, MAX и Telegram, ИИ-агенты (`principal_type`), экспорт.

## Проверки

- PHPUnit: компании A и B, отозванный участник, не руководитель получает отказ, черновик без содержимого,
  правило «Моя команда» по ADR-0010 D2, граница дня в часовом поясе.
- BROWSER: очередь при 375 и 1440 px, фильтры, пустое состояние; UI-стенд #162 до пуша.
- Маршрут FULL (PHP и шаблон), на обеих СУБД.
