# Прототип «Отчёты за день» — как открыть и что смотреть

**ПРОТОТИП.** Статический HTML с синтетическими данными (ООО «Пример», Анна Смирнова, Олег Петров).
Нет подключения к Moodle, BMS24 или production. Кнопки только переключают экраны и показывают плашку
«Прототип: … Данные не сохраняются».

Стили берутся из существующей дизайн-системы репозитория: `local/kbacompany/bms_ui/tokens.css`,
`owned_shell.css`, `ui_kit.css`. Классы — `bms24-ui-*` и owned shell. Новых цветов нет.
Небольшой встроенный CSS отвечает только за компоновку прототипа.

## Как открыть

Вариант 1 — двойной клик по файлу в checkout репозитория (ветка `docs/daily-employee-reports`):

- настольный вид: `docs/daily-reports/prototype/index.html`;
- мобильный вид (пять экранов по 390 px рядом): `docs/daily-reports/prototype/mobile.html`.

Вариант 2 — локальный сервер из корня репозитория:

```bash
python -m http.server 8765 --bind 127.0.0.1
```

Затем откройте `http://localhost:8765/docs/daily-reports/prototype/index.html`.
Для телефона: в браузере компьютера включите режим устройства (F12 → значок телефона) или откройте `mobile.html`.

Вверху страницы фиолетовая пунктирная панель «ПРОТОТИП» с двумя списками: **Экран** и **Состояние**.
Состояние также видно в адресе после `#`, например `index.html#review/pending`.

## Сценарий просмотра (5 минут)

1. `#my/none` — отчёта за 13.11 ещё нет, справа «Данные дня из BMS24» (только чтение). «Начать отчёт».
2. `#my/draft` — черновик: поля сотрудника, связанные задачи, вложения. «Отправить руководителю».
3. `#my/submitted` — отправлен, текст заморожен, видна версия 1.
4. Экран «Г. Проверка отчёта» (`#review/pending`) — руководитель: текст, задачи на момент отправки,
   оценка (положительная / отрицательная / без оценки), отдельная форма возврата с обязательной причиной.
   `#review/returnform` — ошибка возврата без причины.
5. `#my/returned` — сотрудник видит причину возврата, «Доработать» создаёт новую версию.
6. `#my/accepted` — принят с положительной оценкой, версия 2; в истории версия 1 с причиной возврата.
7. `#history/list` — история по датам; «Отправлен позже» отличается от «На проверке»; выходные не «не сданы».
8. `#queue/review`, `#queue/returned`, `#queue/accepted` — очередь руководителя с фильтрами.
9. `#queue/matrix` — «сотрудники × дни»; на телефоне превращается в карточки.
10. `#my/conflict` и `#my/error` — конфликт версии черновика и ошибка сохранения без потери текста.
11. `#noaccess/denied` — нет доступа: доступ к задачам не открывает личный отчёт.

## Что проверено (15.11.2026)

- Открыт в браузере на 1440 × 900 и 375 × 812. Все 16 состояний на 375 px — без горизонтальной прокрутки страницы
  (`scrollWidth = innerWidth`). Широкие таблицы на телефоне заменяются карточками.
- Клик «Доработать» переключает на черновик и показывает плашку прототипа.
- Статусы различаются текстом и значком: ○ Отчёта нет, ✎ Черновик, ⏳ На проверке, ↩ Возвращён, ✓ Принят,
  ⏰ Отправлен позже; оценки 👍 / 👎 / —.

## Не проверено

- Не проверен скринридером и не проверена контрастность всех состояний инструментом.
- Это не Moodle-рендеринг: в продукте разметка будет из Mustache-шаблонов `bms24_*` и сервисов, а не из этого JS.
- Legacy-оболочка `theme_kba` не воспроизведена: прототип показывает owned shell.
