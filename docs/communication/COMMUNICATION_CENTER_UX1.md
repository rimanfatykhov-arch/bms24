# UX-1: Коммуникационный центр

Решение владельца 18.11.2026 заменяет более ранние предложения о подавлении нулевых напоминаний и массовой отметке. Проект: #122, `docs/communication/ux/COMMUNICATION_CENTER_UX.md` в его ветке.

## Состав и зависимость

Основа: E2 #123 `aebe1856bd1c1bd09cb4aa2782bcb5aa8d3b9ea0`, содержащий main/R1/R2 `2739a5d3986b71893979f2f3178b2063a7fa4780`. Отдельная ветка UX-1, чужие рабочие деревья не меняются. Base PR — main, поскольку действующие обязательные CI срабатывают только на main; E2 пока открытая явная зависимость. Это не разрешение merge #123 или этого PR.

## Представление

Три раздела: Разговоры / Обсуждения / Уведомления. В первых двух — Все / Непрочитанные / @; активный раздел и отбор видны. Уведомления — самостоятельная полноширинная область без списка переписок, composer или приветствия. Прочитано — состояние, существующая кнопка отметки остаётся для непрочитанных. Подробности/участники открываются выдвижной панелью, Escape закрывает с возвратом фокуса. Нативный details остаётся доступным без JavaScript. Длинные заголовки имеют title, меню переносится между словами. CSS scoped к центру, кроме одного адресного исправления owned navlabel.

## Изменения поведения — отдельно

1. По умолчанию messages / filter=all («Разговоры · Все»). Старые inbox/unread/mentions URL переводятся в видимый отбор, без скрытого режима. Выбранные обсуждения продолжают использовать прежние проверки доступа.
2. shell_counters incoming и dashboard fallback workspace_counters считают только unread_threads; уведомления — отдельный счётчик с единицей. Одна и та же формула на разных страницах.
3. Встречи не отдельный раздел. Старый tab=meetings переводится в discussions, thread сохраняется; сущности/данные/прямые ссылки не удаляются.

## Что не меняется

Генерация уведомлений, нулевой digest, cron, POST actions/поля, sesskey, права, схема, версии миграций, Core, KBA Theme. Массовой кнопки/нового endpoint нет. R0/R1/R2 и ссылки уведомлений отчётов, task-open, сообщения/вложения, task discussion и E2 сохранены. MAX/Telegram/ИИ не подключаются.

## Проверки и статусы

Локальные проверки — отдельное доказательство от Moodle runtime. Новая PHPUnit suite `communication_center_ux_test` проверяет default, раздельные counters и отсутствие read side effect при открытии уведомлений с лишним thread. BROWSER `communication_ux.py`: обе оболочки ×320/375/390/768/1440, реальный DOM/HTTP/цвета, focus/Escape/overflow; существующие communication_center (8) и plan_discussion (5) остаются обязательны. Fail-closed контракт имеет мутационные отрицательные проверки, в том числе empty, HTTP500/redirect, плохой контраст и browser errors. Окончательные CI/скриншоты/точный SHA фиксируются в PR после выполнения; не считать план PASS.

Цепочка source preservation продлена точными before/after LF hashes в `docs/reconcile/communication-center-ux1-source-preservation.json`: предыдущие строки не переписаны, новые ключи не переопределяют старые, CSS только добавлен. Никаких blanket path exemptions.

## Показ и откат

Codex — единственный оператор общего dev/production. Для dev потребуется совместимое исправление Corporate #125 и отдельная проверка нового состава с #124. UX-1 сам не добавляет миграций; полный кандидат с R1/R2 требует проверенного восстановления данных, code-only downgrade на старый R0 недопустим. Только если обе стороны отката уже на совместимой R1/R2 схеме допустим прежний совместимый код + purge. Отчёты/сообщения/файлы не удаляются. Production — после просмотра и отдельного разрешения на точный пакет, merge — отдельно.

Статусы сейчас: реализовано — локальная ветка; проверено — только перечисленные выполненные проверки в PR; показано — NOT RUN; опубликовано — NOT RUN.
