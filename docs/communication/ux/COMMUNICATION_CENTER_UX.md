## 3. Рекомендуемый вариант интерфейса (один)

**Три раздела вверху центра, список слева, разговор справа, подробности — по запросу.**

- **Верхняя полоса центра:** заголовок, переключатель разделов **Разговоры** (личные и группы) · **Обсуждения**
  (задачи, боевые планы, встречи и другие объекты) · **Уведомления**, кнопка «Новый разговор».
- **Список (разделы «Разговоры»/«Обсуждения»):** поиск и три лёгких отбора — Все · Непрочитанные · @ Упоминания.
  Строка: аватар, название (обрезка с многоточием, полное — в подсказке), тип объекта, последнее сообщение
  с автором, время, число непрочитанных **сообщений**, знак «@».
- **Разговор:** заголовок с названием и типом объекта, состоянием и сроком; «Открыть задачу/план/встречу»;
  «Подробнее»/«Участники» открывают **выдвижную панель** (закрывается крестиком, фоном, Esc). Постоянной пустой
  колонки нет.
- **Лента:** даты-разделители; «Новые сообщения» и автопереход к первому непрочитанному; свои сообщения справа;
  ответ с цитатой; упоминание выделено; файлы списком с обрезкой длинного имени и размером; «изменено»;
  «Ответить / Изменить / Удалить» (удаление — подтверждение внутри сообщения).
- **События объекта** (создана, начата, возвращена…) — компактная строка по центру без «пузыря» и без кнопок,
  визуально отличная от сообщений. «Открыл задачу» в ленту не попадает — только в «Историю» (#110).
- **Поле ввода:** цитата при ответе, выбранные файлы с удалением, подсказка про упоминание, «Отправить»
  (Ctrl+Enter); состояния «Отправляется…» и ошибка с сохранением текста и файлов и «Повторить отправку».
- **Уведомления** — отдельный полноширинный экран, без области разговора и без «Выберите переписку».

Почему так: разделы отвечают на вопрос «где это», отборы — «что из этого показать»; пользователь всегда видит,
какой раздел и отбор действуют. Объектные обсуждения отделены от личных, поэтому сразу видно, к чему относится
разговор. Это согласуется с Битрикс24 (чаты задач в общем списке) и Odoo (обсуждение в записи) без копирования их
внешнего вида и без изменения прав BMS24.

**«Встречи»:** не отдельный раздел. Обсуждение встречи — элемент раздела «Обсуждения» (тип «Встреча», «Открыть
встречу»), сами встречи — в Календаре.

**Счётчики (предложение, требует решения):** меню — число **разговоров и обсуждений с непрочитанным**; раздел
«Разговоры»/«Обсуждения» — число таких разговоров; строка списка — число непрочитанных **сообщений**;
«Уведомления» — число непрочитанных уведомлений, только на своей вкладке. У каждого badge подсказка с единицей.

## 4. Сценарии в прототипе

| Сценарий | Где |
|---|---|
| Личный диалог и группа, поиск человека или существующего разговора, «Уже есть диалог» | Г |
| Выбор разговора, переход к первому непрочитанному | А |
| Сообщения: даты, автор, ответ, упоминание, несколько файлов, длинное имя файла | А (`?reply=m3`) |
| Изменение и удаление своего сообщения | А, Б |
| Отправка, ожидание, ошибка с сохранением текста | А, состояние «Ошибка отправки» |
| Участники и действия группы (исключить, выйти, передача владения — пояснение) | А → «Отдел продаж» → «Участники» |
| Обсуждение задачи: заголовок, «Открыть задачу», события отдельно, тот же разговор, что в карточке | Б |
| Ограничение доступа / отзыв прав | Б, состояние «Нет доступа» |
| Уведомления: тип, текст, время, ссылка, состояние, действие, группировка по дням, свёртка однотипных | В (`?expand=1`) |
| Телефон: список → разговор → подробности | Д |

## 5. Уведомления

- Строка: точка «не прочитано», тип (Упоминание, Задача, План дня, Решение по плану), текст, ссылка на объект,
  время; **действие** «Отметить прочитанным» — кнопка; **состояние** «✓ Прочитано» — текст без кнопки.
- Группы: «Сегодня», «Вчера», «Предыдущие дни». Однотипные напоминания с нулями свёрнуты в одну строку
  «Показать».
- Отдельные предложения (каждое — своё решение): «Отметить все прочитанными» (новое действие сервера);
  не создавать «Напоминание о плане дня», если все показатели равны нулю (изменение правила генерации, cron не
  трогается без решения); ссылка «Настройки уведомлений» — на существующую `calendar_notifications.php`.
  Уведомления не удаляются.

## 6. Телефон

Колонки не сжимаются: список → разговор → подробности. «Назад» возвращает к списку с тем же разделом, отбором и
позицией прокрутки. Поле ввода закреплено внизу разговора (видно над экранной клавиатурой). Проверено в
браузере с эмуляцией устройства: 320, 375, 390, 768 и 1440 px — горизонтальной прокрутки нет, у всех элементов
управления есть подпись [Б].

## 7. Будущие каналы и ИИ (только вариант на будущее)

Флажок «Будущее» показывает: метку канала у сообщения («из Telegram»), канал участника и ИИ-участника с
ответственным сотрудником в «Участниках», пометку «ИИ» у автора; состояние доставки — только если канал его
подтверждает. В текущем продукте каналы и ИИ **не подключены**; реализация — этапы E3–E5 плана #111.

## 8. Этапы реализации (небольшие, каждый — отдельный PR)

### A. Представление без изменения поведения
- **UX-1. Порядок в центре (рекомендуемый первый этап).** Перенос слов в меню без разрыва; верхняя полоса центра
  с тремя разделами вместо 7 чипов, отборы — лёгкие чипы; уведомления — отдельный полноширинный экран без
  приветствия; приветствие читаемым цветом и только когда разговор не выбран; кнопка «Отметить прочитанным» и
  состояние «Прочитано»; постоянная правая колонка заменена выдвижной панелью; обрезка длинных названий.
  Файлы: `bms_ui/owned_shell.css` (одна строка), `styles.css` (scoped `.bms-comm2`), `communication_center_ui_service.php`,
  строки RU/EN. Права, запросы и POST-поля не меняются.
- **UX-2. Лента.** Автопереход к первому непрочитанному, разделитель «Новые сообщения», единый вид событий
  объекта, цитата и файлы как в прототипе.
- **UX-3. Уведомления.** Группировка по дням и свёртка однотипных напоминаний (только отображение).
- **UX-4. Телефон.** Последовательность экранов, сохранение раздела/отбора/позиции, закреплённое поле ввода.

### B. Изменения поведения — отдельное согласование
- Раздел по умолчанию при открытии центра (сейчас `inbox` — только непрочитанное).
- Смысл badge в меню (сейчас разговоры + уведомления).
- «Отметить все прочитанными».
- Не создавать нулевые «Напоминания о плане дня».
- Подсказка имён при вводе «@» (сервер уже распознаёт `@Полное Имя`).

### C. Будущие интеграции
Каналы MAX/Telegram, ИИ-участники, состояния доставки — этапы E3–E5 (#111), не входят в этот UX-проект.

## 9. Критерии приёмки UX-1

1. В меню «Коммуникационный центр» переносится между словами при любой ширине меню.
2. При открытии центра видно, какой раздел и отбор действуют; пустой список объясняет причину и предлагает действие.
3. Во вкладке «Уведомления» нет области разговора и подсказки «Выберите переписку».
4. Контраст текста ≥ 4,5:1 (подсказка, бейджи, чипы); видимый фокус на всех элементах; Esc закрывает панель.
5. «Отметить прочитанным» — кнопка, «Прочитано» — состояние; у непрочитанных — отметка.
6. Нет постоянной пустой колонки; подробности и участники открываются кнопкой с подписью.
7. 320/375/390/768/1440 px: без горизонтальной прокрутки, длинные названия обрезаются с подсказкой.
8. Не изменились: права и видимость обсуждений, POST-поля и sesskey, правила уведомлений, существующие
   браузерные проверки CI (64) — PASS; legacy-режим оболочки работает.
9. Показ владельцу на dev: те же экраны, что в прототипе, на реальных данных тестовой компании.
