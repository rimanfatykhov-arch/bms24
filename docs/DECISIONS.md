## Где что искать

- `AGENTS.md` — обязательный краткий контекст Codex и правила безопасности.
- `docs/22_BMS24_PRODUCT_VISION_FOUR_STREAMS.md` — четыре продуктовых направления и границы архитектуры.
- `docs/adr/ADR-*.md` — отдельные архитектурные решения с историей и supersedes.
- `docs/DECISIONS.md` — индекс принятых решений.
- GitHub Issues — формализованные задачи с приоритетом, критериями и связью с ADR.
- GitHub Pull Requests — изменения кода и документации, ревью, действия CI.
- GitHub Releases / manifest / SHA256 / acceptance record — **только реально собранные и проверенные** релизы.
- Deployment evidence — фактические версии и состояние сред, а не описание ZIP в переписке.

## Как добавлять решение

1. В чате обсуждаем проблемы, варианты, риски и последствия.
2. Владелец подтверждает конкретную формулировку.
3. В PR добавляется ADR с ID, датой, состоянием, обоснованием, вариантами,
   рисками, обратимостью и критериями контроля.
4. После ревью и merge в `main` обновляется этот индекс. Codex читает
   архитектурные ограничения до новых задач.
5. Если решение меняется — новый ADR со ссылкой `Supersedes ADR-...`,
   прежний сохраняется в истории.

Чаты и внешние документы могут содержать дополнительные материалы, но
не должны противоречить утверждённому ADR без нового решения владельца.
