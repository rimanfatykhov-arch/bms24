# Коммуникационный центр: фиксированная рамка, как у мессенджера

Задача владельца от 2026-11-24: страница Коммуникационного центра не должна прокручиваться целиком, как мессенджер
Битрикс24 (`/online/`). Это исходный код-кандидат. Приёмка, установка на TEST и production этим документом не выполняются.

## Как устроено у Битрикс24 (снято с открытой страницы, только чтение)

- Корень — сетка высотой в окно (`min-height: calc(100dvh - …)`, строки `auto / minmax(0,1fr) / auto`): прокрутке
  страницы не из чего взяться.
- Рабочая область — `flex: 1; overflow: hidden; position: relative`, мессенджер внутри — `position: absolute` на 100%.
- Каждая колонка — flex-колонка с `min-height: 0; overflow: hidden`. Шапка чата и поле ввода — `flex-shrink: 0`.
  Прокручиваются только список чатов и лента сообщений (`overflow-y: auto; overscroll-behavior: contain`).
- На странице мессенджера нет подвала (`.no-footer`).

## Что было у нас

Внутри блок уже устроен так же: список `overflow-y: auto`, разговор — flex-колонка, поле ввода `flex: 0 0 auto`.
Но высота самого блока угадывалась: `min(780px, calc(100vh - 210px))` и `min-height: 540px`, на телефоне
`calc(100vh - 230px)` и `min-height: 520px`. Шапка оболочки, заголовок и подвал Moodle в эти 210/230 px не
укладывались, и страница прокручивалась поверх внутренней прокрутки.

## Решение

- Новый AMD-модуль `local_kbacompany/communication_frame` (`amd/src` = `amd/build`, как у остальных модулей).
  Он измеряет реальную страницу: контейнер прокрутки страницы (документ или ограниченный окном `#page` Moodle Boost),
  высоту над блоком и под ним. Затем задаёт блоку высоту так, чтобы страница не прокручивалась. Пересчёт идёт при
  изменении размера окна, `visualViewport` (клавиатура телефона) и содержимого над блоком.
- Модуль следит (`ResizeObserver`) за самим блоком и за всеми его предками до `<body>`, а не только за блоком.
  Причина: прогон BROWSER на Percona (run 45826995637, owned, 320 px, открытый разговор). Верхняя панель owned-оболочки
  получает окончательную высоту только после `bms24_nav_drawer`: он показывает кнопку меню. Модули AMD грузятся
  асинхронно, поэтому рамка иногда измеряла страницу раньше. Над блоком было выше, места меньше 360 px, и рамка
  снималась. Потом панель становилась ниже, но размер самого блока не менялся, и пересчёта не было. В итоге страница
  прокручивалась на 265 px, а поле ввода оказывалось на 1130 px из 900.
- Пока рамка включена, на этой странице не рисуется подвал Moodle (`#page-footer`), как на странице мессенджера.
  Класс `bms24-comm-framed-page` ставится и снимается только скриптом.
- Запасной вариант. Если доступная высота меньше 360 px (короткое окно, телефон боком) или JavaScript выключен,
  остаются прежняя высота из CSS, подвал и обычная прокрутка страницы.
- Работает одинаково в owned и legacy оболочке: высоты шапок не зашиты.
- Только отображение. PHP — одна строка подключения модуля в `communication_center.php`. Схема, версия, права,
  отправка, уведомления и данные не меняются. Разделы «Уведомления» и «Лента дня» — обычные списки, их не трогаем.

## Проверки

- BROWSER `communication_ux.py` → `communication_ux3_fixed_frame`: обе оболочки, ширины 320/375/390/768/1440, высота
  окна 900. Проверяется список и открытый разговор: страница не прокручивается, блок кончается в окне, список и лента —
  контейнеры прокрутки, поле ввода на экране. Контракт проверен мутационными тестами.
- Там же состояние `frame_shift` повторяет сбой Percona детерминированно. Над страницей ставится блок 400 px, рамка
  пересчитывается (событие `resize`), затем блок убирается без событий окна. Рамка должна вернуться сама: страница не
  прокручивается, поле ввода на экране. Замеры берутся после трёх кадров отрисовки, когда запланированный пересчёт уже
  прошёл. На макете со старым модулем `frame_shift` падает на всех ширинах (поле ввода на 1130 px), с новым — проходит.
- Локально: макет обеих оболочек с настоящими CSS и модулем на 1440×900, 375×812 и 375×480 (запасной вариант).

## Сценарий просмотра

1. Открыть «Коммуникации» → разговор на 1440 px. Страница не прокручивается. Список и сообщения листаются
   отдельно, поле ввода внизу.
2. То же на телефоне 375 px: открыть разговор, полистать сообщения, начать ввод — поле остаётся видно.
3. Уменьшить окно по высоте (или повернуть телефон): при нехватке места страница прокручивается, как раньше.
