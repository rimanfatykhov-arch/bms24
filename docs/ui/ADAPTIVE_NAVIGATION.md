Статус: реализация в отдельном PR от `main` `fbf36ed` (18.11.2026), `main` `36cc7dd` слит в ветку 23.11.2026.
Не принята, не опубликована.

## 1. Проблема и причины в коде (до исправления)

Жалоба владельца: меню «Открыть навигацию BMS24» в узкой боковой панели браузера прокручивается
по горизонтали и раскрывается громоздко. Подпись «Открыть навигацию BMS24» есть только в owned
shell (`bms24_app_shell.mustache`, `topbar.mobilemenulabel`), поэтому причины искались там.
Снимки «до» получены на настоящем Moodle в BROWSER CI (`adaptive_nav.py`, первый коммит PR без
изменений продукта), см. раздел 6.

| # | Причина | Где |
|---|---------|-----|
| 1 | **Главная.** Селектор `.bms24-app .bms24-mobilemenu nav {position:absolute; top:100%; width:min(90vw,320px); padding:12px; max-height:70vh; overflow:auto}` задуман для внешнего списка, но совпадает и с вложенным `<nav>` каждой группы (partial `bms24_nav_groups`). Список пунктов раскрытой группы становится абсолютным блоком под внешним списком, вне его видимой области: группа выглядит раскрытой, пунктов не видно. Блоки шириной 320 px внутри контейнера 320 px с отступом 12 px дают горизонтальную прокрутку. Тот же `.bms24-mobilemenu summary` оформлял рамкой и заголовки групп. | `bms_ui/owned_shell.css`, правило `@media(max-width:860px)` (строка 72) |
| 1a | Сам выпадающий блок привязан к кнопке, а не к окну: высота `70vh` не учитывает реальную высоту окна, поворот и safe-area. | там же |
| 2 | Компактный режим боковой панели (`bms-shell-nav-compact`, флаг в `localStorage`) — правила не ограничены `.bms24-sidebar`, поэтому действуют и внутри мобильного меню: скрыты подписи и счётчики (`display:none!important`), заголовки групп получают `font-size:0` и сжимаются до 10 px. Группы выглядят как пустые полосы, раскрытая группа показывает только иконки, закрытую нечем открыть. Флаг из desktop продолжает действовать в узком окне, где боковой панели нет; там же `display:flex!important` вытаскивает полосу 76 px над страницей. | `styles.css` 5224–5250, `amd/src/bms_shell_navigation.js` |
| 3 | Подписи `overflow-wrap:anywhere` разрешают разрыв в любом месте слова; в узкой колонке со счётчиком слова рвутся посередине. | `owned_shell.css` `.bms24-navlabel` |
| 4 | Пункты 40 px, заголовки групп ≈ 37 px — меньше 44 × 44. | `owned_shell.css` |
| 5 | Нет модального поведения: фон прокручивается, Escape/нажатие на фон не закрывают, фокус не удерживается, нет `aria-controls`; закрыть можно только повторным нажатием на summary, которое уезжает вместе с прокруткой. | шаблон и отсутствие JS |

## 2. Решение

* **Широкое окно (≥ 861 px)** — прежняя боковая навигация (258 px, ≤ 1100 px — 220 px) без изменений
  поведения; компактный режим работает как раньше.
* **Узкое окно (≤ 860 px)** — в верхней панели кнопка `<button>` «Меню» с иконкой (`aria-expanded`,
  `aria-controls="bms24-drawer"`). По нажатию — выдвижная панель слева поверх страницы:
  * `position:fixed; top:0; bottom:0; left:0`, высота `100dvh` (запасной вариант `100vh`);
  * ширина `min(360px, 100vw − 48px)`: справа остаётся полоса затемнения для закрытия нажатием;
    при ширине окна ≤ 359 px — на всю ширину;
  * отступы учитывают `env(safe-area-inset-*)`;
  * шапка панели: бренд и кнопка закрытия 44 × 44 («Закрыть меню»); ниже — вертикально
    прокручиваемый список групп, `overscroll-behavior:contain`;
  * фон затемнён (`#0B2B41` 55 %), нажатие на фон закрывает панель;
  * `role="dialog"`, `aria-modal="true"`, имя — «Навигация BMS24». Внутри — обычная навигация сайта:
    `<nav>` и ссылки, без `role="menu"`.
* **Breakpoint 860/861 px** выбран по содержимому, а не по устройству: при 861 px и боковой панели
  220 px на страницу остаётся 641 px (589 px контента после отступов). Ниже этого боковая колонка
  отнимает больше трети ширины, а сузить её нельзя без потери подписей; панель поверх страницы
  отдаёт содержимому всю ширину. Тот же порог уже используется короткими подписями меню (ADR-0009,
  `dailyreports_nav_short`) и проверками `daily_reports_nav`, поэтому он не меняется. Что при 861 px
  страница действительно помещается без горизонтальной прокрутки, а при 860 px работает панель,
  проверяет BROWSER (обе стороны порога).

### Поведение

| Действие | Результат |
|---|---|
| Открытие | Сохраняется позиция прокрутки; `html` получает `overflow:hidden` (при видимой полосе прокрутки — `scrollbar-gutter:stable`, чтобы страница не сдвигалась); основное содержимое `inert`; фокус — на текущий пункт (или на кнопку закрытия); группа текущей страницы раскрыта. |
| Tab / Shift+Tab | Циклически внутри панели; скрытое меню (закрытое или на desktop) не рендерится и недоступно фокусу. |
| Escape, крестик, нажатие на фон | Закрытие; снимаются блокировка прокрутки и `inert`, восстанавливается прежняя прокрутка, фокус возвращается на кнопку «Меню». Введённые данные страницы не затрагиваются. |
| Переход по ссылке | Обычная навигация браузера. |
| Ширина стала ≥ 861 px | Панель закрывается без анимации, блокировка и `inert` снимаются, затемнение не остаётся; если фокус был в панели, он переходит на текущий пункт боковой панели. |
| Ширина стала ≤ 860 px | Компактный флаг боковой панели не применяется (это настройка desktop), меню закрыто. |
| Без JavaScript | Кнопка «Меню» не показывается (`hidden`), работает `<details>`: summary 44 px, панель под верхней панелью шириной `min(360px, 100vw − 16px)` с вертикальной прокруткой. Escape и блокировка фона без JS недоступны. |

### Подписи, группы, счётчики

* `overflow-wrap:break-word` — перенос только между словами; слово рвётся, лишь если само не
  помещается в строку. Подпись — `flex:1 1 auto; min-width:0`, счётчик — `flex:none`, не сжимается.
* Пункты и заголовки групп — не ниже 44 px; заголовки групп — 12 px, верхний регистр сохранён.
* Текущий пункт — прежний зелёный фон с левой полосой и жирный шрифт.
* Набор ссылок, права, маршруты и счётчики не меняются: и боковая панель, и меню строятся одним
  partial `bms24_nav_groups` из одной модели `bms_ui_service`/`bms_main_tool_service`.

## 3. Границы

* Только owned shell `local_kbacompany`: шаблон `bms24_app_shell`, `bms_ui/owned_shell.css`,
  новый AMD `bms24_nav_drawer` (подключается в `bms24_shell_service::prepare_page`, т. е. только в owned),
  правка `bms_shell_navigation` (компактный флаг не действует в узком owned-окне).
* Legacy (`theme_kba/bms/app_shell`, KBA Theme) не меняется; JS-правка ограничена `owned`.
* Moodle Core, KBA Theme, БД, схема, ACL, бизнес-логика и версии плагина не меняются.
* Новые строки RU/EN: `bms24_menu_button`, `bms24_menu_close` — отдельным блоком в конце языковых
  файлов, с записью в source-preservation guard.

## 4. Зависимости

* UX-1 Коммуникационного центра (PR #127) попал в `main` через интеграцию `b9b55f9` и #145/#146/#148; сам
  PR #127 на 23.11.2026 открыт. Он меняет конец `owned_shell.css` (правило для подписи пункта
  «Коммуникационный центр») и `bms24_nav_groups.mustache` (`title` у счётчика). Этот PR не трогает
  ни эти строки, ни partial: правила добавлены в середину `owned_shell.css`, после блока навигации.
  Правило UX-1 (`overflow-wrap:normal` для пункта Центра) совместимо: общий перенос теперь тоже
  только между словами.
* `main` `36cc7dd` слит в ветку (коммит `454112c`, 23.11.2026). Конфликты были только в дописанных
  в конец блоках (языковые файлы, guard и тесты, `contract.py`, `CI_TIERS.md`). Блок навигации теперь
  идёт после блока #145; before-хэши `docs/reconcile/adaptive-navigation-source-preservation.json` равны
  after-хэшам #145. BROWSER: 85 + 16 = 101 обязательная проверка.
* Следующий PR, который допишет блок в конец языковых файлов и guard, перебазируется так же механически.
* От релизного кандидата R1/R2 (#124) не зависит; пакет, открытый владельцу для просмотра отчётов, не заменяет.
