# ADR-0011. Сводка ежедневных отчётов за месяц и график сдачи (по образцу «Рабочих отчётов» Bitrix24)

- Статус: **блок 1 — ПРЕДЛОЖЕНО** к приёмке владельцем (этот PR). **Блок 2 — ОТКРЫТ**: нужны решения владельца, код не пишется.
- Опирается на: ADR-0009 «Ежедневные отчёты сотрудников» и ADR-0010 «Проверяющий по оргсхеме…» (PR #153, в main). Права чтения
  ADR-0010 D4 не расширяются.

## Контекст

В Bitrix24 компании есть страница «Рабочие отчёты» (`/timeman/work_report.php`). Её разобрали 24.11.2026, только
чтение, без изменения настроек. Отчётов там нет: у всех сотрудников 0%, переносить данные нечего. Есть такие
возможности:

1. Сводная таблица за месяц: сотрудники по отделам, колонки — дни месяца, переключение месяца.
2. Статистика по сотруднику: «Процент оценённых отчётов», «Процент положительных оценок».
3. Фильтры «Показывать всех сотрудников» / «Только мои подчинённые» и выбор отдела.
4. «Настройка отчёта» для отдела или сотрудника: период «День / Неделя / Месяц / Отчёт не требуется / наследовать
   настройки отдела» и время сдачи (например 18:00).
5. Связь с учётом рабочего времени: отчёт сдаётся при закрытии рабочего дня.

Пункты 1–3 BMS24 не умеет, пункт 4 тоже, пункт 5 — отдельный модуль учёта времени, в отчёты не входит.

## Решение, блок 1 — сводка за месяц (этот PR)

### S1. Кто видит

Вкладка «Сводка за месяц» есть у читателей всех отчётов компании по ADR-0010 D4: администратор компании и
руководитель. Для остальных вкладки нет, прямой запрос даёт `dailyreports_notavailable`. Вкладка работает только
при включённом `dailyreports_enabled`.

### S2. Что показано

- Таблица «подразделение → сотрудник → день месяца». Подразделения идут в порядке оргсхемы (sortorder, имя).
  Сотрудник показан в каждом подразделении, где у него действующее назначение. Сотрудники без подразделения собраны в
  группу «Не размещены в оргсхеме».
- Состояние ячейки берётся из сохранённых данных: «Нет отчёта», «На проверке», «Возвращён», «Принят» с оценкой
  последнего решения по текущей версии (положительная, отрицательная или без оценки). Значок всегда идёт вместе с
  текстом (для экранного диктора) и не обозначается одним цветом.
- **Черновики не раскрываются.** Отчёт, который ни разу не отправлялся, показан как «Нет отчёта». Отчёт на
  доработке после возврата показан как «Возвращён».
- Ячейка с отчётом ведёт в карточку отчёта. Карточка для читателя D4 открывается только для чтения, решение
  по-прежнему принимает назначенный проверяющий.
- Две колонки, как в Bitrix24:
  - **Оценено отчётов** — принятые с положительной или отрицательной оценкой, делённые на все отправленные за месяц;
  - **Положительных оценок** — положительные, делённые на оценённые.

  Принятие «без оценки» считается отправленным, но не оценённым. Если делить не на что, показан прочерк.

### S3. Фильтры

- Месяц: поле `month` (`YYYY-MM`), кнопки «предыдущий/следующий месяц». Неверное значение заменяется текущим месяцем.
- «Все сотрудники» / «Только мои подчинённые». Подчинённый — сотрудник, в чьей цепочке руководителей ADR-0010 D2
  есть читающий. Сам читающий в этот список не входит.
- Подразделение — только действующее подразделение этой компании. Неизвестное значение означает «все».

### S4. Данные и безопасность

- Схема не меняется, записей нет. Чтение идёт двумя запросами с `companyuuid` в SQL: отчёты месяца с текущей версией
  и последние решения по этим версиям. Пакеты по 500 uuid.
- Оргсхема читается через `daily_report_reviewer_service::graph/chain`, то есть по тем же правилам, что и выбор
  проверяющего.
- Строки RU/EN добавлены отдельным блоком (18 ключей) после блока «Добавлено ранее» (#165). Точные хеши:
  `docs/reconcile/daily-reports-summary-source-preservation.json`.
- Версия плагина не меняется (`2026112301`), потому что шага схемы нет. При выкладке нужно сбросить кеш строк
  (обычная очистка кешей Moodle после обновления кода).

## Блок 2 — график сдачи и напоминание (открыт, нужны решения владельца)

Предлагается настройка «период + время сдачи» для подразделения или сотрудника с наследованием от подразделения
(как в Bitrix24) и напоминание по расписанию. Нужна новая таблица, ограниченная компанией, и отдельный шаг схемы.
До начала работы владелец решает:

1. **Недельный и месячный отчёт** — отдельный отчёт за период (новая сущность периода, `reportday` → период) или
   ежедневные отчёты с недельной/месячной сводкой?
2. **Дни, когда отчёт не требуется**, — пустая ячейка или отметка «не требуется», и считаются ли они в процентах?
3. **Напоминание** — кому (автор; руководитель при просрочке), каким каналом (уведомление BMS24), выключатель сайта.

## Последствия

- Руководители получают обзор месяца без новых прав: читать отчёты компании они уже могли по ADR-0010 D4.
- Карточка, решения, копии, версии и уведомления не меняются.
- Откат: выключатель `dailyreports_enabled` скрывает вкладку вместе со всеми отчётами.
