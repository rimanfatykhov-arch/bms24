# Лента дня → черновик отчёта (первый сценарий)

Задача владельца от 2026-11-23. База: PR #154, коммит `6275795ee24ecbf4f450ad92c1dc827d54e06840`, `local_kbacompany` 2026112301.
Это исходный код-кандидат. Приёмка, установка на TEST и production этим документом не выполняются.

## Решение

- В Центре коммуникаций появляется раздел «Лента дня» (`communication_center.php?tab=dayfeed`). Он показывается, только если
  включены ежедневные отчёты (`dailyreports_enabled`); иначе ссылка на раздел ведёт в «Сообщения».
- Лента показывает сданные результаты собственных задач сотрудника за выбранный день. По умолчанию это сегодня в часовом
  поясе сотрудника (`business_date_service::day()`). Выбор даты в форме ограничен сегодняшним днём; для будущего дня
  кнопка «Добавить» не показывается, а запись в такой день отклоняет хранилище отчётов.
- Каждая запись показывает время, задачу со ссылкой, текст результата, бейдж «Результат сдан» и текущий статус задачи.
- Источник ленты — тот же запрос, что даёт сводку в отчёте (`daily_report_service::context()`). В него входят события `submit`
  журнала задач за этот день: компания проверяется и в журнале, и в задаче, автором события должен быть сам сотрудник,
  дополнительно применяется ACL «мои задачи». Текст результата берётся из `details` события `submit`, а не из текущего
  результата задачи. «Результат сдан» описывает событие; текущий статус показан отдельно и не меняет смысл статуса задачи.
- «Добавить в отчёт» отправляет POST в `daily_report.php` с `sesskey`, компанией, днём и **только id события**. Сервер
  заново читает событие (`daily_report_service::result()` с теми же условиями плюс `l.id`), проверяет доступ к задаче
  (`task_service::readable_projection`), а затем `daily_report_store_service::add_result` (тот же lock, транзакция и
  запись черновика, что у `save_draft`) добавляет в «Сделано» блок `«Задача»: результат` и связывает задачу с черновиком.
- Повтор определяется по id события `submit`, а не по тексту. При добавлении в существующий журнал отчёта
  `local_kbacompany_dreportlog` пишется запись `result_added` с `{"event": id}`. Проверка и запись выполняются под одним
  lock и в одной транзакции. Поэтому два похожих результата (одинаковые название и текст) добавляются оба, а повтор после
  переименования задачи или правки текста не создаёт дубль. Если событие уже добавлено в этот отчёт, кнопка в ленте
  ничего не записывает, а кнопка в открытой форме сохраняет только правки пользователя. Если сотрудник сам удалил блок из
  текста, то же событие повторно не добавляется. Кнопки «Добавить» в форме отправляют всю открытую форму, поэтому
  несохранённый текст не теряется. Ревизия проверяется как при обычном сохранении.
- Отправленный отчёт не меняется: для него кнопки «Добавить» нет, есть пояснение. Отправляет отчёт сам сотрудник
  существующей кнопкой.

## Рамки

- Только результаты задач. Сообщения, MAX/Telegram/ИИ и автозаполнение других полей отчёта не входят.
- Схема БД, версия плагина, capabilities и виды уведомлений не меняются. Новое действие `result_added` пишется в
  существующий журнал `dreportlog` (поле `action`, JSON в `details`). Добавлены 19 языковых строк RU/EN; изменения
  хешей языковых файлов описаны в `day-feed-report-draft-source-preservation.json`.

## Безопасность

- Для чтения и записи требуются текущая компания (`company_context`), автор события, совпадающий с текущим пользователем,
  компания и в журнале, и в задаче, и читаемая задача. Чужое событие, событие другого дня, другая компания и поддельный
  `sesskey` отклоняются без записи.
- Текст результата не принимается от клиента.

## Проверки

- PHPUnit `local/kbacompany/tests/daily_report_feed_service_test.php`: пустой день, только свои результаты дня,
  добавление в заполненный черновик, повтор без дубля, два похожих результата, повтор после переименования задачи, создание черновика, конфликт ревизии, чужие автор, день и
  компания, отправленный отчёт, выключенная функция.
- BROWSER `tools/ci/browser/day_feed.py` с контрактом `day_feed_checks` (owned 1440, legacy 375): день по умолчанию, выбор
  даты, пустой день, добавление, повтор в форме и в ленте, сотрудник компании B, поддельный `sesskey`, отправка, отсутствие
  горизонтальной прокрутки, ошибок браузера и HTTP 5xx.

## Сценарий приёмки на TEST (выполняет Codex)

1. Включить ежедневные отчёты. Сотрудником сдать две задачи с результатами.
2. Открыть Центр коммуникаций → «Лента дня». Должен открыться сегодняшний день с двумя записями: время, задача, результат.
3. Выбрать день без результатов. Должно появиться пустое состояние.
4. Вернуться на сегодня. Сохранить черновик отчёта с текстом в «Сделано», затем нажать «Добавить в отчёт» у первой
   записи. Должен открыться отчёт, в котором результат стоит после прежнего текста.
5. Дописать текст в форме и снова нажать «Добавить» у той же записи. Правка должна сохраниться, а результат не должен
   задублироваться. Повторное нажатие в ленте тоже ничего не меняет.
6. Добавить второй результат и отправить отчёт. В ленте за этот день кнопки «Добавить» больше нет.
7. Сотрудник другой компании не видит этих записей и не может добавить их по прямому запросу.
8. Повторить шаги 2–6 на ширине телефона (375 px): не должно быть горизонтальной прокрутки.
