# BMS Dev AI — протокол интеграционной приёмки на тестовом Moodle

Этот файл является **инструкцией**, не свидетельством проведённого теста.

1. Снимите резервную копию файлов, исходной версии плагина, базы и `moodledata`.
2. Проверьте фактические версии Moodle, PHP и MySQL. Не считайте PHP 8.1
   подтверждённым лишь потому, что код прошёл lint под другой версией.
3. Разверните изолированный тестовый Moodle с копией **обезличенных данных**.
   Запустите upgrade Moodle и убедитесь в отсутствии ошибок и повторных DDL.
4. Выполните unit-тесты Moodle (`vendor/bin/phpunit` при подготовленной
   тестовой конфигурации), интеграционные и UI-сценарии задач, Канбана,
   Боевых планов, недельной координации, прав исполнителя/руководителя.
5. Запустите `php local/kbacompany/cli/rc30_acceptance.php --all --format=json
   --strict > rc30_acceptance.json`; сохраните код завершения.
6. Проверьте нагрузку на индексы и MySQL-запросы в условиях реальной БД.
   Включите тесты изоляции нескольких компаний, пустых/перемешанных записей,
   обратной совместимости ссылок на поручения.
7. Попросите независимого QA приложить результаты тестов, Security — результаты
   проверки разрешений и чувствительных данных.
8. Перед выпуском — проверка обновления со старой версии, проверка плана
   отката и **отдельное решение** ответственного человека.

Результаты этих испытаний в build1873 **не представлены**; ни CI-конфигурация,
ни offline-допуск не делают RC30 принятым.
