# BMOS-A0. Human Approval Contract

**Статус: PROPOSED.**

## 1. Когда нужно подтверждение человека

- Всегда для класса **R3** (изменение чужой работы: статус, срок, описание задачи поста, черновик задачи → каноническая
  задача и т. п.).
- Для **R2**, если `riskpolicy` ревизии определения не разрешила исполнять команду сразу (по умолчанию в A1–A2 —
  подтверждение для всех R2, кроме `task.comment` и собственного отчёта агента, Q-09).
- **R4** не подтверждается — запрещён агенту (A0_03 §4).

## 2. ApprovalRequest

`approvalreq`:

| Поле | Содержание |
|---|---|
| `uuid`, `companyuuid`, `revision` | |
| `requesterprincipaluuid`, `agentrunuuid`, `correlationid` | Кто и в каком запуске просит |
| `command`, `targettype`, `targetuuid`, `targetrevision` | Что будет сделано и над чем |
| `payloaddigest`, `payload` | Точный payload; хранится в домене, без секретов; изменение = новый запрос |
| `summary`, `rationale`, `provenance` | Что предлагается, краткое обоснование, источники (недоверенные помечены) |
| `riskclass`, `impact` | Класс и последствия простыми словами |
| `approverrule` | `post_supervisor` · `task_reviewer` · `capability:<name>` · `named_user` |
| `approveruserid` | Назначенный человек (если правило даёт одного) |
| `status` | `pending` → `approved` → `executed` / `failed`; `rejected`; `expired`; `cancelled`; `superseded` |
| `expiresat` | Обязателен; по умолчанию 72 ч (Q-09) |
| `decidedby`, `decidedat`, `decisionreason` | |
| `executionaudituuid`, `failurecode` | Результат исполнения |

## 3. Правила

1. **Утверждает только человек** с действующим членством и правом по `approverrule`. Принципал не утверждает свой
   запрос; `service_integration` и `ai_agent` не утверждают никакие.
2. **Нет самоутверждения через спонсора по умолчанию** для R3, если спонсор — также поручивший работу и политика
   двух лиц включена (Q-09).
3. **Перепроверка при исполнении.** После `approved` команда исполняется заново через все 14 шагов (A0_03 §2) от
   имени агента с ссылкой на approval. Если ревизия объекта изменилась — `failed: stale_revision`, автоповтора нет,
   агент может создать новый запрос.
4. **Отзыв во время ожидания.** Отзыв принципала, гранта, занятости или kill switch переводит все `pending` в
   `cancelled`.
5. **Идемпотентность.** Один `idempotencykey` команды — один запрос. Повторное утверждение того же запроса —
   возвращает тот же результат.
6. **Конкуренция.** `approve`/`reject` с `expectedrevision`; второе решение — `stale_revision`.
7. **Видимость.** Утверждающий видит payload, источник, обоснование, риск и метку «ИИ». Недоверенный текст
   отображается как цитата, а не как инструкция.
8. **Аудит.** Решение пишет `wpattr` (actor = человек) и outbox `bmos.approval.decided`; исполнение — `wpattr`
   (actor = агент, `approvaluuid` заполнен).

## 4. Приёмка результата и отчётов

- Рабочий элемент агента (`work`) принимает или возвращает человек (`work.accept`/`work.return`).
- Отчёт агента (A2) принимает или возвращает только уполномоченный человек; принятая версия не переписывается.
- Принятие результата не означает внешнюю публикацию, оплату или закрытие процесса (PR #77 §4).
