# CAT-0. Жизненный цикл, версии и мастер подготовки агента

**Статус: PROPOSED.** Ни один шаг не реализован. Этапы BMOS — по A0_10 (PR #183, ревизия 7 (`68b1dd0`), A0 PASS).

## 1. Редакции шаблона

- Редакция шаблона создаётся как `draft`, публикуется (`published`) и после этого **неизменяема**. Исправление —
  новая редакция; прежняя переходит в `superseded`. Редакция с дефектом безопасности — `withdrawn`: новые адаптации
  запрещены, действующие экземпляры получают предупреждение и анализ влияния, но не меняются автоматически.
- Статус зрелости (`CONCEPT`…`DEPRECATED`) — отдельный признак редакции (CATALOG_TEMPLATE_CONTRACT §3).
- Каждая опубликованная редакция имеет `package_digest`. Экземпляр хранит код, редакцию и digest, из которых создан.

## 2. Обновление шаблона и экземпляры

Новая редакция шаблона **не меняет** конфигурации действующих агентов. Для каждого экземпляра со старой редакцией:

1. **Анализ влияния:** какие блоки изменились (ЦКП, Р/Д, инструменты, контекст, гранты, риск, Recognition), какие
   функции, гранты и кейсы затронуты.
2. **Решение человека:** остаться на прежней редакции, перейти на новую или прекратить использование.
3. **Переход** — новая ревизия `AgentDefinition` (и при необходимости черновик новой редакции Role DNA компании).
   Старая ревизия и её запуски сохраняются.
4. **Повторная проверка** затронутых кейсов Recognition и safety-проверок. До их PASS новая ревизия не активируется.
5. **Гранты не расширяются** автоматически: если новая редакция требует новых прав, они выдаются отдельно (шаг 10
   мастера), двумя людьми, где это требует A0_02.

## 3. Мастер подготовки агента (12 шагов)

Выполняет уполномоченный человек компании. После каждого шага сохраняется черновик; можно остановиться. Ни выбор
шаблона, ни копирование, ни утверждение конфигурации **не дают права на исполнение**.

| Шаг | Действие | Что создаётся / проверяется | Права | Этап BMOS |
|---|---|---|---|---|
| 1 | Выбор шаблона каталога | Опубликованная, не `DEPRECATED`/`withdrawn` редакция; минимальный этап ≤ текущего | Нет | CAT-3 (после A1) |
| 2 | Выбор существующего функционального поста | Пост компании; готовность по Role Intelligence (цель, опубликованные функции, Role DNA) | Нет | — |
| 3 | Сопоставление Role DNA с функциями поста | Черновик Role DNA компании из проекта шаблона (`roledna`, провенанс); таблица «Р/Д/КТ ↔ функция/poswork `uuid`+`revision`»; непокрытые функции остаются за человеком | Нет | Требует семантических блоков Role DNA 0.7.1 |
| 4 | Настройка AI Execution Profile | Черновик `AgentDefinition` ревизии 1: профиль модели из реестра `local_kbaai`, системный профиль, `tools` ⊆ `required_tools`, `actions`, `riskpolicy` | Нет | A1 (A1-07, A1-09) |
| 5 | Проверка доступности инструментов | Каждая команда из `tools` существует на текущей версии платформы и разрешена на текущем этапе; иначе `NOT_AVAILABLE`, шаг не закрывается | Нет | A1 |
| 6 | Источники контекста | `contextsources` ⊆ `context_requirements`; поля DTO, период; запрещённые классы данных исключены | Нет | A1 |
| 7 | Recognition и safety checks | Прогон кейсов Recognition Pack и negative safety cases на синтетике; статусы CONFIRMED/GAP/NOT_CHECKED/CRITICAL_RISK; решение человека | Нет | CAT-4 |
| 8 | Утверждение конфигурации | Ревизия `AgentDefinition` утверждается человеком, `configdigest` фиксируется | Нет | A1 |
| 9 | Position Occupancy | `posoccup` в статусе `proposed`; режим `agent`/`hybrid`; `allowedfunctions`; руководитель; два лица для `mode=agent` | Нет (занятость прав не даёт) | A1 |
| 10 | Отдельная выдача грантов | Гранты ⊆ `grant_requirements`, ≤ 90 дней, человеком с правом; `delegated_team` — только с A3 и двумя людьми | Только перечисленные | A1 / A3 |
| 11 | Лимиты и надзор | Бюджеты (без лимита запуск невозможен), спонсор, руководитель, проверяющий, kill switch | Нет | A1 |
| 12 | Допуск к разрешённому пилоту | Все предыдущие шаги закрыты; ворота этапа PASS; решение владельца; только ручной запуск, синтетика, без внешней сети до отдельного разрешения | Запуск в пределах грантов | A3 для пилота AGENT-001 |

Шаги 1–6 в CAT-3 создают только черновики. Шаги 7–12 — CAT-4 и требуют ворот A1–A3.

## 4. Жизненный цикл экземпляра

Экземпляр — это обычные сущности BMOS компании со своими статусами (A0_02, A0_06): принципал `draft → active ⇄
suspended → revoked`, занятость `proposed → approved → active ⇄ suspended → ended/revoked`, гранты
`active/revoked/expired/superseded`, запуски по A0_06. Статусы каталога их не заменяют и на них не влияют.
