# Коммуникационный центр E2: обсуждение боевого плана

Решение владельца Q9 (16.11.2026, «Everyone with access to the plan»), поручение «Yes, start E2».
Ветка `feature/communication-battleplan-discussion` от `main` `9736452` (= опубликованный #120 R0 поверх #114).
План и ADR — PR #111 (этап E2).

## Поведение

- В карточке боевого плана новая вкладка **«Обсуждение»** (между «Проверкой» и «Историей»). У плана одно обсуждение;
  то же обсуждение открывается в Коммуникационном центре (раздел «Обсуждения», ссылка «Открыть план»).
- **Читают** все, кто может открыть план (существующее правило чтения плана `access_sql`): сотрудник плана,
  проверяющий, наблюдатель, руководитель компании, руководитель подразделения по правам BMS. Чтение не делает
  участником: нет отметок прочтения и уведомлений; файлы обсуждения открываются тем же читателям.
- **Пишут** участники плана и руководители с правом изменять план (`discussion_target.can_post`). Первое сообщение
  создаёт обсуждение и добавляет участниками сотрудника, проверяющего, наблюдателя и создателя плана (если у них есть
  доступ). Сообщение из карточки или «Присоединиться к обсуждению» в центре добавляет в участники. Читатель без права
  писать видит обсуждение только для чтения.
- В карточке плана: ответ с цитатой и несколько файлов. Изменить или удалить своё сообщение — в Коммуникационном
  центре (тот же разговор).
- **Сообщение никогда не меняет план**: не утверждает, не возвращает, не меняет состав; решения — только действиями плана.

## Границы

- Схема, `version.php`, миграции, capabilities — без изменений: `battleplan` — значение существующего поля
  `commthread.contextkind`.
- Все запросы в границах `companyuuid`; чужая компания, отсутствие доступа к плану и отозванное членство дают отказ,
  неотличимый от «нет плана».
- Новые файлы: `battle_plan_discussion.php` (POST + sesskey), `classes/local/battle_plan_discussion_service.php`,
  `classes/local/battle_plan_discussion_ui_service.php`. Изменены: `battle_plan_service` (два метода),
  `battle_plan_navigation_service` (вкладка), `battle_plan.php` (вкладка), `communication_service` (вид объекта),
  `communication_object_service` (описание плана), центр (присоединение и «Открыть план»), строки RU/EN.
- Изменение правил видимости (ACL): маршрут **не FAST**, полная приёмка.
- MAX, Telegram и ИИ не входят.

  читатель плана читает без участия и присоединяется сообщением, центр показывает тот же тред и «Открыть план»;
  отказ сотруднику без доступа, чужой компании и после отзыва членства; контракт.
