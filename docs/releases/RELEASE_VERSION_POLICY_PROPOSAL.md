# Политика версионирования релизов BMS24 — предложение

Статус: **предложение**, требует решения владельца. Не меняет существующие гейты.

## Проблема на факте

Версия плагина `2026111601` закреплена в **семи** местах:

| Файл | Что закреплено |
|---|---|
| `tools/dev_ai_gate.py` | «plugin version must be 2026111601» |
| `tools/check_reconcile_1879.py` | регэксп `$plugin->version = 2026111601` в `version.php` |
| `tools/check_workflow_policy.py` | строка `--expected-version 2026111601` в workflow |
| `tools/adr0005_schema_policy.py` | словарь версий плагина и Corporate |
| `tools/acceptance/pr90/daily_reports_upgrade_policy.py` | версия кандидата и совпадение fresh/upgrade |
| `tools/check_pr53_pr56_integration.py` | хронология `upgrade_plugin_savepoint`, последние три `[2026111100, 2026111600, 2026111601]` |
| `.github/workflows/bms24-ci.yml` | имена артефактов и `--expected-version` |

Плюс точные хеши трёх файлов (`lang/ru`, `lang/en`, `styles.css`) в двух местах
(`check_pr53_pr56_integration` и цепочка `test_pr102_source_preservation`).

Следствие, наблюдённое 21.11.2026: правка только представления потребовала
**пяти** отдельных циклов CI по ~20 минут, потому что каждый прогон вскрывал
следующее закреплённое значение. Один выпуск — пять правок политики.

## Предложение

### 1. Один источник истины

Заменить версию и хеши, размазанные по коду, на один файл:

```json
{
  "plugin": "local_kbacompany",
  "version": 2026111601,
  "corporate": 2026111100,
  "release_notes": "RELEASE_NOTES_RC29_build2026111601.md",
  "pinned": {
    "local/kbacompany/lang/ru/local_kbacompany.php": "<sha256>",
    "local/kbacompany/lang/en/local_kbacompany.php": "<sha256>",
    "local/kbacompany/styles.css": "<sha256>"
  }
}
```

Гейты читают его вместо литералов. Тогда смена версии — одна строка.

### 2. Один инструмент вместо ручной правки

`tools/release_bump.py`:
- поднимает версию в `version.php`, в реестре и в workflow;
- пересчитывает хеши закреплённых файлов;
- создаёт запись в `docs/reconcile/*-source-preservation.json` с `before` из предыдущей записи;
- добавляет файл в `FOLLOWUPS`;
- печатает diff и отказывается работать, если цепочка evidence не сходится.

### 3. Правила версии

- **Любое изменение поведения плагина** (PHP, шаблоны, схема) — новая версия.
- **Пакет только представления** может сохранить версию, но тогда он обязан быть
  идентифицирован SHA256 и записан в журнал выпуска. Двух одинаковых по версии
  пакетов в продакшне быть не должно без такой записи.
- **Одна версия — один пакет.** Если содержимое изменилось, пакет пересобирается
  и SHA256 фиксируется заново.
- Хеши закреплённых файлов обновляются **в том же коммите**, что и файлы. Иначе
  гейт `parent source lost` блокирует мерж.

### 4. Что даёт

| Сейчас | После |
|---|---|
| смена версии = 7 правок + evidence | одна команда |
| правка представления = 5 циклов CI | один цикл |
| риск забыть место — высокий | источник один |

## Что нужно решить

1. Принимаем ли реестр `release/version-policy.json` как источник истины.
2. Разрешаем ли presentation-only пакеты без смены версии (с записью SHA256).
3. Кто владелец `tools/release_bump.py` — Codex или Claude.

До решения действует текущее правило: версия `2026111601`, пакеты различаются SHA256,
и каждая смена версии сопровождается правкой всех семи гейтов и evidence-цепочки.
