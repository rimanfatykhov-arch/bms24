# Коммуникационный центр: единое обсуждение задачи, события, ответы, участники

Решение владельца 15.11.2026: «Да, пункты 1–5» (после сравнения с Битрикс24 и Odoo).
Ветка `feature/communication-center-cleanup` перебазирована на #113 `5924bc074c2a34d485b18a4fba4f7b7aa9534358`
(опубликованный #110 + дневная сводка #107; оператор Codex). Порядок выпуска: А — #113, Б — эта доработка поверх А.

## Поведение

1. **Обсуждение задачи видит каждый, кто может открыть задачу** — в карточке и в центре. Чтение не делает
   участником: нет отметок прочтения и уведомлений. Сообщение из карточки или кнопка «Присоединиться к обсуждению»
   в центре добавляют в участники; присоединиться может только тот, у кого есть право писать в обсуждение задачи.
   Личные диалоги, группы и обсуждения других объектов по-прежнему видят только участники.
2. **События задачи в ленте обсуждения** (создана, начата, предъявлена, принята, возвращена с причиной, отменена,
   изменена, изменён наблюдатель, добавлена подзадача) — проекция существующей «Истории» (`tasklog`), а не сообщения.
   Открытие задачи и «добавил сообщение» в ленту не выводятся.
3. **Ответ с цитатой** («Ответить») в карточке задачи и в центре; цитата удалённого сообщения показывает только
   отметку об удалении. **Упоминание в тексте**: `@Полное Имя` участника — отдельное уведомление «Вас упомянули».
4. **Без дублей личных диалогов**: «Написать» тому же сотруднику открывает существующий диалог (в обе стороны).
   **Группа**: видна роль «владелец»; владелец исключает участника; участник может выйти; если выходит владелец,
   владельцем становится самый давний участник. История сохраняется.
5. **Фильтры списка**: Все, Непрочитанные, Сообщения (личные и группы), Обсуждения (объекты), Упоминания,
   Уведомления, Встречи. В шапке обсуждения задачи — ссылка «Открыть задачу».

## Границы и права

- Схема, `version.php`, миграции, capabilities не меняются. Новых таблиц нет.
- Видимость расширена **только** для `contextkind='task'` (`communication_service::VIEWER_READ_KINDS`);
  доступ к задаче перепроверяется через `communication_object_service::describe` → `task_service::can_view_task`
  на каждом чтении, в живом обновлении и при скачивании файла (`can_view_message`: файлы обсуждения задачи
  открывает тот, кто видит задачу; файлы других тредов — только участникам).
- Все запросы ограничены `companyuuid`; чужая компания и пользователь без доступа к задаче получают отказ,
  неотличимый от «нет объекта».
- POST + sesskey для новых действий (`leavethread`, `removeparticipant`); выйти/исключить можно только в группах.
- Это изменение правил доступа (ACL): маршрут **не FAST**, требуется полная приёмка.

## Известные риски

- Зависимость от #113: если его head изменится (Codex исправляет HTTP 500 на dev), ветка перебазируется снова, цепочка lang-хэшей пересчитывается.
- Строки событий используют время записи в `tasklog`; при пагинации центра события показываются только на
  последней странице, без поиска.
